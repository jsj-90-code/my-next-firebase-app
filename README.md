# 점포평가 시스템 (V62) 사용 안내

PC방 신규 후보지의 예상매출(V62 모델)을 계산하고, 기존 가맹점 실매출로 모델을 검증하는 사내 도구입니다.
아래 순서대로 따라 하면 됩니다.

## 1. 처음 한 번만 하는 준비

1. 이 저장소를 내려받고, 터미널(명령창)에서 이 폴더로 이동합니다.
2. 패키지를 설치합니다.
   ```bash
   npm install
   ```
3. `.env.local` 파일이 있는지 확인합니다(없으면 `.env.local.example`을 복사해서 `.env.local`로 만들고, Firebase 콘솔에서 발급받은 값을 채워 넣습니다). 이미 있다면 이 단계는 건너뜁니다.
4. Firestore 보안규칙을 배포합니다(점포평가 화면들이 데이터를 읽고 쓰려면 반드시 필요합니다. 이미 배포했다면 다시 할 필요는 없지만, `firestore.rules`를 고친 뒤에는 매번 다시 배포해야 합니다).
   ```bash
   npx firebase-tools deploy --only firestore:rules,firestore:indexes
   ```

## 2. 실행하기

```bash
npm run dev
```

터미널에 나오는 주소(보통 http://localhost:3000)를 브라우저에서 열고, 회사 구글 계정(@isens.camp)으로 로그인한 뒤 홈 화면에서 **"점포평가 시스템 (V62)"** 카드를 클릭합니다. 또는 바로 `http://localhost:3000/store-eval`로 들어가도 됩니다.

## 3. 화면 구성

- **대시보드**: 등록된 후보지 수, 평가완료/입력필요/포화주의/입지재검토 건수, 후보지별 예상매출을 한눈에 봅니다.
- **신규후보지**: "+ 신규 후보지 등록"을 누르면 N001, N002... 형식 코드가 자동으로 생성됩니다. 상세 페이지에는 탭이 4개 있습니다.
  1. **기본정보** — 후보지 정보, 상권 인구통계, 자사 시설/사양을 입력합니다. "임시저장"은 나중에 다시 고칠 수 있는 초안, "저장"은 정식 등록입니다.
  2. **경쟁점** — 후보지 주변 경쟁 PC방을 하나씩 추가합니다. 조사를 못 했으면 "경쟁점없음" 또는 "노후·저경쟁력 미조사" 중 하나를 골라주세요.
  3. **입지동선평가** — 상권 안 위치, 동선, 외부유입제한, 브랜드구분(반드시 "블랙라벨"이어야 최종판정이 나옵니다) 등을 입력합니다.
  4. **최종결과** — 위 세 탭을 다 채우면 V62 예상매출, 85%/115% 범위, 최종판정이 자동으로 계산됩니다. "적용된 산식과 계수 보기"를 누르면 어떤 수식·계수로 계산됐는지 전부 펼쳐볼 수 있고, "인쇄/PDF 저장"으로 출력할 수 있습니다.
- **기존 가맹점 검증**: 기존 가맹점의 실제매출과 모델 예측값을 비교해서 모델이 얼마나 정확한지 보여줍니다. (아래 "4. 기존 가맹점 매출 데이터 연동" 참고)
- **운영설정**: V62 계산에 쓰이는 모든 계수와 판정 기준을 봅니다. **관리자로 등록된 사람만 값을 바꿀 수 있습니다.** 관리자를 추가하려면 Firebase 콘솔 → Firestore Database → `storeEvalAdmins` 컬렉션에서, 문서 ID를 그 사람의 회사 이메일로(예: `jsj-90@isens.camp`) 만들면 됩니다(문서 내용은 아무거나 넣어도 됩니다 — 문서가 "존재하는지"만 확인합니다).
- **백업**: (관리자 전용) 전체 데이터를 JSON 파일 하나로 내려받습니다.

## 4. 기존 가맹점 데이터 — Google Sheet 실시간 연동 + Firestore 저장

2026-08-20부터 Google Sheets API로 원본 스프레드시트("PC가맹_PC_가맹점전수조사_데이터")에
직접 연결해 Firestore로 데이터를 가져옵니다(`src/lib/googleSheets.ts`가 이미 쓰던 것과 같은
서비스계정 자격증명 재사용). 관련 컬렉션:

- `storeEvalExistingStores` — 가맹점 마스터(01_점포기본정보 전체 + V61 학습 특징치·실제매출)
- `storeEvalExistingStoreSales` — 월별 매출(가맹점코드+연월별 PC매출/상품매출, 매출DB에서 직접 동기화)
- `storeEvalExistingStoreMembers` — 03_회원정보입력 스냅샷 누적(계산에는 안 쓰는 참고 데이터)
- `storeEvalCompetitors` / `storeEvalLocationEvaluations` — 신규후보지와 컬렉션을 공유(경쟁점·입지평가는 코드로 구분 없이 같은 구조)

**동기화 스크립트** (`.env.local`에 `FIREBASE_CLIENT_EMAIL`/`FIREBASE_PRIVATE_KEY`,
Google Sheet를 그 서비스계정 이메일에 뷰어로 공유해야 함):
```bash
# 1) 최초 1회 — 01/05/09/03 시트의 나머지 원본 입력값을 전부 Firestore로 옮긴다
node scripts/migrateFullExistingStoreProfiles.mjs

# 2) 반복 실행 — 매출DB에 새 월매출이 올라오면 이 스크립트를 다시 돌려서 반영한다
#    (오픈 1~12개월 평가창을 자동 적용해 completedMonths/actualMonthlyRevenueAvg를 재계산함)
node scripts/syncSalesFromRevenueSheet.mjs
```
아직 스케줄러(Cron)로 자동 실행되지는 않습니다 — 매출DB가 갱신될 때마다 수동으로 재실행해야
합니다. 정기 자동화가 필요하면 Vercel Cron이나 Firebase Scheduled Function으로 이 스크립트
로직을 옮기는 후속 작업이 필요합니다.

**신규 가맹점 추가**: `/store-eval/existing-stores` 화면에서 직접 등록하거나, 신규후보지
평가를 마친 뒤 [최종결과] 탭의 "오픈 확정 → 기존 가맹점으로 전환" 버튼으로 경쟁점·입지평가
입력을 그대로 이어받아 등록할 수 있습니다. 이후 월매출·회원 스냅샷은 그 화면에서 계속
추가하거나, 매출DB 시트에 입력한 뒤 위 동기화 스크립트로 반영하면 됩니다 — 스프레드시트 없이도
운영 가능한 구조입니다.

## 5. 꼭 알아두어야 할 점 (정확도 관련 한계)

2026-08-20에 원본 Apps Script(`점포평가.gs`, `repair.gs`) 코드를 확보해 대부분을 정확한 코드로 반영했습니다(로컬 사본은 `reference/apps-script/`에 있습니다 — git에는 올라가지 않습니다). 다만 남은 한계가 있습니다. 자세한 내용은 `docs/data-issues.md`에 정리해 두었습니다.

1. **V61 기본예측은 실제 릿지회귀 학습모형을 씁니다.** 원본은 비음수 릿지회귀+대당월매출 중앙값 블렌드라는 통계모형을 쓰는데, 이 알고리즘을 `src/lib/storeEval/calc.ts`에 정확히 포팅했고(`fitEmpiricalRevenueModel`/`predictEmpiricalRevenue`), 기존 가맹점 26곳의 실측 특징치(요금·예측자사수요/PC·경쟁력점수·실제매출)로 실제 학습시켰습니다. `scripts/seedExistingStoreTrainingData.mjs`로 Firestore에 이 데이터를 넣어야 폴백 대신 이 실측 모형이 적용됩니다(안 넣으면 화면에 "임시 근사치·검증 전"이라고 표시됩니다). 리브-원-아웃 검증 결과는 평균절대오차 12.25%·중앙값 8.77%·±20% 이내 73.1%로, 기존 Google Sheet 참고치(11.7%/9.1%/76.9%)와 비슷한 수준입니다. 6. 기존 가맹점 검증 화면에서 12개월 미완료 매장까지 포함한 재직기간별 코호트 검증 결과를 확인할 수 있습니다.
2. **사양·좌석·입지 점수는 이제 자동 계산됩니다.** VGA 모델명·존 구성 개수·층수+엘리베이터로부터 원본 그대로(`scoreFromVga_`/`scoreFromZoneComposition_`/`scoreFromAccess_`) 자동 계산하며, 더 이상 평가자가 1~5점을 직접 고르지 않습니다. 먹거리·인테리어·모니터 점수는 원본에서도 사람이 직접 입력하는 항목이라 그대로 유지됩니다.
3. **09_입지동선평가의 1~5점 판단기준표는 여전히 원본에 없습니다.** 이 시트는 `점포평가.gs`가 다루는 범위 밖(사람이 직접 만든 스프레드시트 수식 레이어)이라, Apps Script 코드를 확보해도 풀리지 않는 문제였습니다. 화면에는 참고 사례만 보여주고 "공식 기준"이라고는 표시하지 않습니다. 4개 점수(상권내위치·주요동선·선점경쟁·접근가시성)는 계속 평가자가 직접 입력하고, 종합점수 가중치(30/30/25/15%)만 자동 계산합니다.
4. **실측기반 예상월매출(경쟁점 실가동좌석 기반)과 AA 기준매출**을 새로 추가했습니다. 경쟁력격차 구간별 수요확보율·신규수요증가율 룩업표, 오픈월부터 10개월 평균 목표치 표는 원본 `08_계산기준`에서 그대로 가져왔습니다. V61(인구·이용률 기반)과는 독립된 두 번째 예측 경로로, 최종결과 화면에 나란히 표시됩니다.
5. **계절지수는 적용하지 않습니다.** 원본 어디에도 월별 계절 보정 테이블이 없어 지어내지 않았습니다. 완료된 달의 실제매출 평균과 모형의 단일 예측값을 그대로 비교합니다.
