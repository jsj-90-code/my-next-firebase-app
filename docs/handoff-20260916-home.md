## ⭐ 오늘 제일 중요한 것 하나

**실험실 화면이 `outsideOptionIp`(PC방 안 가는 몫)를 모델 기본값 0 대신 500으로 덮어쓰고
있었다.** 조절판 시절 슬라이드의 출발값인데, 조절판을 걷어내면서 그대로 고정 계수로 굳었다.

왜 치명적인가: 수요 축척은 **"독점 상권은 점유율이 1이라 수요식만 남는다"**를 전제로 독점
매장에 맞춘다(`calibrationTarget`). 안가는몫이 500이면 경쟁점 0곳인 독점 매장도 점유율이
99/(99+500)=17%가 되어 전제가 깨진다. 축척이 1/0.17 ≈ 6배로 부풀고, 점유율이 그만큼
작아져 **매출만 얼추 맞는** 상태가 됐다.

|  | 안가는몫 500 | 안가는몫 0 |
|---|---:|---:|
| MAPE | 41.78% | **23.43%** |
| ±20% 적중 | 29% | **58%** |
| 수요 전부라면 100% 초과 | 37/38곳 | **1/38곳** |
| 산식 점유율 범위 | 6.8~19.8% | **22~100%** |
| 탕정역점(독점) 점유율 | 17.6% | **100.0%** |

⚠️ **오늘 낮에 잰 입지 분석을 전부 그 틀린 지점에서 돌렸다.** 다시 재니 결론이 뒤집혔다.
릴리스 문서 4절·6절의 숫자는 **낡았다** — 아래 "지금 성적"이 맞는 값이다.

## 회사에서 제일 먼저

```bash
git pull
node scripts/dumpValidationSnapshot.mjs      # 검증 스냅샷은 git에 없다
npm run build && npx vitest run --exclude "**/_*.test.ts" --reporter=dot
```

⚠️ **붉은 테스트 2건은 코드 문제가 아니다.** 저장된 적중률과 광주각화점 수요 캐시가 좌표
교체 전 값이다. 검증 화면을 한 번 열고 06시 크론이 캐시를 다시 쓰면 맞는다.

⚠️ 실험실 복제본(`storeEvalLab*`)은 이미 Firestore에 있으니 다시 만들 필요 없다.
운영 쪽 최신 자료를 당겨오려면 `node scripts/syncLabCollections.mjs --apply` —
**그러면 실험실에서 고쳐둔 값이 덮인다.** 로드뷰 판정은 별도 컬렉션이라 안 덮인다.

## 이 PC에만 있는 것

`.local-tools/`는 gitignore다. 다시 만들려면:

| 파일 | 다시 만드는 법 |
|---|---|
| `validation-snapshot.json` | `node scripts/dumpValidationSnapshot.mjs` |
| `roadview-judgments.json` | **다시 못 만든다** — AI 판독 결과다. Firestore에 올려뒀으니 거기서 읽으면 된다 |
| `coord-crosscheck.json` | `node scripts/crosscheckCoordsByPlace.mjs` |
| `competitor-coords.json` | `node scripts/geocodeCompetitors.mjs` |
| `kakao-place-density.json` | `node scripts/collectKakaoPlaceDensity.mjs` |

로드뷰 캡처 하네스는 `scripts/roadview/`에 있다(README에 함정 정리). playwright-core는
저장소에 안 넣었으니 스크래치패드에 깔아야 한다.
