## 1. ⭐ 오늘 제일 중요한 것 — 화면이 계수를 잘못 쓰고 있었다

실험실 화면이 `outsideOptionIp`(PC방 안 가는 몫)를 **모델 기본값 0 대신 500으로** 덮어쓰고
있었다. 조절판 시절 슬라이드의 출발값인데, 조절판을 걷어내며 그대로 고정 계수로 굳었다.

**왜 치명적인가**: 수요 축척은 *"독점 상권은 점유율이 1이라 수요식만 남는다"*를 전제로
독점 매장에 맞춘다(`calibrationTarget`). 안가는몫이 500이면 경쟁점 0곳인 독점 매장도
점유율이 99/(99+500)=17%가 되어 **전제가 깨진다.** 축척이 6배로 부풀고, 점유율이 그만큼
작아져 **매출만 얼추 맞는** 상태가 됐다.

|  | 안가는몫 500 | 안가는몫 0 (지금) |
|---|---:|---:|
| MAPE | 41.78% | **23.43%** |
| ±20% 적중 | 29% | **58%** |
| "수요 전부라면" 100% 초과 | 37/38곳 | **1/38곳** |
| 산식 점유율 범위 | 6.8~19.8% | **22~100%** |
| 탕정역점(독점) 점유율 | 17.6% | **100.0%** |

**교훈**: 조절판을 없앨 때 슬라이드 출발값을 고정 계수로 굳히면 안 된다. 그리고 **중간
단계가 뜻이 통하는지** 봐야 한다 — 독점 매장 점유율이 17%로 나오는 건 숫자가 아니라 뜻이
틀린 것이다. 최종 오차만 보면 두 오류가 상쇄돼 안 보인다.

잔차화 중심도는 고친 뒤에도 무작위 대조군 p=0.005 ✅ · LOO 벌어짐 0.01%p · 훈련겹 37/38이
ν=0.5다. 직전 기록은 입지·새 경쟁항 이전 29.42%.

확인: `npx vitest run src/lib/storeEval/_textbookFull.test.ts --reporter=verbose --disable-console-intercept`

### ⚠️ 잔차화 중심도는 **켜지 않기로 했다** (개념적 이유)

사용자 질문: "키는 게 맞아? 개념적으로" — 다시 따져보니 **아니다.**

1. **표본 의존적이다.** 잔차화는 38곳에 회귀선을 긋고 거기서 얼마나 벗어났나를 재는 것이라,
   점포 고유의 속성이 아니라 "이 표본 안에서의 상대적 위치"다. 후보지에 쓰려면 회귀 계수를
   박아야 하는데 38곳에서 나온 마법 숫자가 더 늘어난다.
2. **정공법이 아니다.** 이중계산이 문제면 두 항의 정의를 안 겹치게 고치는 게 맞다.
   잔차화는 응급처치다 — "원인이 이중계산이 맞다"는 **증거**로는 값어치가 있다.
3. **효과 크기가 점유율 보정치고 크다.** ν=0.5는 "중심도 4배면 점유율 2배"다. 경쟁 상황이
   같은데 그럴 리 없다 — **수요 쪽 효과**로 보인다. 그렇다면 점유율이 아니라 수요식을
   고쳐야 한다.

**지금 기본값(중심도 ν=0.25 · 접근성 κ=0.25)을 그대로 둔다.** 이건 손 안 댄 원래 중심도라
표본 의존 문제가 없다.

## 4. 운영과 실험실을 갈랐다

실험실이 운영 V62와 **같은 문서를 읽고 있어서**, 실험용으로 기초자료를 고치면 운영 예측이
조용히 따라 움직였다. 시설·사양까지 실험실에서 고칠 참이라 사용자 방향으로 분리했다.

| | 운영 V62 | 실험실 |
|---|---|---|
| 기존점·후보지·경쟁점·입지평가·설정 | `storeEval*` | `storeEvalLab*` |
| 월매출 | `storeEvalExistingStoreSales` | **같은 것을 읽는다** |
| 로드뷰 판정 | — | `storeEvalLabRoadviewJudgments` |

- 복사는 **한 방향(운영 → 실험실)**뿐. `node scripts/syncLabCollections.mjs --apply`를
  **명시적으로 돌릴 때만** 일어난다. **돌리면 실험실에서 고친 값이 덮인다.**
  로드뷰 판정은 별도 컬렉션이라 안 덮인다.
- ⚠️ **새 컬렉션을 만들면 `firestore.rules`에 규칙을 추가하고 배포해야 한다.** 오늘 빠뜨려서
  화면에 "Missing or insufficient permissions"가 떴다. 복사 스크립트는 firebase-admin이라
  규칙을 우회해 쓰기는 멀쩡히 되므로 **개발자 쪽에서는 안 보인다.**

**조절판도 없앴다.** 계수는 `DEFAULT_TEXTBOOK_PARAMS`에 고정이고 화면은 읽기 전용 표로
보여만 준다. 계수 변경은 코드 작업이다.

**표 표기도 고쳤다**(사용자 지적): 가동률은 그 자체가 %라 상대오차가 오해를 부른다 →
부호 붙인 **퍼센트포인트**(`+21.0%p`)로. "경쟁없을때" → "수요 전부라면",
"필요 점유율" → "실제 먹은 몫".
