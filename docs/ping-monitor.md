- 국내 PC에서도 같은 양상이라 해외 수집 서버에서만 생기는 문제라는 설명은 지지되지 않는다. IP가 맞다는 사용자 확인을 전제로 응답 필터링·NAT·경로 문제 등을 의심하되, 외부 무응답만으로 차단 위치나 PC 전원 상태를 확정하지 않는다.

- 즉석 확인은 TCP만 사용한다. 결과를 실제 가동 PC 수·가동률로 단정하지 않고 TCP 응답 IP 수와 정기 측정(ICMP+TCP)과의 차이를 표시한다.
- 실제 복구는 매장 관리자가 PC별 공인 IP 매핑을 확인하고 필요한 경우 측정 서버 출발지에 한정해 ICMP Echo 요청을 허용한 뒤, 켜짐/꺼짐이 알려진 PC와 대조해야 한다. 공유기만 응답하거나 여러 PC가 하나의 공인 IP를 공유하면 외부 응답 개수로 좌석 수를 셀 수 없다. 상대 매장 협조가 없으면 허가된 관리 프로그램 데이터 또는 현장 실측이 필요하다. 무응답을 0%로 해석하지 않는다.

옛 핑봇(`ping.isens.camp`)은 유지보수가 끊겼다. 사용자가 직접 쓰려고 새로 만들었다 — 경쟁점 **상호·주소·IP대역**만 넣으면
1시간마다 켜진 PC를 세어 가동률을 **기한 없이** 쌓는다.

## 어떻게 재나

- Vercel 함수는 핑(ICMP)을 못 보낸다. 대신 IP마다 포트 두 개(80·3389)에 **TCP 연결을 한 번 시도**한다.
  켜진 PC는 "연결 거절"을 바로 돌려주고(=켜짐), 꺼진 PC는 대답이 없다(=꺼짐). 문을 여는 시도가 아니고, 포트 스캔도 아니다.
- 2026-10-06 실측: `118.128.168.1~110`에서 핑과 TCP 결과가 110개 전부 일치(11:10 5대, 11:50 6대).
- `115.89.100.1~140`(옛 핑봇도 못 재던 곳)은 핑·TCP 모두 0/140, 공유기(254)만 대답 → **PC가 바깥 확인을 막아 둔 매장**.
  이런 곳은 72번 넘게 재도 0이면 화면에 "측정 불가 의심"으로 따로 뜬다(가동률 0%로 섞지 않으려고). 기준값은 `summary.ts`의 `BLOCKED_SUSPECT_SAMPLES`.
- Windows에서 시험할 땐 거절이 ~2.1초 늦게 온다(재시도) — 대기 시간이 Windows 4초·서버 2초인 이유.

  → **방문 없는 가동률 경로는 회사 차원 제휴(미디어웹·엔미디어플랫폼 지역 집계)만 남는다. 앱 쪽은 다시 파지 말 것.**

## 저장

- `pingMonitorStores/{id}` — 등록 정보 + `days.{YYYY-MM-DD} = {a: 켜진 수 합, t: 대수 합, n: 측정 횟수}` + `lastSample`
  + `recent.{HH} = {a, t, at}`(시간대별 마지막 측정 — "최근 24시간"용, 2026-10-07. 그 전 기록은 `scripts/pingMonitor/backfillRecent.mjs`로 옮김).
  목록은 이것만 읽는다(매장당 읽기 1번).
- `pingMonitorDaily/{id}_{YYYY-MM-DD}.hours.{HH} = {a, t}` — 상세 화면 시간대별. 최근 92일까지만 읽는다(무료 요금제 읽기 한도).
- 가동률 = **일일평균**(2026-10-07 사용자): 날마다 a÷t를 구해 평균한다. 24시간(`FULL_DAY_MIN_SAMPLES`)을 다 못 잰 날 — 등록한 날 오후부터 잰 날 등 —
  은 낮·밤이 치우쳐 뺀다("어제 7시간 돌린 데이터는 날려야"). 처음엔 서버 장애로 한두 시간 빠진 날을 살리려고 22로 뒀으나 2026-10-08 사용자 결정으로 24 —
  빠진 2시간이 저녁 피크면 영향이 크다. 장애로 한 회차라도 빠지면 그날은 통째로 빠진다(18로 두면 빠진 시간이 낮에 몰린 날이 통과해 치우친다 — 10-07 암사역 콤마 18칸 중 빈 6칸이 전부 11~16시). 진행 중인 오늘은 "오늘" 칸에만 따로.
- **최근 24시간**: 시간대 칸마다 24시간 안 마지막 측정을 합친 Σa÷Σt, **24칸 꽉 차야 값**(사용자 2026-10-07 — 회차가 한 번 빠지면 24시간 동안 "-"). 0~24시 날짜를 기다리면 오후 등록 후보지는
  2일 가까이 걸려서(사용자 2026-10-07) 둔 값 — 등록 다음 날 같은 시각이면 하루치를 쓸 수 있다. 신규 후보지 평가 칸엔 이 값을 먼저 넣고 7일이 차면 바꾼다.
- 대수를 나중에 고쳐도 지난 기록 분모는 그때 값으로 남는다.
- 같은 한국 시(時)에 두 번 불려도 한 번만 센다(트랜잭션).
- 화면은 등록 칸만 쓸 수 있고 측정 기록은 서버만 쓴다. 지우기는 막았다(`firestore.rules`). 측정을 멈추려면 상세 화면에서 "1시간마다 측정"을 끈다.

## 알람 경위 (2026-10-06 하루 동안)

   서버는 `CRON_SECRET`도 받으니, 요금제가 Pro로 바뀌면 `vercel.json`에 매시 예약을 넣고 워크플로를 지우면 된다.

## 옛 핑봇 값과 이어 쓰기
