# 사람이 판정해야 하는 것 — 2km 경쟁점 폐업 대조

만든 날 2026-09-20 (무인작업) · 생성기 `scripts/buildRival2kmReview.mjs`

**열 파일: [`2km-경쟁점-대조.html`](./2km-경쟁점-대조.html)** — 브라우저로 그냥 열면 된다.

| | |
|---|---|
| 카카오가 준 전체 행 | **1,187** |
| 사람이 실제로 볼 것 | **215** (52개 매장) |
| 줄어든 비율 | 전체의 **18%** |

판정칸은 **영업 / 폐업 / 모름** 셋이다. **모르면 비워 둬라** — 추측해서 채우면
자료가 지금보다 더 나빠진다.

---

## 1. 왜 이 일이 필요한가

`.local-tools/kakao-neighborhood.json`(2km 안 PC방 좌표, 54곳)에 **폐업 매장이 섞여
있다.** 사용자가 문경시청점을 지도로 대조해서 드러났다 — **7곳 중 3곳(43%)이 폐업**
(팡팡피씨방·스위티 피시방·라이또 PC방, 전부 1.5km 지점). 카카오 장소 API는 폐업 표시를
따로 주지 않는다.

이 자료가 `_catchment.test.ts`("2km 안에 대체 PC방이 없다"는 사용자 가설)가 쓰는
**유일한 근거**다. 그 검정은 가설을 기각했는데, 근거 자료가 부풀려져 있으므로
**기각 결론이 흔들린다.**

우리 정식 경쟁점 DB는 500m까지만 조사한다. 그래서 오염 구간(500m~2km)이 정확히
이 가설이 쓰는 구간과 겹친다. **자동으로는 풀 수 없다.**

## 2. 1,187행을 215행으로 줄인 근거

검정이 쓰는 변수는 둘뿐이고, **둘 다 500m 밖만 센다.**

```
outside          = 500m ~ 2km 안 PC방 수
nearestOutsideM  = 그중 최단거리 (없으면 2000)
```

여기서 세 단계로 줄였다.

| 단계 | 줄어든 것 | 남는 행 |
|---|---|---|
| 출발 | — | 1,187 |
| 자기 자신 제거(30m 안) | 64행 | 1,123 |
| **500m 안 제거** — 검정이 아예 안 쓴다 | 320행 | 803 |
| **C등급 제거** — 판정해도 순위가 안 바뀐다 | 588행 | **215** |

### 등급을 나눈 기준

검정은 **순위 기반**(스피어만·편상관)이다. 절대 개수가 아니라 매장끼리의 **순서**만
결과를 바꾼다.

- **A등급 (128행 · 25개 매장)** — 500m 밖 PC방이 **10곳 이하**인 매장의 전부.
  가설이 사는 구간이다. 문경시청(5곳)·양주덕정(1곳)·진주혁신도시(0곳)·영월(0곳)이
  여기 있고, 한 곳만 폐업으로 바뀌어도 순위가 크게 움직인다.
- **B등급 (87행 · 29개 매장)** — 조밀한 매장의 **최단 3곳**. 이것만 확정하면
  `nearestOutsideM`이 정해진다. 최단이 영업으로 확인되면 그 매장은 거기서 끝이다.
- **C등급 (588행)** — 조밀한 매장의 네 번째 이후. 기본으로 **숨겨져 있다.**

### ⚠️ 이 등급 나누기의 한계 (중요)

C등급을 빼도 되는 근거는 **관측된 폐업률 43%**다. 500m 밖이 28~40곳인 매장은
43%가 폐업해도 16~23곳이라 희소군(10곳 이하)과 순위가 안 겹친다.

**최악(C등급이 전부 폐업)을 가정하면 순위는 뒤집힌다.** 즉 이 등급은
**품을 줄이려는 장치이지 "C는 안 봐도 맞다"는 결론이 아니다.**
A·B를 끝낸 뒤 결과가 아슬아슬하면 C도 봐야 한다.

## 3. 어떻게 보나

1. 매장 줄의 **"지도에서 이 매장 열기"**로 카카오맵을 연다.
   그 화면에서 **PC방**을 검색하면 주변 목록이 한꺼번에 뜬다.
   → **매장당 지도를 한 번만 열면 된다.** 행마다 링크를 누르면 215번을 눌러야 한다.
2. 아래 목록과 대조해 **영업 / 폐업 / 모름**을 누른다.
3. 다 하면 **CSV 내보내기**로 파일을 저장해서 주면, 그걸로 검정을 다시 돌린다.

판정은 브라우저에 자동 저장된다(새로고침해도 남는다 — 확인했다). 저장이 막히는
브라우저면 페이지 맨 위에 빨간 경고가 뜬다. 그때는 중간중간 CSV로 내보내면 된다.

### 먼저 보면 이득인 것

- **"같은자리" 배지 — A·B등급 안에 41행.** 같은 주소(또는 25m 안)에 상호가 둘인 곳이다.
  **한쪽이 폐업했을 가능성이 높다.** 예: 청주터미널점 반경의
  `레드포스PC아레나 청주복대점` ↔ `탑스타PC`(같은 주소).
- **A등급이 5행 이하인 매장 10곳** — 시흥능곡(1)·양주덕정(1)·검단사거리(3)·구미산동(3)·
  오송(3)·인천서창(3)·화명대로(3)·문산(4)·증평(4)·문경시청(5).
  가설의 핵심 매장이 다 여기 있고, 합쳐서 **30행**이다. 시간이 없으면 이것만 봐도 된다.
  (진주혁신도시·영월은 500m 밖이 아예 0곳이라 볼 것이 없다.)

## 4. 표에 일부러 넣지 않은 것

**예상매출·실매출·오차·적중률이 한 글자도 없다.**

`scripts/buildMarketSplitJudgePage.mjs`(2026-09-18 상권분리 판정)와 같은 규율이다.
판정하는 사람이 "이 매장은 과소예측이지" 를 알고 보면, 시험이 아니라 **사후설명**이
된다. 폐업 여부는 성적과 무관하게 지도만 보고 정해야 한다.

⚠️ 다만 **매장별로 묶어 놓은 것 자체가 약한 단서**다(A등급 매장 = 주변이 희소한 매장).
지도를 매장당 한 번만 열게 하려면 묶는 수밖에 없어서 감수했다. 기록해 둔다.

## 5. 자료 자체의 경고

- **"잘림" 배지 5곳** — 전대후문·부천상동역·수원인계·신중동·전대상대.
  카카오가 목록을 잘라서 줬다. **실제로는 더 많다.** 이 매장들의 개수는
  **하한으로만** 써야 한다. (다섯 곳 모두 조밀한 매장이라 B등급 3행씩만 본다.)
- **500m 밖인데 공식 DB에 있는 것 3행** — 좌표가 어긋나 경계에 걸친 경우다.
  공식 DB(500m)로 걸러지는 건 사실상 500m 안쪽뿐이었다. 232곳 중 **500m를 넘는
  공식 경쟁점은 1곳**(클라우드 1500m)뿐이라, "이미 조사된 곳을 빼서 줄인다"는
  방법은 **이 구간에서는 거의 효과가 없었다.** 줄이기는 전부 위 2절의 등급이 했다.
- **매장명 앞뒤 공백** — `창원상남점`이 ` 창원상남점`으로 들어 있다(앞에 공백 하나).
  표시에만 영향이 있고 매칭은 코드로 하지만, 원본을 고칠 때 같이 보면 좋다.

## 6. 판정이 끝난 뒤

CSV를 받으면 `_catchment.test.ts`를 폐업 제외본으로 다시 돌린다. 그 시험은
**사전 등록된 관문 5개**(두 곳 빼고도 되는가 · 인구 통제 · 무작위 대조군 · 세 자 · LOO)를
그대로 갖고 있다. **관문을 고치지 말고** 같은 기준으로 다시 판정해야 한다.

## 7. 다시 만들려면

```bash
node scripts/buildRival2kmReview.mjs
```

입력은 `.local-tools/kakao-neighborhood.json`(git에 있다)과
`.local-tools/validation-snapshot.json`(`node scripts/dumpValidationSnapshot.mjs`로 뜬다)
둘뿐이다. 판정 기록은 브라우저에 있으므로 **다시 만들어도 지워지지 않는다.**
