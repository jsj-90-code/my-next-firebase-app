# 주소만 초기평가 도구 — 만든 것과 안 만든 것 (2026-09-22)

화면: `/store-eval/quick-eval` · 인계문: `docs/handoff-address-only-tool.md`

---

## 0. 무엇인가

주소 한 줄로 상권자료를 자동수집해서 **운영 V62 산식 그대로** 예상매출을 내고, AI 평가문까지
붙이는 화면이다. 점포개발 **초기 선별**용이고, 결재 숫자는 여전히 [신규후보지]에서 낸다.

산식은 `evaluateCandidate()` 한 곳만 부른다 — [최종결과] 탭과 **같은 배선**이다.
다른 건 입력 자료뿐이고, 조사로만 알 수 있는 칸은 비워서 운영 V62에 **이미 있는** 기본값
장치가 채우게 둔다(`computeCompetitorAppliedPcCount`, `applyStandardOwnFacilityDefaults`,
`resolveManagementScores`).

**운영 V62 파일은 한 글자도 안 고쳤다.** 기존 화면도 안 건드렸다(메뉴 한 줄만 추가).

---

## 1. 사용자가 정한 것 (2026-09-22)

| 물어본 것 | 정해진 것 |
|---|---|
| 유동인구 | 소상공인365 자동수집을 시도한다. 실패하면 **지어내지 않고** "수집 실패"로 남긴다 |
| 입지평가(가시성 등) | 기존 Gemini AI 초안으로 자동 채점한다 |
| 결과 저장 | **저장 안 함.** Firestore에 한 줄도 안 쓴다 |
| 성인PC방 거르기 | 인허가 짝맞추기는 생략. **상호 이름 규칙**으로 거른다(인계문 4절) |
| AI 평가문 | **Gemini 무료 티어**로 쓴다 (웹검색이 필요 없어서 무료로 된다) |

## 2. 자료가 학습자료와 같은 자로 잰 값인지 — 확인함

도구가 넣는 값이 V62를 학습시킨 값과 출처가 다르면 예측이 조용히 어긋난다. 그래서 먼저 쟀다.

| 항목 | 대조 | 결과 |
|---|---|---|
| 주거인구(SGIS 반경조회) | 운영 52곳 손입력값 | 중앙 차이 **0.0%**, 51곳 중 34곳이 1% 이내 (2026-09-15에 이미 측정, 그래서 운영도 이 값으로 덮었다) |
| 유동인구 500m(소상공인365) | 운영 54곳 | 비율 중앙 **1.000**, 최악 0.98, **54곳 전부 ±10% 안** (2026-09-22 측정) |

=> **환산계수가 필요 없다.** 그대로 쓴다.

## 3. 자동 / 기본값 경계

화면과 AI 평가문은 `src/lib/storeEval/quickEval/quickEvalDefaults.ts`의 재고 표를 **읽어서**
그린다. 숫자를 화면에 글자로 박지 않는다(CLAUDE.md 규칙).

| 항목 | 출처 |
|---|---|
| 좌표 | 카카오 주소검색 |
| 주거인구 500m·1km(연령9구간·남녀) | SGIS 반경조회 2024년 |
| 유동인구 500m(총·성별·연령) | 소상공인365 (최근 12개월 평균 + 최근월을 그 축척으로 환산) |
| 경쟁점 목록·거리 | 카카오 장소검색 500m, 격자분할 |
| 경쟁점 PC 대수 | **기본값 90대** (운영 V62의 간략_기본대수) |
| 경쟁점 품질 | **전부 빈칸** → 결측 처리(동급) |
| 입지평가 5항목 | Gemini AI 초안 |
| 자사 시설·관리점수 | 회사 표준 / 가맹점 평균 |
| 자사 PC대수·시급·층·엘리베이터·브랜드 | **사람이 입력**(기획값이라 자동화 대상이 아니다) |

### ⚠️ 반만 채우지 마라

측정값이다(`_addressOnlyMode.test.ts`): 품질만 비우고 대수는 실측 = **12.57%**,
둘 다 비우면 **10.82%**. 어설프게 반만 채우면 자료가 어긋나 **더 틀린다.**
조사가 들어오면 품질과 대수를 **같이** 채워야 한다.

## 4. 화면에 띄우는 오차 (측정값)

| 단계 | MAPE | ±20% |
|---|---|---|
| 정밀 평가(전부 조사됨) | 8.83% | 92.11% |
| **주소만** | **13.40%** | **86.84%** |

⚠️ 이 측정은 **기존 가맹점 38곳**으로 잰 것이고, **가시성을 표본 중앙값으로 고정**해서 쟀다.
이 도구는 가시성을 AI로 매기므로 조건이 완전히 같지 않다 — 화면에도 그렇게 적어 뒀다.
AI 채점을 쓸 때의 오차는 **아직 안 쟀다**(다음 세션 과제, 6절).

## 5. 과금

| 자료원 | 과금 |
|---|---|
| 카카오 주소검색·장소검색 | 무료(일 할당량) |
| SGIS 주거인구 | 무료 |
| 소상공인365 유동인구 | 무료(스크래핑) |
| **입지평가 AI 초안** | **유료.** googleSearch 그라운딩이 유료 티어 전용이라 `GEMINI_API_KEY_LOCATION_EVAL`(전용 결제 프로젝트)로 나간다. 그라운딩만 월 5,000건 무료 |
| **AI 평가문** | **무료.** 웹검색이 필요 없어 무료 티어 키(`GEMINI_API_KEY`)로 돈다 |

⚠️ 평가문이 쓰는 무료 티어 키는 **좌석배치도 자동화와 할당량을 공유**한다. 연달아 돌리면
좌석배치도 쪽에서 429가 날 수 있다. 무료 티어는 구글이 입력을 제품 개선에 쓸 수 있으므로,
그게 걸리면 `GEMINI_API_KEY_QUICK_EVAL`에 유료 키를 넣으면 그쪽이 우선한다.
입지평가 전용 유료 키로는 **폴백하지 않는다** — 그 분리는 일부러 만든 것이다.

## 6. 안 한 것 / 남은 것

1. **AI 채점 입지평가의 오차를 안 쟀다.** `_addressOnlyMode.test.ts`의 L3는 고정값 기준이다.
   재려면 기존점 38곳에 AI 초안을 돌려서(유료 호출 76회) 같은 배선으로 비교해야 한다.
2. **경쟁점 PC 대수는 여전히 90대 기본값이다.** 인계문 5절의 막다른 길 그대로다.
3. **카카오 40건 상한** — 격자분할로 우회했지만 2단계(49질의)에서 멈춘다. 그래도 잘리면
   화면에 "일부 빠졌을 수 있음"으로 뜬다.
4. **인허가 짝맞추기를 안 붙였다.** 성인PC방은 이름 규칙으로만 거른다 — **새 업태가 생기면
   `pcBangNameFilter.ts`를 갱신해야 한다.**
5. **저장이 없다.** 초기추정과 정밀평가를 나중에 대조하려면 저장이 필요해진다(그때 결정).

## 7. ⚠️ 빌드 메모리 (이 작업 중 발견)

`npm run build`가 **Node 기본 힙(2GB)으로는 OOM**으로 죽는다. 타입 검사 하나가 이미
1.85GB를 쓴다(파일 2,347개, `npx tsc --noEmit --extendedDiagnostics`로 측정).
**이 도구 때문이 아니라 저장소 전체가 천장에 닿아 있는 것이다.**

```
NODE_OPTIONS=--max-old-space-size=8192 npm run build     # 이러면 통과한다
```

근본 해법 후보(아직 안 함): 빌드용 tsconfig에서 `*.test.ts` 제외, 큰 JSON을 import 대신
런타임 로드로 바꾸기(`src/lib/storeEval/data/rival2km.json` 152KB).
