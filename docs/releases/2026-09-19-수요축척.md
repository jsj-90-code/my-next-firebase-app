## 1. 인계 문서가 제안한 고치는 법은 **항등변환**이었다

`_specialDemand.test.ts`에 "독점 기하평균 정규화"가 해법으로 적혀 있고, 성적표에도
`정규화 A=6.885`라는 줄이 따로 찍힌다. 그래서 뭔가 달라진 것처럼 보인다. 아니다.

```
  정규화 상수 g = 1.2022   (독점 3곳의 배수 기하평균)
    A        5.7268 -> 6.8848   (정확히 g배)
    배수(없음)  1.0000 -> 0.8318   (정확히 1/g배)

  38곳 예측 매출 최대 차이:  0.000000%
  MAPE 22.51% -> 22.51% · 중앙 14.3% -> 14.3% · ±20% 63% -> 63% · 100%초과 6 -> 6곳
```

매장에 들어가는 건 **A × 배수 곱 하나**뿐이고, A는 그 뒤에 어차피 다시 맞춰진다.
배수를 g로 나누면 A가 g배 되어 곱이 그대로다. **각화 119.5%도 그대로 남는다.**

→ (1)절에 `expect(worst).toBeLessThan(1e-9)`로 굳혀 놨다. **다음 세션에서 또 시도하지 말 것.**

또 하나 정정: 인계 문서는 A를 *"중앙값을 쓰고 있어 사실상 가운데 1곳이 정한다"*고 적었는데,
`fitHoursPerUser`는 **기하평균**이다(`logMean`). 3곳이 전부 A에 들어간다.

## 2. 그럼 진짜로 무슨 일이 벌어지나 — 배수가 축척 표본을 찢는다

`fitHoursPerUser`는 독점 3곳의 로그잔차 기하평균이 1이 되게 A를 잡는다. **곱만 1로 묶일 뿐
흩어짐은 자유다.** 그래서 물어야 할 건 "각화가 100%냐"가 아니라 **"배수를 켜면 축척 표본
안쪽이 모이나 찢기나"**다.

```
  [배수 끔]  A=6.885
    탕정역점   산업단지  배수 1.00   필요 점유율  97.6%
    광주각화점  없음     배수 1.00   필요 점유율  99.4%
    남악점    기타     배수 1.00   필요 점유율  99.2%
    -> 최대÷최소 1.019배   로그표준편차 0.0084

  [지금 배수]  A=5.727
    탕정역점   산업단지  배수 1.39   필요 점유율  84.4%
    광주각화점  없음     배수 1.00   필요 점유율 119.5%
    남악점    기타     배수 1.25   필요 점유율  95.4%
    -> 최대÷최소 1.416배   로그표준편차 0.1439
```

**배수를 끄면 수요식이 독점 3곳을 2% 안에 맞춘다.** 이건 이 프로젝트에서 나온 제일 깨끗한
숫자다. 그리고 배수를 켜면 그게 41.6%로 벌어진다.

읽는 법이 중요하다. 탕정역·남악이 **진짜로** 통계에 안 잡히는 수요를 갖고 있다면, 배수 끔에서
그 둘의 필요 점유율이 각화보다 **높게** 나와야 한다(수요를 과소평가했으니 더 먹어야 하니까).
그래야 배수가 셋을 한 줄로 모은다. 실제로는 셋이 이미 한 줄이다 — **독점 조건에서 산업단지·기타의
추가 수요는 관측되지 않는다.**

### 표본이 얼마나 얇은지도 같이 드러났다 (잭나이프)

```
  [배수 끔]   A 흔들림 폭  2.9%   (한 곳 빼는 것만으로)
  [지금 배수]  A 흔들림 폭 21.3%
      각화 뺌 -> A -10.3% · MAPE 25.04% · 100%초과 8곳
```

배수가 축척을 **7배 더 불안정하게** 만든다. 38곳 전부가 이 3곳에 걸려 있다.

## 3. 그런데 배수를 버릴 수도 없다 — 관문 둘을 통과한다

여기서 "그럼 배수를 끄자"로 가면 틀린다. 세 가지를 확인했다.

### (가) 수준 옮기기가 아니다

배수가 하는 일이 그냥 "A를 16.8% 내리는 것"이라면 배수 없이 A만 내려도 같아야 한다. 아니다.

```
  배수 끔 (A 자유)          A=6.885  MAPE 22.93%  중앙 20.6%  ±20% 50%  100%초과  4곳
  배수 끔 + A를 배수값으로     A=5.727  MAPE 25.90%  중앙 19.5%  ±20% 55%  100%초과 12곳
  지금 배수                A=5.727  MAPE 22.51%  중앙 14.3%  ±20% 63%  100%초과  6곳
```

같은 A에서 25.90% vs 22.51%. **유형 차이가 진짜로 일을 한다.**

### (나) 무작위 대조군을 세 자 모두 통과한다

유형 이름표만 매장들 사이에서 500번 섞었다(배수 값도 유형별 곳수도 그대로).

```
              배수 끔    섞음 5%   섞음 중앙   섞음 95%   진짜 배정    p값
  MAPE       22.93%   24.59%   29.36%   34.66%   22.51%   0.006
  중앙         20.6%    18.3%    25.0%    33.7%    14.3%   0.000
  ±20%          50%      29%      42%      55%      63%   0.002
```

섞음 중앙(29.36%)이 배수 끔(22.93%)보다 **훨씬 나쁘다.** 아무 데나 붙여서 나오는 이득이 아니다.
이 프로젝트에서 대조군을 세 자 모두 이 정도로 통과한 항목은 드물다.

### (다) 부호 있는 오차도 같은 방향을 가리킨다

필요 점유율은 나눗셈이라 증거로 못 쓴다(어제 함정 2). 그래서 **부호 있는 매출 오차**로 다시 쟀다.
배수 끔 · A=6.885에서:

```
  없음      n=22  +6.0%      대학가    n=5  -2.9%
  기타      n= 4  +8.8%      산업단지   n=3  -20.6%
  관광·유흥  n= 2  -28.3%     군부대    n=2  -53.3%
```

군부대가 **53% 과소예측**된다 — 배수 2.25는 필요 점유율이 아니라 매출 오차로도 확인된다.

## 4. 17%는 경쟁 항에 살지 않는다 — 어제 B가 증상이었다는 가설은 **기각**

인계 문서의 제일 큰 기대는 *"어제 실패한 B(경쟁 항)와 C(두 매장)가 둘 다 A의 증상일 수 있다"*였다.
가르는 법: 배수 끔에서 부호 있는 오차를 독점/경쟁으로 갈라 본다. 경쟁상권만 치우쳐 있으면
경쟁 항이 범인이다.

```
  독점 3곳         부호오차 중앙  +4.7%
  경쟁 '없음' 21곳   부호오차 중앙  +6.0%
```

**거의 같다.** 독점이든 경쟁이든 "없음" 매장은 똑같이 6% 과대예측된다.
17% 수준 차이는 **독점↔경쟁의 차이가 아니라 유형 간의 차이**다.
→ 어제 B(경쟁 항)를 A의 증상으로 다시 꺼낼 근거는 없다.

| # | 시도 | 결과 |
|---|---|---|

### 3번이 왜 개념은 맞았나 — 진짜 순환은 여기다

**독점매장의 필요 점유율은 자유로운 측정값이 아니다.** A가 바로 그 값들의 기하평균이 1이 되게
맞춰지니까 셋은 100% 언저리에 **박혀 있다**(97.6 · 99.4 · 99.2). 그런데 배수 유도 규칙은
유형별 필요 점유율 중앙을 쓰면서 **그 박힌 값을 같이 넣는다.**

```
  기타    전체 4곳 중앙 63.8% -> 배수 1.26     <- 남악(박힌 99.2%)이 중앙을 끌어올린다
         경쟁 3곳 중앙 47.6% -> 배수 0.94
  산업단지  전체 3곳 중앙 70.2% -> 배수 1.39     <- 탕정역은 중앙이 아니라 영향 없음
         경쟁 2곳 중앙 70.2% -> 배수 1.39
```

**축척을 정한 매장이 배수도 정하고 있다.** 이게 인계 문서가 말한 "순환"의 실체이고,
정규화가 아니라 여기가 고칠 자리였다. 다만 고쳐 보니 성적이 안 따라왔다(위 3번).

### 유도 절차 자체는 LOO를 못 넘는다

```
  배수 끔                        LOO MAPE 22.94%  중앙 20.5%  ±20% 50%
  지금 배수 (고정 · 표본 안 유리)      LOO MAPE 23.15%  중앙 17.8%  ±20% 61%
  매번 다시 유도 — 전체로            LOO MAPE 26.81%  중앙 20.3%  ±20% 50%
  매번 다시 유도 — 경쟁만으로          LOO MAPE 27.05%  중앙 25.2%  ±20% 45%
```

유도된 배수가 한 곳 뺄 때마다 크게 흔들린다: **군부대 1.00~2.23 · 산업단지 1.39~1.93 · 기타 0.94~1.26.**
(군부대가 1.00으로 떨어지는 회차는 2곳 중 1곳이 빠져 "표본 2곳 미만" 규칙에 걸리는 경우다.)

**즉 배수의 방향은 진짜인데(대조군 통과) 값은 못 믿는다(LOO 실패 · 흔들림 큼).**

## 6. 남은 것 — 사용자 판단이 필요하다

배수를 켜고 끄는 게 **세 자에서 갈린다.** 둘 다 맞는 소리라 내가 고를 수 없다.

|  | 배수 끔 | 지금 배수 |
|---|---|---|
| 표본 안 MAPE | 22.93% | **22.51%** |
| 표본 안 중앙 | 20.6% | **14.3%** |
| 표본 안 ±20% | 50% | **63%** |
| **LOO MAPE** | **22.94%** | 23.15% |
| LOO 중앙 | 20.5% | **17.8%** |
| LOO ±20% | 50% | **61%** |
| 독점 3곳 흩어짐 | **1.019배** | 1.416배 |
| A 잭나이프 흔들림 | **2.9%** | 21.3% |
| 광주각화점 필요 점유율 | **99.4%** | 119.5% |
| 필요 점유율 100% 초과 | **4곳** | 6곳 |

- **정확도 세 자**는 배수 켬이 낫다(LOO MAPE만 뒤집힘).
- **구조 건전성 네 자**는 배수 끔이 전부 낫다.

지금 값을 그대로 두면 각화 119.5%를 안고 가는 것이고, 끄면 대조군을 통과한 신호를 버리는 것이다.
**세 번째 길**로 생각해 볼 만한 것(아직 측정 안 함, 다음 세션 후보):

1. **배수의 방향만 쓰고 크기를 줄이기** — 예: 배수를 √배수로 눌러 흔들림을 줄인다.
   대조군은 방향을 지지하지만 LOO는 크기를 못 믿는다고 말하고 있으니 결이 맞다.
   ⚠️ 눌림 정도를 MAPE로 고르면 그게 눈금 옮기기다. 고르는 자를 먼저 정해야 한다.
2. **군부대를 따로 떼기** — 매출 오차 −53.3%로 다른 유형과 차원이 다르다. n=2가 걸림돌.
3. **축척 표본을 늘리기** — 독점매장이 3곳뿐인 게 뿌리다. 매장 45~50곳 되면 자연히 풀린다.

## 7. 문경시청·양주덕정은 어떻게 됐나 (인계 문서 4절)

A를 고치진 못했지만, **두 곳의 숫자가 배수에 얼마나 업혀 있었는지는 갈렸다.**

```
                 배수 끔      지금 배수
  문경시청점      188.2%      226.3%
  양주덕정점      119.9%      144.2%
```

- **양주덕정점(119.9%)은 배수 끔에서 각화(99.4%)와 크게 다르지 않다.** 144.2%의 상당 부분이
  배수가 만든 수준 이동이었다. 개별 사정으로 팔 만큼 특별한 매장이 아닐 수 있다.
- **문경시청점은 배수를 꺼도 188.2%다.** 이건 진짜다. 인계 문서 4절의 목록(반경 밖 손님 ·
  가동률 원자료 · 유동인구 단조성 · 단가층)을 그대로 파면 된다.

즉 4절의 "두 곳"은 사실상 **한 곳**이다.

그건 배수가 만든 119.5%다(본문 2절).

## B. 사용자 가설 — PC방 공백 상권이라 넓은 데서 손님이 온다

사용자가 네이버지도로 직접 보고 세운 가설이다. *"양주덕정점은 반경 2키로내에 인접 경쟁매장 빼고
PC방이 없어 (...) 상가들이 학교근처에 있어서 못들어가네 다른 상권에 PC방이."*

기전은 말이 된다 — 학교환경위생정화구역 때문에 주변 상권에 PC방이 못 들어오면, 그 수요가
갈 곳이 여기밖에 없고, 400m·1km로 센 수요보다 훨씬 넓은 데서 손님이 온다.

### 검정 결과 — 기전은 맞는데 대리자가 반대로 나왔다

우리 경쟁점 자료는 **500m까지밖에 없다**(229곳 중 228곳이 0~500m). 2km 공백은 자료로 확인이
안 된다. 그래서 **공급부족도 = 1km 주거인구 ÷ (자사PC + 500m 경쟁PC)**로 같은 기전을 쟀다.
가설이 맞다면 공급부족도가 높은 매장을 과소예측해야 한다(음의 상관).

⚠️ 필요 점유율은 분모에 예측값이 들어가 자기 자신과 상관이 난다(어제 함정 2). 그래서
검정에는 **부호 있는 매출 오차**를 썼다 — 분모가 실매출이라 안 얽힌다.

```
  순위상관 r = +0.463   t = 3.13 (유의선 2.03)   <- 가설과 **반대 부호**

  공급부족도 4분위 (낮음 = PC방 흔한 동네)
    1분위  인구/PC  49   매출오차 중앙 -40.3%
    2분위  인구/PC  71   매출오차 중앙 -11.8%
    3분위  인구/PC 112   매출오차 중앙  +1.0%
    4분위  인구/PC 225   매출오차 중앙  +2.9%
```

**PC방이 흔한 동네를 심하게 과소예측한다.** 모자란 동네는 오히려 잘 맞는다.

그리고 양주덕정점은 공급부족도 49로 **제일 낮은 분위**다. 경쟁점 자료를 펼쳐 보면:

```
  양주덕정점  자사 119대
    더캠프     90m  110대  (실측)
    PC나인     95m  243대  (실측)
    엔터나인   170m  105대  (실측)
    -> 170m 안에 458대. 전부 추정이 아니라 실측값이다
```

사용자가 본 "인접 경쟁매장"이 이 **세 곳 뭉치**다. 2km 밖 공백은 우리 자료로 확인이 안 되지만,
적어도 **바로 옆은 비어 있지 않다.**

## C. 그럼 뭐가 상관있나 — 갈라 보니 주거인구였다

공급부족도는 분자(주거인구)와 분모(총PC)가 같이 움직인다. 갈랐다.

```
  공급부족도 (주거÷총PC)   r = +0.463  t = 3.13  유의
  주거인구 1km           r = +0.340  t = 2.17  유의     <- 이게 범인
  경쟁 PC 수             r = -0.089  t = 0.54    -
  유동인구 400m          r = -0.038  t = 0.23    -
  경쟁PC ÷ 자사PC        r = -0.106  t = 0.64    -

  경쟁상권 35곳만: 경쟁 PC 수 r = -0.013  t = 0.08  유의하지 않다
```

**경쟁은 아무 상관이 없다.** 어제 B(경쟁 항이 과하다)를 여기서도 지지하지 않는다 —
본문 4절의 독점↔경쟁 검정과 같은 결론이다.

### 교란 둘을 걷어내도 남는다

```
  [지금 배수]  전체 38곳  주거1km   r = +0.340  t = 2.17  유의
              '없음' 22곳 주거1km   r = +0.459  t = 2.31  유의
              '없음' 22곳 유동400m  r = +0.111  t = 0.50    -
  [배수 끔]    전체 38곳  주거1km   r = +0.535  t = 3.80  유의
              '없음' 22곳 주거1km   r = +0.459  t = 2.31  유의
```

특수수요 유형을 "없음" 22곳으로 묶어도, 배수를 꺼도 살아남는다.
**그리고 유동인구층에는 이 현상이 없다 — 주거층에만 있다.**

양수 = 인구 많은 동네를 과대예측 = **작은 동네를 과소예측한다.**

### 어제 10번(수요 ∝ 인구^b)과 같은 것인가 — 아니다, 더 좁다

어제 기각된 건 **전체 수요**에 지수를 건 것이었다. 여기서 나온 건 **주거층에만** 있는 현상이고
유동층은 r=0.111로 깨끗하다. 지수를 전체에 걸면 유동층까지 같이 휘어서 기각된 것일 수 있다.

물리적으로도 말이 된다 — **작은 동네일수록 상권 반경이 1km보다 넓다.** 시골에서는 차로 다니고,
문경시내 사람이 문경시청점에 온다. 유동인구는 400m 안에서 이미 세고 있으니 반경 문제가 덜하고,
주거인구만 1km로 잘려 있다.

**사용자의 직관(상권이 산식이 보는 것보다 넓다)은 자료가 지지한다.** 다만 그 이유가
"PC방이 없어서"는 아니고 "**주거 반경이 작은 동네에서 너무 좁아서**"로 보인다.

⚠️ 아직 아무것도 안 바꿨다. 지수나 반경을 여기서 고르면 그게 어제 열 번 밟은 함정이다.
   다음 단계는 **주거 반경 자체를 넓혀 보는 것**이지 계수를 새로 만드는 게 아니다.
   `sgis-resident-population.json`에 500m·1km가 있는데 2km가 있는지 먼저 확인해야 한다.

## G. 사용자가 가설을 더 정확히 다시 줬다 — 내 검정이 왜 빗나갔는지 설명된다

사용자(2026-09-19, 같은 날 저녁):
> *"양주덕정점 매장 주변에 PC방이 있긴 한데, 주변 반경 뭐 300미터 정도 되나 **여기에 있는
> PC방이 반경 2키로에 있는 전부**라고. 그래서 잘됐나봐. 그리고 그 반경 2키로가 죽은 상권이
> 아니라 다 상권이 형성되어 있고 **초중고가 다 있는** 상태임. 그 반경 2키로에 경쟁점 없는
> 이유는 **학교정화구역 때문에 PC방이 입점 불가**한 상황인가봐."*

**B절의 검정은 틀린 자로 쟀다.** 내가 쓴 공급부족도는

```
  공급부족도 = 1km 주거인구 ÷ (자사PC + **500m** 경쟁PC)
```

인데, 사용자가 말하는 상권은 **2km**다. 분자도 분모도 상권보다 좁은 반경으로 쟀으니,
300m 뭉치 바로 옆만 보고 "PC방 흔한 동네"라고 읽은 것이다. **상권 단위로 다시 재면
정반대일 수 있다.** B절의 "가설과 반대 부호"는 가설을 기각한 게 아니라 **측정이 못 미친 것**이다.

그리고 C절에서 독립적으로 나온 것(주거층에만 있는 과소예측 · 작은 동네일수록)은
이 기전과 **같은 방향**이다.

### 얼마나 움직여야 설명되나 — 민감도

수요에서 주거가 차지하는 몫이 생각보다 크다.

```
  매장           주거 몫  유동 몫   필요점유율   주거 2배면   주거 3배면
  문경시청점        83%    17%    226.3%     123.4%      84.8%
  양주덕정점        84%    16%    144.2%      78.5%      53.9%
  강릉교동점(신)     67%    33%    108.3%      65.0%      46.5%
  구미산동점        84%    16%    103.7%      56.4%      38.8%
  인천서창점        80%    20%    100.9%      56.1%      38.9%
  (38곳 주거 몫 중앙 81% · 최소 56% · 최대 96%)
```

**양주덕정점은 주거를 2배로만 잡아도 78.5%로 들어온다.** 2km 상권이 사실이라면
(면적 4배 · 바깥 고리 밀도가 안쪽의 1/3만 돼도 약 2배) 숫자가 맞는다.
문경시청점은 2.5배쯤 필요하다.

### ⚠️ 그런데 "반경을 그냥 넓히자"는 답이 아니다

반경을 38곳 전부에 똑같이 넓히면 **큰 동네가 같이 커진다.** 오히려 시골은 1km 밖이
논밭이라 덜 늘고 도심은 4배 가까이 느는 게 보통이라, 작은 동네 과소예측이 **더 심해질**
수 있다. 사용자가 말한 기전은 "반경이 어디나 넓다"가 아니라

> **"경쟁점이 막혀 있어서 이 매장의 상권만 넓다"**

이다. 즉 변수는 반경이 아니라 **경쟁 공백 범위**다.

### 그걸 재려면 자료 둘이 더 있어야 한다 (지금 없다)

```

  2. 2km 안 PC방 분포   경쟁점 자료는 500m까지다(229곳 중 228곳)
                      -> 카카오 장소검색 meta.total_count로 반경별 PC방 개수를 센다
                         (scripts/collectKakaoPlaceDensity.mjs와 같은 방식,
                          업종코드엔 PC방이 없어 키워드 검색을 써야 한다)
```

둘이 모이면 **상권 반경으로 다시 잰 공급부족도**가 나오고, B절을 제대로 다시 검정할 수 있다.
그리고 "경쟁 공백 반경"이 38곳에서 과소예측을 설명하는지도 관문(LOO·대조군)에 걸 수 있다.

⚠️ 아직 수집 안 했다 — 외부 API를 부르는 일이라 사용자 승인 후에 한다.

```
  (가) 경쟁력 항목으로서의 주차 — 우리는 되고 경쟁점은 안 된다
       -> 경쟁 항이다. 문경은 천장이 3.6%p뿐이다(backlog 2026-09-19)
  (나) 상권 반경 요인으로서의 주차 — 차로 오니까 먼 데서도 온다
       -> 수요 항이다. 천장이 없다. 오늘 나온 "저인구 동네 과소예측"과 결이 같다
```

### 자료가 한 건도 없다

기존점·경쟁점·입지평가 **전부 0건**이다. 가장 가까운 기존 항목인 `inflowRestriction`
(유입제한)은 주차가 아니라 물리적 진입 장벽 쪽이고, 산식에도 안 쓰인다. 참고로 재 보면:

```
  inflowRestriction ↔ 부호오차   r = -0.150  t = 0.91 (선 2.03)  유의하지 않다
    없음 n=19 -9.6% · 보통 n=16 -12.9% · 강함 n=3 +1.0%
```

### 밑바탕은 이미 있다

"손님이 멀리서 온다"는 자국은 자료에 **이미 있다** — 주거인구 1km ↔ 부호오차 r=+0.340(유의).
저인구 동네를 과소예측한다. **빠진 건 "그 이유가 주차냐"다.**

### 재려면 — 싼 길이 있다

```
  (나) 수요 쪽만 보려면 **자사 41곳 주차 가능 여부**만 있으면 된다. 경쟁점 229곳은 필요 없다
       — 우리 손님이 얼마나 멀리서 오느냐는 우리 주차 사정만의 문제이기 때문이다
  (가) 경쟁력 쪽까지 보려면 경쟁점 229곳도 채워야 한다
```

⚠️ 자사만 채우는 건 보통 '자사 전용 이름표 함정'에 걸리는데, (나)는 **자사 안에서 갈리는
   값**이라(되는 곳/안 되는 곳) 그 함정에 안 걸린다.

⚠️ 다만 사용자가 말한 건 사실상 **상호작용**(주차 × 거리)이다. n=38에서 상호작용은
   단독 변수보다 훨씬 잡기 어렵다 — 어제 단독 변수 열 개가 전부 기각됐다.
   **먼저 주차 단독으로 걸어 보고, 그게 안 되면 상호작용은 접는 게 맞다.**

## S. 맞다 — 점촌터미널 233m, 점촌 시내 상업핵 한복판이다

카카오로 문경시청점 주변을 훑었다 (2026-09-19).

```
  점촌터미널(시외버스)   233m        문경중앙시장   1,094m
  음식점  300m 71곳 / 500m 163곳 / 1km 303곳      대형마트 300m 안 4곳
  카페    300m 18곳 / 500m  33곳                학원  1km 59곳
  영화관  0곳

  유동인구 고리 밀도(명/km²)
    0~100m 185,000 · 100~200m 120,000 · 200~300m 38,500 · 500~1000m 10,200
```

**문경시는 911km²에 인구 6만 남짓인데 그게 점촌 한 곳으로 모인다.** 그 한복판에 우리 매장이
있고 시외버스터미널이 233m다. 사용자 짐작이 맞다.

## T. 그런데 그걸 산식에 반영해도 안 풀린다

이 자리 수요는 1km 주민이 아니라 **시 전역에서 흘러드는 사람**이다. 그런데 산식은 문경을
주거 83% : 유동 17%로 센다. 원자료는 반대인데도 그렇다:

```
  유동 400m 27,745명  >  주거 1km 18,786명     <- 원자료는 유동이 더 크다
  그런데 floatingFactor(α) = 0.15를 곱한다      <- "스쳐 가는 사람이 대부분"이라서
  -> 유동 기여가 1/6로 줄어 주거가 83%가 된다
```

그래서 α를 올려 봤다. **문경이 거의 안 움직인다.**

```
      α     MAPE     중앙   ±20%    최대  100%초과   문경 필요점유율   문경 유동몫
   0.15   22.51%   14.3%   63%    62%     6곳       226.3%      17%   <- 지금
   0.20   22.19%   18.4%   63%    62%     5곳       224.6%      21%
   0.30   22.52%   19.2%   55%    62%     4곳       221.5%      28%
   0.50   23.72%   22.2%   45%    66%     3곳       216.5%      40%
   1.00   26.35%   22.0%   45%    75%     3곳       208.0%      57%
```

α를 0.15에서 **1.00까지(유동인구를 100% 손님으로 세도)** 문경은 226.3% → 208.0%다.
그동안 38곳 성적은 MAPE 22.51→26.35%, ±20% 63→45%로 무너진다.

**왜 안 움직이나**: α를 올리면 모든 매장 수요가 같이 커지고, 축척 A가 독점 3곳에서 다시
맞춰지며 그만큼 내려간다. 문경의 유동/주거 비(1.48)가 다른 매장과 크게 다르지 않아
상대 위치가 거의 그대로다.

⚠️ α=0.20 칸의 MAPE 22.19%를 집으면 안 된다 — 중앙이 14.3%→18.4%로 나빠진다.
   어제 두 번 밟은 "MAPE만 좋아지는 변경"이다. α는 "스쳐 가는 사람 중 몇 %가 손님이냐"는
   **물리량**이라 성적이 아니라 자료로 재야 한다(`docs/backlog.md`에 열린 항목으로 있음).
