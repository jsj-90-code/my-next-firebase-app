# 2026-10-29 · 좌석배치도 — 책상 인식 단계 없애기(존 초안 한 번에 수량·사이즈·브라켓)

## 왜
사용자 「초단순화」: 도면 입력 → 존 초안 → 책상 수량 채우기 → 마무리로 채팅을 두 번 시키던 것을 한 번으로.
도면 PDF에 책상마다 치수 글씨("850*680")가 이미 들어 있고(10-28 존 상자 맞춤에서 위치만 쓰고 폭은 버렸음), 이걸로 세면
AI 어림 없이 정확하다. 브라켓은 무조건 들어가는 값이라(사용자) 따로 단계를 두면 줄어드는 게 없다 → 존 초안을 낸 같은 채팅에서 이어서 센다.

## 새 순서 (책상 발주 도면 탭)
1. 매장명 입력해야 도면 업로드가 열림 → PDF에서 브라켓 도면(보통 3쪽) 고르고 자르면 **자동 저장**
2. Claude 앱에 "○○점 존 초안 만들어 줘" → 채팅이 존 초안을 내고 **이어서** 상자마다 브라켓을 셈
   (`get_seat_layout_bracket_crops`/`submit_seat_layout_brackets`, source=draft)
3. [채팅 존 초안 불러오기] 한 번 → 존 + 책상 수량·사이즈(웹이 PDF 글씨로) + 브라켓
4. 존을 고치면(옮기기·크기·새로 그리기) 수량·사이즈는 즉시 다시 세고, 브라켓만 그 존이 "다시 세기"가 됨 →
   저장 후 "○○점 바뀐 존 브라켓 다시 세 줘"(source=changed) → [채팅 결과 불러오기]
5. [확인하고 통합발주서 등록] — 합계를 한 번 보여 주고 저장·등록. 브라켓 안 센 존이나 존 밖 책상이 남으면 막음.

- PC 대수 = 책상 수(사용자 10-29). PC 존도 같은 방식으로 자동으로 셈. 카운터는 책상 발주 도면에 없고 PC 발주 도면에만 있음 —
  책상이 하나도 안 든 존(카운터)은 손대지 않고 손으로 넣은 값 유지.
- PDF 글씨가 없는 옛 도면(폭 정보 없음)은 예전 순서(존 다듬고 저장 → "책상 인식해 줘") 그대로.
- 브라켓을 센 존 모양은 존마다 `bagShelfKey`(zoneShapeKey)로 남긴다 — 지금 모양과 다르면 다시 세기.

## 시험
- 단위 시험 52개 통과(새로: 존별 수량·사이즈, 걸친 책상은 작은 존 몫, 카운터 null, 옛 도면 null, 표준 밖 폭, 자를 때 폭 유지 / 커넥터 도구 목록 13·10개).
- 실데이터: 운영 매장 3곳의 저장된 책상 합계·사이즈별 수량 = 브라켓 도면(3쪽) PDF 글씨 수, **세 곳 모두 사이즈별로 일치**
  (울산삼산 99 · 평택소사벌 114 · 호구포 94). 존별 대조는 못 함 — TEST 프로젝트가 지워졌고 운영 3곳은 글씨 위치 저장 전에 만든 것.
- 빌드 통과. 브라우저 실사용(새 프로젝트로 한 바퀴)은 아직 — 사용자 확인 필요.

## 틀린 줄 알고 뺀 것
- 처음엔 도면 제목 옆 "브라켓 수량 90개(+5 여유)"로 브라켓 합을 검산하려 했다. 확대해 보니 이 숫자는 **부품 수**다 —
  주황 점이 책상과 책상 경계마다 찍혀 한 줄 3석이면 4개. 발주서 값은 "브라켓 달린 책상 수"라 다르다
  (평택: 부품 90 · 저장값 59, 울산 34 · 35, 호구포 58 · 62). 검산은 넣지 않았고, 채팅 지시문에 "점이 아니라 선이 지나가는 책상을 세라"를 넣었다.

## 같은 날 추가 — 카드는 기존 디자인으로 되돌리고 크기만 · 이름표가 사이즈 표 피하기

## 같은 날 추가 — 광주첨단점TEST: 세레머니 팀룸 2개 · 브라켓 오탐 · VIP 검산
- 세레머니 팀룸은 매장마다 2개 — 존 초안을 넣을 때 2개가 안 되면 4인룸을 세레머니 팀룸으로 바꿔 채움(앞 4인룸부터), 지시문에도.

  덮인 구간의 합집합으로 잼. 시험 PDF: 울산 32 · 평택 71 그대로, 호구포는 49→48로 줄었다가, 사용자 「49가 맞다 — 기둥 밑 850은 선을 짧게 쳤다」로 "책상 양 끝에 주황 점이 둘 다 있으면 선이 짧아도 브라켓"을 더해 다시 49(점은 곡선·짧은 직선 다각형 둘 다 — 작고 정사각형에 가까운 주황 도형).

  ("다른 폭 줄은 friends/하드웨어 존, 칸막이로 혼자 둘러싸인 1000mm 1석은 one_seat"), 지시문에도.

- 광주: 창가 칸에서 통로를 사이에 두고 마주 보는 프렌즈 두 줄이 B·C로 갈림 → 존 초안을 넣을 때 마주 보는 같은 유형 프렌즈·VIP를 한 존으로
  합침(mergeFacingZones: 마주 보는 범위 70%+ 겹침, 틈 1.5m 이하, 합친 상자가 다른 존과 30cm 넘게 겹치거나 다른 존 책상을 먹으면 안 합침). 지시문에도.
- FPS 고르는 순서에 "통로를 사이에 두고 마주 보는 두 줄의 합이 딱 10석"(광주: LOL A 5 + LOL B 왼쪽 줄 5)을 2순위로 — 등 맞댄 섬 하나(10석)·11석 줄보다 먼저(사용자).
  커넥터: FPS 실제가 10석이 아니면 한 번 되돌려 딱 10석 조합을 묻고, AI가 note에 "10석 조합 없음"을 적으면 통과(10석 미만 되돌림도 같은 통과 조건 — 반복 방지).

  (1인석·멀티·LOL·FPS·FC 등). 방은 10-27 「팀룸 따로따로」 그대로. 광주: 프렌즈 B+C, 커플석 A+B, 1인석 A+B, LOL A+B가 한 존씩.
- 이어서 사용자 「룸도 합칠 수 있으면 합쳐」: 방 포함 모든 유형(같은 유형끼리, 같은 기준). 채팅은 방마다 상자를 내고 웹이 넣을 때 합침.

## 10-30 — 합친 상자에 빈 공간이 크면 따로(울산삼산점TEST 팀룸)
- 세로로 긴 세레머니 팀룸 + 가로로 긴 팀룸이 아래 끝만 맞아 ㄴ자인데, 감싸는 네모로 합쳐 빈 귀퉁이까지 존이 됐다(빈 공간 ≈ 두 방 넓이의 49%).
- 존은 네모만 저장되므로 ㄴ자 존 대신: 합친 상자에서 두 상자와 사이 통로 띠를 뺀 빈 공간이 두 상자 넓이 합의 20%(`MERGE_MAX_EMPTY`)를
  넘으면 합치지 않는다. 광주 프렌즈 B·C·1인석·커플석과 울산 2인룸 둘은 나란해서 빈 공간 ≈ 0% — 그대로 합친다.
- 채팅 지시문에도 "ㄴ자처럼 어긋나면 따로" 한 줄.

## 10-30 — 채팅 결과 저절로 넣기
- 사용자 「앱으로 안 가고 웹에서 바로, 가능하면 자동으로」 → 채팅(AI 인식)은 그대로 앱에서(유료 API 안 씀), **불러오기만 자동**.
- 웹이 `seatLayoutChatDrafts/{프로젝트}`를 실시간으로 지켜보다가(예전: 창에 돌아올 때 한 번 읽기) 이 프로젝트를 **연 뒤에** 새로 온 결과를 넣는다.
  존 초안·브라켓·좌석번호는 바로, 책상·PC는 확인 창만 띄움. 열기 전에 와 있던 결과는 버렸던 것일 수 있어 예전처럼 알림 띠·버튼으로만.
- 존 초안은 채팅이 덮어쓸 수 있어(FPS·VIP 되돌림, 브라켓 이어 세기) 먼저 넣으면 존이 두 번 들어간다 → 서버가 마지막 초안에 `final: true`를
  붙이고(되돌림 없음 + 브라켓 이어 세기 없음, 또는 브라켓까지 다 셈) 웹은 그것만 자동으로 넣는다.
- 채팅 답 안내·작업 순서에 "열어 두었으면 저절로" 한 줄. 커넥터 도구 입력은 안 바꿔서 재연결 필요 없음.

## 10-30 — 책상 통합발주서 등록 때 PC 발주 도면 자동 반영
- 사용자 「수량 확인/통합발주서 등록을 누르면 PC 발주 도면에 존 구성 자동 반영」: 등록하면서 PC 존을 책상 존 구성으로 맞춰 같이 저장한다.
  같은 이름·유형 PC 존의 사양은 유지. PC 탭에서 따로 나눈 존이 있으면 덮어쓸지 묻고, [취소]면 PC 존은 그대로(등록만).
- 사용자 「자동 반영된 경우 책상 구역 불러오기는 생략, 반영 안 된 경우는 그냥」: PC 존 모양이 책상 존과 같으면 PC 탭 작업 순서에서
  "책상 구역 불러오기" 단계를 뺀다.
- 사용자 「책상 저장하고 다시 수정한 경우는?」: 반영 직후 PC 존 모양을 `pcSyncedKey`로 남긴다. 지금 PC 존이 그대로면(PC 탭에서 안 건드림)
  책상 존을 고쳐 **저장만 해도** PC 존이 따라가고, 다시 등록할 때 옛 이름이 남은 것을 "PC에서 나눈 존"으로 오해해 묻지 않는다.
  PC 탭에서 나누거나 대수를 고친 뒤면 PC 존은 그대로(등록 때는 덮어쓸지 물음). [책상 구역 불러오기]도 같은 표시를 남긴다.
