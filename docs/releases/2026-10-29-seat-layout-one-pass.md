# 2026-10-29 · 좌석배치도 — 책상 인식 단계 없애기(존 초안 한 번에 수량·사이즈·브라켓)

## 왜
사용자 「초단순화」: 도면 입력 → 존 초안 → 책상 수량 채우기 → 마무리로 채팅을 두 번 시키던 것을 한 번으로.
도면 PDF에 책상마다 치수 글씨("850*680")가 이미 들어 있고(10-28 존 상자 맞춤에서 위치만 쓰고 폭은 버렸음), 이걸로 세면
AI 어림 없이 정확하다. 브라켓은 무조건 들어가는 값이라(사용자) 따로 단계를 두면 줄어드는 게 없다 → 존 초안을 낸 같은 채팅에서 이어서 센다.

## 새 순서 (책상 발주 도면 탭)
1. 매장명 입력해야 도면 업로드가 열림 → PDF에서 브라켓 도면(보통 3쪽) 고르고 자르면 **자동 저장**
2. Claude 앱에 "○○점 존 초안 만들어 줘" → 채팅이 존 초안을 내고 **이어서** 상자마다 브라켓을 셈
   (`get_seat_layout_bracket_crops`/`submit_seat_layout_brackets`, source=draft)
3. [채팅 존 초안 불러오기] 한 번 → 존 + 책상 수량·사이즈(웹이 PDF 글씨로) + 브라켓
4. 존을 고치면(옮기기·크기·새로 그리기) 수량·사이즈는 즉시 다시 세고, 브라켓만 그 존이 "다시 세기"가 됨 →
   저장 후 "○○점 바뀐 존 브라켓 다시 세 줘"(source=changed) → [채팅 결과 불러오기]
5. [확인하고 통합발주서 등록] — 합계를 한 번 보여 주고 저장·등록. 브라켓 안 센 존이나 존 밖 책상이 남으면 막음.

- PC 대수 = 책상 수(사용자 10-29). PC 존도 같은 방식으로 자동으로 셈. 카운터는 책상 발주 도면에 없고 PC 발주 도면에만 있음 —
  책상이 하나도 안 든 존(카운터)은 손대지 않고 손으로 넣은 값 유지.
- PDF 글씨가 없는 옛 도면(폭 정보 없음)은 예전 순서(존 다듬고 저장 → "책상 인식해 줘") 그대로.
- 브라켓을 센 존 모양은 존마다 `bagShelfKey`(zoneShapeKey)로 남긴다 — 지금 모양과 다르면 다시 세기.

## 시험
- 단위 시험 52개 통과(새로: 존별 수량·사이즈, 걸친 책상은 작은 존 몫, 카운터 null, 옛 도면 null, 표준 밖 폭, 자를 때 폭 유지 / 커넥터 도구 목록 13·10개).
- 실데이터: 운영 매장 3곳의 저장된 책상 합계·사이즈별 수량 = 브라켓 도면(3쪽) PDF 글씨 수, **세 곳 모두 사이즈별로 일치**
  (울산삼산 99 · 평택소사벌 114 · 호구포 94). 존별 대조는 못 함 — TEST 프로젝트가 지워졌고 운영 3곳은 글씨 위치 저장 전에 만든 것.
- 빌드 통과. 브라우저 실사용(새 프로젝트로 한 바퀴)은 아직 — 사용자 확인 필요.

## 틀린 줄 알고 뺀 것
- 처음엔 도면 제목 옆 "브라켓 수량 90개(+5 여유)"로 브라켓 합을 검산하려 했다. 확대해 보니 이 숫자는 **부품 수**다 —
  주황 점이 책상과 책상 경계마다 찍혀 한 줄 3석이면 4개. 발주서 값은 "브라켓 달린 책상 수"라 다르다
  (평택: 부품 90 · 저장값 59, 울산 34 · 35, 호구포 58 · 62). 검산은 넣지 않았고, 채팅 지시문에 "점이 아니라 선이 지나가는 책상을 세라"를 넣었다.
