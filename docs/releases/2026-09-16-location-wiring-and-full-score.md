## 1. 좌표표가 42곳에서 새고 있었다 — 원인은 수집기가 아니라 주소변환기

3번을 52곳 채우려는데 `.local-tools/geocoded-sites.json`이 42곳(기존점 41 + 후보지 1)에서
멈춰 있었다. 후보지 10곳은 **운영 DB에 좌표가 멀쩡히 있었는데**, `geocodeExistingStores.mjs`가
"좌표 있으면 조회할 필요 없다"며 건너뛰면서 **기록도 안 남긴** 탓이었다.

이 파일을 전제로 도는 수집기(유동인구·주거인구·편심도)는 여기 없는 지점을 통째로 못 본다.
조회는 그대로 건너뛰되 좌표표에는 편입하도록 고쳤다(`method: "운영DB"`).

```
조회 성공 42곳 · 실패 0곳 · 운영DB 편입 10곳 · 좌표표 총 52곳
```

## 3. 조립 코드를 한 곳으로 모았다 (`labInput.ts` 신설)

측정 하네스가 화면의 조립 코드를 **베껴 쓰고** 있었다. 그래서 입지 5항목이 화면에만
추가됐을 때 하네스는 `location`을 아예 안 넘겼고, 그 상태로 잰 MAPE 54.6%가 한동안
"교과서식 성적"으로 돌아다녔다.

`buildLabRows()` 하나로 모았다. 화면과 하네스가 같은 함수를 부르므로 **새 항목을 화면에
붙이면 하네스도 자동으로 같이 본다.** 이 종류의 사고가 구조적으로 안 난다.

## 4. ⭐ 입지를 붙인 전체 MAPE — 처음 쟀다. 그리고 결과가 반대다

하네스: `_textbookFull.test.ts` (신규, gitignore 예외 편입)
표본 38곳 · 파라미터 `DEFAULT_TEXTBOOK_PARAMS` + `outsideOptionIp: 500`

### 항목별

| 입지 처리 | MAPE | 중앙 | ±20% | 최대 |
|---|---:|---:|---:|---:|
| 입지 없음 | 44.86% | 39.5% | 26% | 139% |
| 중심도만 | **54.50%** | 52.4% | 13% | 121% |
| 접근성만 | **38.64%** | 31.3% | 21% | 130% |
| 중심도+접근성 (지금 기본값) | 45.86% | 41.9% | 24% | 112% |

### 계수를 훑으면 방향이 분명하다

```
[중심도 ν]  0 → 38.64%   0.1 → 41.65%   0.25 → 45.86%   0.5 → 55.38%   (올릴수록 나빠진다)
[접근성 κ]  0 → 54.50%   0.1 → 50.79%   0.25 → 45.86%   0.5 → 42.87%   (올릴수록 좋아진다)
```

**점유율에서 고른 값과 매출에서 좋은 값이 갈린다.** `_locationRebuild.test.ts`(경쟁상권 29곳,
점유율 잔차)에서는 중심도가 제일 강했고(대조군 MAPE p=0.002) 접근성은 턱걸이(p=0.046)였다.
전체 파이프라인에서는 **정확히 뒤집힌다.**

### 왜 그런가 — 이중계산으로 보인다

수요식은 **유동 400m**를 쓰고, 중심도는 **유동 300m ÷ 유동 1km**다. 둘이 겹친다.

```
중심도 ↔ 수요식 유동400m 상관  r=0.605  (n=38)
```

점유율만 볼 때는 수요 다리가 고정돼 있어 이 겹침이 안 드러났다. 매출까지 가면 수요가
이미 센 유동 밀도를 **점유율에서 한 번 더 곱하는** 셈이 된다. 그래서 ν를 올릴수록
단조롭게 나빠진다.

`_locationRebuild.test.ts` ⑧번이 "수요식 반경의 그림자가 아니다"를 이미 검정했지만,
그건 **점유율 잔차 안에서** 반경을 바꿔본 것이라 전체 파이프라인의 이중계산은 못 잡는다.

### ⚠️ 채택하지 않았다

숫자가 좋아졌다고 계수를 바꾸지 않는다([[storeeval-experiment-judgment]] · `docs/backlog.md`
산식 실험 판정 기준). 여기 있는 건 **측정**이고, 채택은 무작위 대조군 + 기전 설명이
있어야 한다. 기준선 44.86%도 기록 29.42%와 표본·구성이 달라 직접 비교가 안 된다.

**사람이 정할 것**: 중심도를 (a) 끌지, (b) 수요식과 안 겹치는 형태로 다시 정의할지
(예: 유동이 아니라 카카오 업소밀도판 — ⑨에서 약하다고 접었던 것), (c) 점유율 쪽 결론을
믿고 그대로 둘지.

### 유동 방향 ω (참고 — 켜지 않았다)

```
ω=0 → 45.86%   0.1 → 45.08%   0.25 → 44.33%   0.5 → 43.67%   1 → 42.40%
```
올릴수록 좋아지지만 이건 위 중심도 문제와 얽혀 있다(중심도가 나쁜 쪽으로 당기는 걸
방향 항이 상쇄하는 모양일 수 있다). **대조군을 못 넘은 항목이라 0으로 둔다.**
