## 4. ⭐ 입지를 붙인 전체 MAPE — 처음 쟀다. 그리고 결과가 반대다

하네스: `_textbookFull.test.ts` (신규, gitignore 예외 편입)
표본 38곳 · 파라미터 `DEFAULT_TEXTBOOK_PARAMS` + `outsideOptionIp: 500`

### 항목별

| 입지 처리 | MAPE | 중앙 | ±20% | 최대 |
|---|---:|---:|---:|---:|
| 입지 없음 | 44.86% | 39.5% | 26% | 139% |
| 중심도만 | **54.50%** | 52.4% | 13% | 121% |
| 접근성만 | **38.64%** | 31.3% | 21% | 130% |
| 중심도+접근성 (지금 기본값) | 45.86% | 41.9% | 24% | 112% |

### 계수를 훑으면 방향이 분명하다

```
[중심도 ν]  0 → 38.64%   0.1 → 41.65%   0.25 → 45.86%   0.5 → 55.38%   (올릴수록 나빠진다)
[접근성 κ]  0 → 54.50%   0.1 → 50.79%   0.25 → 45.86%   0.5 → 42.87%   (올릴수록 좋아진다)
```

**점유율에서 고른 값과 매출에서 좋은 값이 갈린다.** `_locationRebuild.test.ts`(경쟁상권 29곳,
점유율 잔차)에서는 중심도가 제일 강했고(대조군 MAPE p=0.002) 접근성은 턱걸이(p=0.046)였다.
전체 파이프라인에서는 **정확히 뒤집힌다.**

### 왜 그런가 — 이중계산으로 보인다

수요식은 **유동 400m**를 쓰고, 중심도는 **유동 300m ÷ 유동 1km**다. 둘이 겹친다.

```
중심도 ↔ 수요식 유동400m 상관  r=0.605  (n=38)
```

점유율만 볼 때는 수요 다리가 고정돼 있어 이 겹침이 안 드러났다. 매출까지 가면 수요가
이미 센 유동 밀도를 **점유율에서 한 번 더 곱하는** 셈이 된다. 그래서 ν를 올릴수록
단조롭게 나빠진다.

`_locationRebuild.test.ts` ⑧번이 "수요식 반경의 그림자가 아니다"를 이미 검정했지만,
그건 **점유율 잔차 안에서** 반경을 바꿔본 것이라 전체 파이프라인의 이중계산은 못 잡는다.

### ⚠️ 채택하지 않았다

숫자가 좋아졌다고 계수를 바꾸지 않는다([[storeeval-experiment-judgment]] · `docs/backlog.md`
산식 실험 판정 기준). 여기 있는 건 **측정**이고, 채택은 무작위 대조군 + 기전 설명이
있어야 한다. 기준선 44.86%도 기록 29.42%와 표본·구성이 달라 직접 비교가 안 된다.

## 4-2. 이중계산을 걷어내 봤다 — 뜻은 살아나고, 성능은 관문을 못 넘는다

카카오 업소밀도판은 안 쓴다(사용자 직감 + ⑨에서 이미 r 대조군 p=0.317로 탈락). 대신
**잔차화**했다: `log(중심도)`를 `log(유동400m)`에 회귀시키고 잔차만 쓴다. 남는 건
"같은 규모의 동네끼리 비교했을 때 우리가 중심이냐 끝이냐"로, 원래 재려던 그것이다.
새로 모을 자료가 없고 계산만 다시 한다. 기하평균을 기준값(3.22)에 맞춰 되돌린다.

```
수요식 유동400m와의 겹침   r = 0.605  ->  -0.180     (겹침이 사라진다)
log-log 기울기 0.526 (n=38)
```

### 뜻은 분명히 살아난다

| 매장 | 그 동네 유동400m | 중심도 순위 | 걷어낸 뒤 |
|---|---:|---:|---:|
| 야탑점 | 219,509 | 9위 | **27위** — 번화가라 높았을 뿐, 그 안에선 가장자리 |
| 양주덕정점 | 44,214 | 32위 | **14위** — 작은 동네지만 그 안에선 한가운데 |
| 청주대점 | 49,599 | 30위 | **13위** |

### 성능도 좋아진다

```
잔차화 중심도 ν   0 -> 38.64%   0.1 -> 37.72%   0.25 -> 36.36%   0.5 -> 37.24%   1 -> 46.79%
(비교) 손 안 댄 중심도 ν=0.25 -> 45.86%
```

최적 ν가 **0.25**로 나온다 — 점유율 공간에서 독립적으로 고른 값과 같다.

### ❌ 그런데 관문을 못 넘는다

전체 파이프라인용 관문을 새로 세웠다(`_textbookFull.test.ts`). 기존 관문은 점유율
공간에만 있고, 오늘 드러난 이중계산은 바로 그 공간에서 안 보이던 것이라 여기서 다시 세웠다.

```
[무작위 대조군] 진짜: ν=0.25 · 38.64% -> 36.36% (좋아진 폭 2.28%p)
                뒤섞은 값 200회: 중앙 0.03%p · 95퍼센타일 7.00%p
                p = 0.229  ❌ 미달

[LOO]           표본 안 36.36% -> 홀드아웃 36.60%  벌어짐 0.24%p
                훈련겹이 고른 ν: 0.25(35회) · 0.5(2회) · 0(1회)   ← 매우 안정
```

**LOO는 아주 안정적인데 대조군을 못 넘는다.** 뜻은 이렇다 — ν=0.25는 일관되게 골라지지만,
그렇게 얻는 2.28%p가 **뒤섞은 가짜 값으로도 종종 나온다.** 자유 계수를 하나 더 준 효과와
구분이 안 된다.

⚠️ 대조군 분포의 95퍼센타일이 7.00%p나 되는 게 더 중요한 신호다. **전체 파이프라인 MAPE는
입지 계수를 고를 자로 쓰기엔 잡음이 너무 크다** — 표본 38곳에 오차 106~139%짜리가 섞여 있어
몇 곳이 전체를 흔든다. 여기서 몇 %p로 계수를 고르는 건 아직 무리다.

## 4-3. 그래서 확실한 것과 불확실한 것

**확실한 것** — 지금 기본값(손 안 댄 중심도 ν=0.25)은 **끄는 것보다 나쁘다.** 45.86% vs
38.64%로 7.2%p 차이고, ν를 올릴수록 단조롭게 나빠지며, 기전(r=0.605 이중계산)이 설명된다.
증거 셋이 한 방향이다.

**불확실한 것** — 잔차화한 중심도가 **도움이 되는지**. 방향은 맞아 보이나 관문을 못 넘었다.

**사람이 정할 것**: 전체 파이프라인에서 중심도를 (a) ν=0으로 끌지, (b) 잔차화한 값으로
바꾸되 ν는 자료가 말할 때까지 0으로 둘지, (c) 점유율 쪽 결론을 믿고 지금처럼 둘지.
(c)는 위 "확실한 것" 때문에 권하지 않는다.

### 유동 방향 ω (참고 — 켜지 않았다)

```
ω=0 → 45.86%   0.1 → 45.08%   0.25 → 44.33%   0.5 → 43.67%   1 → 42.40%
```
올릴수록 좋아지지만 이건 위 중심도 문제와 얽혀 있다(중심도가 나쁜 쪽으로 당기는 걸
방향 항이 상쇄하는 모양일 수 있다). **대조군을 못 넘은 항목이라 0으로 둔다.**

# 7. 운영과 실험실을 갈랐다

사용자: "v62(기존 점포평가)랑 실험실이랑 데이터 분리해서 관리했으면 하는데... 시설이나

맞는 판단이었다. 6절이 바로 그 문제의 실례다 — 자료를 고쳤더니 운영 숫자가 같이 움직였다.

|---|---|---|
| 기존점 | `storeEvalExistingStores` | `storeEvalLabExistingStores` |
| 후보지 | `storeEvalCandidates` | `storeEvalLabCandidates` |
| 경쟁점 | `storeEvalCompetitors` | `storeEvalLabCompetitors` |

월매출만 복제하지 않는다. 실측 사실이라 실험실에서 고칠 일이 없고, 두 벌로 두면 "어느 쪽
