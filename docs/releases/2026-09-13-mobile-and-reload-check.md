# 새로고침 경고 실확인과 모바일 화면 시각 확인

2026-09-13 밤. 인계 문서(`docs/handoff-to-claude-20260913.md`)의 남은 두 항목을 일반 Chrome에서 확인했다.

## 확인 환경

일반 Chrome 153(임시 프로필)을 디버깅 포트로 띄우고 회사 구글 계정으로 직접 로그인한 뒤, 운영 배포본
(`https://my-next-firebase-app-one.vercel.app/store-eval/candidates/N012`)을 확인했다. 앞선 Edge Game
Bar sidebar 모드의 제약(새 탭 생성 제한, 캡처 시간 초과)은 없었다.

## 1. 새로고침 기본 경고 — 확인됨

- 기본정보 후보지명을 `산본점` → `산본점테스트입력`으로 바꾸자 "저장하지 않은 변경이 있습니다" 표시.
- 실제 새로고침 시 브라우저 네이티브 `beforeunload` 대화상자가 떴다.
- 취소(머무르기)하면 같은 URL에 남고 입력값 `산본점테스트입력`이 그대로 유지됐다.
- 다시 새로고침 후 확인(떠나기)을 누르면 새로고침이 진행되고 값이 저장본 `산본점`으로 돌아왔으며
  미저장 표시도 사라졌다.
- 새로고침 호출은 디버깅 연결로 발생시켰으나 대화상자 자체는 브라우저 네이티브 동작이다. 메시지 본문은
  빈 문자열로, 크롬이 자체 문구를 쓰기 때문이다(커스텀 문구는 브라우저가 무시한다).
- 확인용 편집은 저장하지 않았다. 운영 데이터 변경 없음.

## 2. 모바일 화면 시각 확인 — 문제 없음

390px 모바일 에뮬레이션에서 화면을 이미지로 직접 확인했다(DOM 너비 측정이 아니라 실제 렌더링).

- 기본정보: 상단 입력부부터 하단 `임시저장`·`저장` 버튼까지 글자 겹침·버튼 잘림 없음. 문서 가로폭 390px,
  가로 넘침 요소 0개.
- 경쟁점 목록: 카드 레이아웃 정상. 배지("조사완료", "노후·저경쟁력 미조사")와 `수정`·`삭제` 버튼 모두
  화면 안에 들어온다.
- 경쟁점 편집 폼: 조사상태부터 경쟁력 점수까지 라벨·입력칸·도움말이 겹치지 않는다.
- 입지동선평가: 점수 선택, 실시간 미리보기, 메모, 하단 `저장` 버튼까지 정상.
- 미저장 이동 경고 대화상자도 390px에서 정상 표시됐다(경쟁점 추가 폼을 연 채 탭 이동 시 확인).
- 이 세 화면에는 `<table>`이 없어 긴 표 가로 스크롤 대상은 없었다.

관찰만 하고 고치지 않은 것: 경쟁점 목록의 `수정`·`삭제` 버튼 높이가 26px로 작은 편이다. 화면을 벗어나지
않고 WCAG 2.5.8(24×24) 기준은 충족해 이번에는 건드리지 않았다.

## 3. 발견한 문제 — 지도가 빈 상자로 표시됨

기본정보 탭의 지도 영역이 테두리만 있는 빈 상자로 렌더링됐다. 모바일만의 문제가 아니라 데스크톱 폭에서도
같다.

원인은 코드가 아니라 카카오 개발자 콘솔 설정이다.

```
GET https://dapi.kakao.com/v2/maps/sdk.js?appkey=...
→ 401 {"errorType":"AccessDeniedError",
       "message":"domain mismatched! caller=https://my-next-firebase-app-one.vercel.app.
                  check out registered web domains."}
```

카카오가 JS 대신 JSON 오류를 돌려주므로 크롬이 `ERR_BLOCKED_BY_ORB`로 스크립트를 차단하고,
`window.kakao`가 만들어지지 않아 지도가 그려지지 않는다. 로컬 `.env.local`과 배포본의 JS 키는 같은
값이라 키가 잘못된 게 아니라 **운영 도메인이 등록되어 있지 않은 것**이다.

### 남은 조치 (사람이 해야 함)

카카오 개발자 콘솔 > 내 애플리케이션 > 앱 설정 > 플랫폼 > Web > 사이트 도메인에
`https://my-next-firebase-app-one.vercel.app`을 추가하면 지도가 바로 나온다. 코드 배포는 필요 없다.

### 이번에 한 코드 변경

`src/components/storeEval/CandidateMap.tsx` — SDK 로드가 실패하면 빈 상자 대신 이유를 설명하는 안내
문구를 띄운다(`<Script onError>`). 원인 해소가 아니라, 도메인이 등록되기 전까지 사용자가 빈 상자를 보고
이유를 모르는 상황을 없애려는 것이다. 산식·가중치·저장 로직은 건드리지 않았다.

## 검증

- `npx.cmd vitest run --exclude "**/_*.test.ts"`: 48개 파일 694개 통과(31개 에뮬레이터 전용 skip).
- `npm.cmd run lint` 통과. 첫 구현은 effect 안에서 setState를 호출해 `react-hooks/set-state-in-effect`에
  걸렸고, 방어 코드를 빼고 `onError`만 남겨 해결했다.
- `npm.cmd run build` 통과(TypeScript, 26개 페이지).
- 보안 규칙 에뮬레이터 테스트는 이번 변경이 규칙·저장 경로를 건드리지 않아 다시 돌리지 않았다.
