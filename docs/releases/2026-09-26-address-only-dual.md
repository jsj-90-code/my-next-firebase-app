# 2026-09-26 밤 — 3단계 준비: 주소만 조건 되짚기 (측정만, 채택 대기)

하네스 `src/lib/storeEval/_addressOnlyDual.test.ts`. 기존점 40곳을 "주소만 넣었다면"으로 재현(주소만 화면과 **같은 함수** buildQuickCandidate → evaluateCandidate),
그 매장은 학습에서 빼고 맞힘. 경쟁점 = **카카오 500m**(kakao-neighborhood.json, 이름 거르기 같음, 자기 매장 제외), 대수·품질은 주소만 기본값(100대·2.5점).
입지평가는 되짚기에서 AI를 못 돌려 **사람 입지평가를 대신 씀(= AI가 사람만큼 맞힌다는 상한)**. 입지평가가 없으면 V62가 값을 안 낸다.

## 화면 전용 설정 가르기
| 설정 | 효과 | 판정 |

| **학습 경쟁점 비움** | 23.0 → 14.1%, 편향 +19.0 → +1.9% | 핵심 — 후보지(경쟁점 모름)와 학습 매장을 **같은 정보 수준**으로 맞추는 것(산식 변경 아님) |

## 읽기
- 사용자 짐작("주소만 산식은 바뀌거나 없어질 대상")과 달리, **주소만 설정 둘(경쟁점 비움·천장)은 자료가 지지한다.** 없애면 과대 +19%.
- **실험실은 주소만 조건에서 크게 과대(+23.6%)** — 카카오 경쟁점을 기본 품질(2.5점)로 넣고, 2km 경쟁점도 없다(후보지 화면 실험실은 조사 품질·2km 포함).
  지금 상태로는 주소만 화면에서 실험실은 참고 값·현장 확인 신호로만 쓸 수 있다.
