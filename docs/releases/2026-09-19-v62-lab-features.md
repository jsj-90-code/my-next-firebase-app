## 0. 사용자 요구와 그게 왜 좋은 설계인가

> *"v62에 실험실데이터 조합 잠시 찾아보고, 적용해보자. (...) 실험실데이터 무조건 mape로
> 가는 게 아니라 실험실에서 나온 내용 중 적절한 요소가 아닌 것들, 그니까 우리가 이 내용은
> 아니다라고 정정한 것들도 함께 적용해보자."*

**기각한 항목을 같이 태우면 그게 위약군이 된다.** 이게 판정의 핵심이다:

```
  채택군만 좋아지고 기각군은 안 좋아진다  ->  진짜 신호
  기각군도 똑같이 좋아진다              ->  칸을 하나 더 준 효과일 뿐 = 과적합
```

위약군 없이 채택군만 태우면 "좋아졌다"를 **반드시** 얻는다(자유도가 하나 느니까).

## 4. QSC가 무엇을 고치나 — 물리적으로 말이 된다

```
  ── 좋아진 곳 (QSC 낮음) ──          ── 나빠진 곳 (QSC 높음) ──
  구미산동점  QSC 73.9  17.9% -> 3.9%   남악점    QSC 98.5   6.0% -> 11.9%
  발산역점    QSC 83.2  15.3% -> 6.2%   김포구래점 QSC 96.4  16.0% -> 20.6%
  장산점     QSC 82.7   9.7% -> 1.1%   증평점    QSC 96.0  10.8% -> 14.7%
  진주혁신도시  QSC 87.0   7.7% -> 3.5%   광주첨단점 QSC 98.0  21.0% -> 24.8%
```

**관리 점수가 낮은 매장을 산식이 과대예측하고 있었고, QSC 칸이 그걸 정확히 끌어내린다.**
구미산동점(QSC 73.9, 표본 최저)이 −14.0%p로 제일 크게 고쳐진다. 우연한 맞춤이 아니라
"관리는 매출에 실재한다"(2026-09-17 탄력도 0.84)와 같은 얘기다.

### 대가 — ±20%가 97% → 92%

```
  ±20%를 벗어난 매장 2곳:  인천서창점 19% -> 21%  ·  김포구래점 16% -> 21%
```

평균은 좋아지는데 꼬리 두 곳이 밖으로 나간다. **세 자 중 하나가 반대로 간다.**

## 5. ⚠️⚠️ 그런데 후보지 예측은 한 톨도 안 바뀐다

**QSC는 개점 뒤 매장을 돌아보고 매기는 점수라 후보지에는 존재하지 않는다.**
없으면 평균(표준화 후 0)이 들어가 기여가 정확히 0이다.

즉 이 개선은 **기존점 사후 설명력**이지 **후보지 예측력**이 아니다.
실험실에서도 같은 이유로 2026-09-15·09-17 두 번 보류됐다(`docs/backlog.md` "결정 대기").
**V62에서도 결론이 같다.**

## 6. 사용자 질문에 대한 답

> *"기본산식(V62)을 현재 실험실 데이터에서 나온 내용으로 대입했을 때 적중률 향상 가능한지?"*

**후보지 적중률 기준으로는 — 지금 실험실 산출물 중 올릴 수 있는 게 없다.**

| | |
|---|---|
| 후보지에 값이 있고 V62를 개선하는 변수 | **0개** |
| 후보지에 값이 있지만 V62를 나쁘게 하는 변수 | 중심도 · 교과서식 예측 가동률 · 특수수요 배수 |
| V62를 개선하지만 후보지에 값이 없는 변수 | **QSC 하나** (기존점 MAPE 9.17→7.90%) |

실험실이 지금까지 만든 것들(입지 5항목·유효거리·교과서식 수요식·특수수요 배수·2km 상권
자료)은 **교과서식 산식 안에서는 뜻이 있지만 V62의 회귀에는 얹히지 않는다.** V62는 이미
자기 피처로 9.17%를 내고 있고, 계수 넷이 하한선에 붙어 있다 — 자료가 지금 피처도
다 지지하지 못하는 상태라 칸을 더 주면 나빠진다.

# 덧붙임 — 두 가지를 더 쟀다 (사용자 추가 질문)

## 8. ⛔ 내 6절 주장이 틀렸다 — "후보지는 한 톨도 안 바뀐다"는 **거짓**이다

칸을 하나 더하면 **나머지 계수도 다시 학습된다.** 그러면 QSC 항을 안 거치고도 후보지 예측이
움직인다. 이걸 안 보고 "안 바뀐다"고 쓴 건 틀렸다.

```
  [이용시간]  공급 대비 수요   0.0294 -> 0.0207   **−29.6%**
  [먹거리]    공급 대비 수요   0.0810 -> 0.0753   −7.0%
  (나머지는 하한선/상한에 붙어 있어 안 움직인다)
```

### 그래서 후보지가 실제로 얼마나 움직이나 — 쟀다

후보지 = QSC가 없어 평균이 들어가는 곳. **실제 QSC로 학습한 뒤 QSC를 평균으로 두고 예측**해
기준선과 견줬다.

> ⚠️ 처음엔 전 매장 QSC를 같은 값으로 넣어 흉내냈는데 **틀린 방법**이었다 — 분산이 0이라
> 표준화에서 전부 0이 되고 학습이 기준선과 같아져 변화 0.00%가 나온다. 하네스에 적어 뒀다.

```
  후보지 예측 변화   평균 |0.63%| · 중앙 0.59% · 최대 1.71%
  많이 움직인 곳: 창원남양 +1.7% · 전대상대 +1.6% · 시흥능곡 +1.5% · 하남덕풍 +1.4%
```

**최대 1.71%다.** MAPE 9%인 모형에서 2% 미만이면 실질적으로 같다고 볼 수 있다.
"검증 안 된 변경이 후보지로 크게 새어나간다"는 걱정은 자료상 근거가 없다.

## 9. 사양 점수를 실험실 판으로 갈아끼우면 — **나빠진다**

사용자(2026-09-19): *"그거 말고도 사양 먹거리 시설 관리 등 이런 쪽도 데이터는 실험실 데이터가
좀 더 맞는 거 아닌가?"*

**지적의 종류가 QSC보다 낫다.** 둘은 성격이 다르다:

```
  QSC        = 피처를 **한 칸 더한다**    -> 자유도 +1 · 후보지엔 값이 없음
  사양 교체   = 기존 칸의 **값을 고친다**  -> 자유도 그대로 · 후보지에도 그대로 적용됨
```

그리고 실험실은 운영 사양표가 **틀렸다는 근거**를 갖고 있다(`labSpecScore.ts`):
RTX 3060 Ti 2.25 < RTX 4060 3.00(실제로는 3060 Ti가 빠르다) · i3 13100F = i5 13400F(티어 무시).

경쟁력점수는 선형 가중합이라 사양 차이가 정확히 전파된다:
`Δ자사 = (실험실사양 − 운영사양) × w.spec`, 경쟁평균도 PC수 가중으로 같은 방식.

```
  점수가 움직인 매장 38/41곳 · 경쟁점 127/168건 (경쟁력점수에서 사양 비중 25%)

                       MAPE      중앙    ±10%   ±20%
  지금 (운영 사양표)     9.17%    7.89%    66%    97%
  실험실 사양표          9.25%    9.25%    63%    97%
```

**나빠진다 — 특히 중앙값이 7.89% → 9.25%.**

자사 사양이 거의 전부 내려간다(하남덕풍 2.76→2.60 · 청주터미널 2.96→2.74 · 구미산동 2.93→2.72).
**물리적으로 더 정확한 표가 V62 적중률은 낮춘다.** 사양 점수가 매출을 설명하는 힘이 원래
약하다는 뜻이다(V62의 자사 경쟁력 계수는 이용시간·먹거리 둘 다 0.0900에 붙어 있다).

→ **사양 교체는 V62에 적용하지 않는다.** 다만 실험실 사양표가 틀렸다는 뜻은 **아니다** —
   RTX 서열은 사실 문제다. "더 맞는 값"과 "V62 적중률을 올리는 값"이 다를 뿐이다.

⚠️ **존구성(시설)은 아직 안 쟀다.** 실험실 판(`labZoneComposition.ts`)이 지적하는 건 정확도가
   아니라 **편향**이다 — VIP존·프렌즈존·퍼스트클래스존이 경쟁점 228건 전부 0건이라
   "종류를 세면 자사가 항상 이긴다"(자사 41/41곳). 이건 MAPE로 판정할 문제가 아니라
   **후보지를 과대평가하는 구조 문제**일 수 있다. 다음에 따로 본다.

## 10. 정리 — 적용 판단

|---|---|---|---|
| **QSC 관리지수** | MAPE 9.17→**7.90%** · 중앙 7.89→**6.39%** · ±10% 66→**71%** | 예측 변화 최대 1.71% | **적용 후보** |

# 덧붙임 2 — 판정 기준을 바꿨다 (사용자 원칙)

> *"v62라고 mape 위주로 진행하는 게 아니라, 근거가 명확한, 이런 값이라면 적중률이 떨어져도
> 적용해야지."*

맞다. 실험실에서 하루 종일 지킨 규율("MAPE로 값을 고르지 않는다")을 운영에도 그대로 적용한다.
**그래서 아래 표의 MAPE는 채택 근거가 아니라 치르는 대가로 읽는다.**

## 11. 근거의 종류로 다시 나눴다

```
  [사실 문제]   운영 값이 사실과 어긋난다        -> 적중률과 무관하게 고친다
  [통계 근거]   관문을 통과했다                -> 대가를 보고 정한다
  [근거 약함]   실험실 안에서만 뜻이 있다        -> 안 건드린다
```

## 12. 대가를 쟀다

```
                       MAPE      중앙    ±10%   ±20%
  지금 (운영 잣대)      9.17%    7.89%    66%    97%
  사양만 실험실 판       9.24%    9.01%    66%    97%
  존구성만 실험실 판     10.25%   10.42%    47%    95%
  둘 다 실험실 판       10.03%    9.57%    55%    92%
  (사양 38곳 · 존구성 38곳이 움직인다 · 자사 41곳 중)
```

## 13. ⭐ 그런데 존구성은 **실험실 판도 비대칭을 못 고친다**

대가가 크니(±10% 66% → 47%) 근거가 정말 '사실 교정'인지 확인했다.

```
  잣대      자사 중앙   경쟁점 중앙   자사가 경쟁 중앙보다 높은 비율
  운영        3.35      1.00              98%   (자사 41곳 · 경쟁 232곳)
  실험실       3.40      1.00             100%   (자사 38곳 · 경쟁 230곳)
```

**실험실 판으로 바꿔도 자사 승률이 98% → 100%로 오히려 올라간다.** 경쟁점 중앙은 1.00에
그대로 붙어 있다.

### 왜 그런가 — 잣대가 아니라 **자료**가 문제다

실험실이 지적한 "자사 전용 이름표(VIP존·프렌즈존·퍼스트클래스존)" 자체는 사실이다. 그런데
경쟁점 존구성 점수가 1.00(최저)에 몰려 있는 진짜 이유는 **경쟁점 존 자료가 거의 비어 있어서**다.
잣대를 바꿔도 빈칸은 빈칸이다.

→ **존구성은 실험실 판으로 갈아끼우지 않는다.** 대가만 치르고 고쳐지는 게 없다.
   진짜 해법은 **경쟁점 존구성 조사**다 — 잣대 교체가 아니라 자료 수집이다.
   (V62는 2026-09-17에 이미 "미조사 경쟁점이 최저점 받던" 문제를 고쳤다. 남은 건 자료다.)

## 14. 최종 분류와 권고

| 항목 | 근거 | 대가 | 권고 |
|---|---|---|---|
| **사양표 → 실험실 판** | **사실 문제** — RTX 3060 Ti(2.25) < RTX 4060(3.00)은 사실과 어긋남 · i3 13100F = i5 13400F(티어 무시) | MAPE +0.07%p · 중앙 +1.12%p · **±10%·±20%는 그대로** | **적용** |
| **QSC 관리지수 추가** | 통계 근거 강함 — 탄력도 0.84 · 위약군 5개 전부 실패 · 난수 40회 전부 미달 | ±20% 97→92%(2곳) · 후보지 예측 변화 최대 1.71% | **적용** |
| 존구성 → 실험실 판 | 비대칭은 사실이나 **실험실 판이 그걸 못 고침**(자사 승률 98→100%) | ±10% 66→47% | **안 함** (경쟁점 존 조사가 진짜 해법) |
| 중심도 · 교과서식 예측 · 특수수요 배수 | 근거 약함 — 실험실 안에서만 뜻이 있음 | 전부 악화 | 안 함 |

⚠️ 사양 교체는 **±10%·±20% 적중률을 한 칸도 안 깎는다.** 평균·중앙만 조금 나빠진다.
   "틀린 값을 그대로 두는 것"과 견주면 치를 만한 대가다.

# 덧붙임 3 — ⛔ 13절 판정을 **철회한다**. 존구성은 사실 교정이 맞다

사용자(2026-09-19): *"경쟁점은 VIP존 프렌즈존이 없는데 자사는 있다. 그래서 자사의 VIP존은
1인석으로 바꼈고 프렌즈존은 2인석·3인석으로 변환했잖아."*

## 15. 내가 틀린 판정 기준을 썼다

13절에서 나는 **"자사 승률이 내려가나"**로 판정했다. 승률이 98% → 100%로 오히려 올라가니
"실험실 판이 비대칭을 못 고친다"고 결론냈다. **그 기준이 틀렸다.**

자사가 실제로 특화좌석이 많으면 **이기는 게 맞다.** 물어야 할 건 승률이 아니라:

> **자사 우위가 [이름표 종류 수] 때문인가, [실재하는 좌석] 때문인가**

## 16. 갈라 보니 정확히 고쳐지고 있었다

(조사된 경쟁점 194곳 · 자사 41곳 · 중앙값)

```
  [운영 — 다양성 = 존 **이름** 종류 수]
    다양성   자사 3.50  경쟁 1.00   차이 2.50    <- 자사에만 있는 이름표가 그대로 점수
    수용력   자사 3.00  경쟁 1.00   차이 2.00

  [실험실 — 다양성 = **룸** 종류 수 · 수용력 = 좌석 전부]
    다양성   자사 2.00  경쟁 1.00   차이 1.00    <- 2.50 -> 1.00 으로 **줄었다**
    수용력   자사 4.00  경쟁 1.00   차이 3.00    <- 2.00 -> 3.00 으로 늘었다
```

**이름표 우위가 2.50에서 1.00으로 걷혔다.** 대신 수용력 차이가 늘었는데, VIP존이 1인석으로
프렌즈존이 좌석으로 제대로 세어지기 때문이다 — **실재하는 좌석이니 맞는 방향**이다.

총점이 3.35 → 3.40으로 비슷한 건 **두 변화가 상쇄돼서**다. 그래서 승률로 보면 안 보이고
분해해야 보인다. 13절은 그걸 놓쳤다.

### 그래서 왜 이게 '사실 교정'인가

운영 잣대에서는 **경쟁점이 아무리 좋아도 자사를 못 따라잡는다** — VIP존·프렌즈존·
퍼스트클래스존이라는 칸이 경쟁점 조사표에서 228건 전부 0건이기 때문이다. 우리 브랜드
용어라 조사자가 경쟁점의 같은 실체를 보고도 그 칸에 안 넣는다.

실험실 잣대에서는 **경쟁점도 특화좌석이 많으면 높은 점수를 받는다.** 우위가 남더라도
그건 **겨룰 수 있는 우위**다. 이게 교정의 뜻이다.

## 17. 최종 권고 (14절을 대체한다)

| 항목 | 근거 | 대가 | 권고 |
|---|---|---|---|
| **사양표 → 실험실 판** | 사실 문제 — RTX 3060 Ti(2.25) < RTX 4060(3.00) · i3 13100F = i5 13400F | MAPE +0.07%p · 중앙 +1.12%p · **±10%·±20% 그대로** | **적용** |
| **존구성 → 실험실 판** | 사실 문제 — 이름표 우위 2.50 → 1.00으로 걷힌다. 경쟁점이 겨룰 수 있게 된다 | MAPE +1.08%p · 중앙 +2.53%p · **±10% 66→47%** | **적용** |
| **QSC 추가** | 통계 근거 — 탄력도 0.84 · 위약 5개·난수 40회 통과 | ±20% 97→92% · 후보지 변화 ≤1.71% | **적용** |
| 중심도 · 교과서식 예측 · 특수수요 배수 | 근거 약함 | 전부 악화 | 안 함 |

⚠️ 셋을 다 적용하면 표본 안 적중률이 눈에 띄게 내려간다(±10% 66% → 47%대). 그건
**사용자 원칙대로 치르는 대가**다 — *"근거가 명확한 값이라면 적중률이 떨어져도 적용해야지."*

⚠️ 다만 이 대가는 **화면에 설명이 필요하다.** 적중률이 떨어진 걸 보고 "산식이 나빠졌다"고
   읽으면 안 되기 때문이다. "틀린 값을 고쳐서 내려간 것"이라고 적어야 한다.

## 18. 남은 진짜 과제 — 경쟁점 존 조사

조사된 경쟁점 194곳에서도 존구성 중앙이 **1.00(최저)**이다. 미조사 38곳은 아예 기본값이다.
잣대를 고쳐도 **빈칸은 빈칸**이다. 경쟁점 존구성 조사가 들어와야 이 항목이 제 일을 한다.

# 덧붙임 4 — 먹거리·인테리어 질문, 그리고 사양에서 '사실'과 '판단'을 갈랐다

사용자(2026-09-19): *"먹거리랑 인테리어는? 검토한거지?"*

## 19. 먹거리·인테리어 — 갈아끼울 잣대가 **없다**

실험실이 그 둘은 **그대로 통과**시킨다.

```
  ownQualityParts:    food: s.ownFoodScore · interior: s.ownInteriorScore · management: s.ownManagementScore
  rivalQualityParts:  food: c.foodScore    · interior: c.interiorScore    · management: c.managementScore
```

운영과 같은 값이다. 그리고 2026-09-18에 자사 기준값을 검토했지만 **둘 다 4.0 유지 확정**했다.
관리는 실험실이 QSC로 대체하는데(`qscToManagementScore`) 그게 지금 다루는 QSC 항목이다.

→ **먹거리·인테리어는 잣대 문제가 아니라 자료 문제다.** 미확인이라 2점 받은 경쟁점 73곳이
   진짜 과제이고, 그건 조사로만 풀린다(`docs/handoff-*` 6절에서 "제일 값어치 크다"고 적힌 항목).

## 20. ⚠️ 사양에서 **사실 교정**과 **판단**을 섞을 뻔했다

실험실 사양은 변환표뿐 아니라 **비중도** 바꾼다(VGA 0.40→0.50 · 모니터 0.25→0.15).
그런데 `labSpecScore.ts`가 스스로 적어 뒀다:

> *"0.50은 **뜻으로 고른 값**이고, 자료는 반대하지 않는 정도다"*
> *"이 값을 자료로 다시 고르려 하지 말 것"*

즉 비중은 **판단**이지 RTX 서열 같은 검증 가능한 사실이 아니다. 사실 교정 명목으로
판단을 끼워 넣으면 안 된다. 갈라서 쟀다:

```
                              MAPE      중앙    ±10%   ±20%
  지금 (운영)                  9.17%    7.89%    66%    97%
  변환표만 실험실 (비중 운영 유지)  **9.06%**  8.24%    66%    95%
  변환표+비중 둘 다 실험실        9.24%    9.01%    66%    97%
```

**사실 교정만 떼면 MAPE가 오히려 좋아진다(9.17% → 9.06%).** 앞서 "사양 교체는 나빠진다"고
적은 건 **비중 변경까지 같이 넘겼기 때문**이었다. 갈라내니 거의 공짜다.

```
  [사실 교정 — 적용]
    GPU 성능지수   RTX 3060 Ti(2.25) < RTX 4060(3.00)은 검증 가능하게 틀림
    CPU 성능지수   i3 13100F = i5 13400F는 틀린 서술
                  (실험실도 "근거는 영향력이 아니라 서술의 정확성" · 대조군 p=0.213)
  [판단 — 적용하지 않음]
    비중 0.40/0.25 -> 0.50/0.15   별도 결정 사항. 지금 섞지 않는다
```
