# 후보지 관리와 모바일 사용성 개선

사용자가 프로그램의 품질·서비스·정확성과 전문적인 완성도 개선을 위임한 작업이다.
기존 크림·테라코타 테마와 예측 산식 동결 방침을 유지했다.

## 바뀐 사용 흐름

- 신규후보지에서 전체·진행·보류·완료·종료 건수를 보고 상태별로 좁힐 수 있다.
  이 상태는 담당자의 검토 상태이며 대시보드의 산식 판정과는 별개다.
- 이름·주소·코드를 함께 검색한다. `군포 산본`처럼 여러 단어를 입력하면 모두 포함하는
  후보지를 찾는다. 최근 수정순·이름순·코드순 정렬을 지원한다.
- 768px 미만에서는 표 대신 카드로 주소 전체, 검토 상태, 최신성 안내, 작업 버튼을 표시한다.
  복사·삭제는 데스크톱과 동일한 처리 함수를 사용한다.
- 공통 메뉴는 1024px 미만에서 펼침 메뉴가 된다. 현재 위치를 표시하고 링크 선택 후 닫힌다.
- 조회 실패·빈 목록·검색 결과 없음·불러오는 중을 구분한다. 재조회 실패 시 이전 목록임을
  알리고 복사·삭제를 비활성화한다. 늦은 목록 응답은 최신 조회 결과를 덮어쓰지 않는다.
- 최신성 부가 조회 실패를 숨기지 않고 안내한다. 목록 새로고침은 관련 부가 정보도 다시 읽는다.
- 대시보드에 페이지 제목과 후보지 관리 진입을 추가했다. ExcelJS는 내보내기 요청 시 로드하며,
  내보내기 실패는 사라지는 알림창 대신 화면에 남긴다. 전후 속도 수치는 측정하지 않았다.

## 확인 결과

- 빌드: 성공, TypeScript 검사 및 26개 페이지 생성 완료.
- 일반 테스트: 678개 통과, Firestore 에뮬레이터 전용 22개 생략. 린트 통과.
- 검색·상태 조합, 전각/영문 코드 정규화, 정렬과 원본 순서 보존 회귀 테스트 3개 추가.
- localhost에서 기존 회사 계정으로 로그인해 후보지 9곳을 확인했다.
- 390px: 모바일 카드, 상태 필터 빈 결과, 초기화, `군포 산본` 검색 결과 1곳,
  코드순 정렬, 메뉴 펼침과 링크 선택 후 닫힘 확인.
- 320px/390px에서 문서 폭이 뷰포트를 넘지 않음을 확인하고 라이트·다크 화면을 확인했다.
- 대시보드: 전체 9곳, 평가 완료 6곳, 포화 주의 3곳 표시 확인.
- 엑셀 다운로드 이벤트 감지는 시간 초과했으나 Downloads의 생성 파일을 직접 열어 검증했다.
  `후보지목록` 시트는 헤더 포함 10행, 17열이다. 내보내기 후 콘솔 오류는 없었다.

운영 자료를 생성·복사·삭제하는 버튼은 검증 목적으로 실행하지 않았다.
산식 계수·가중치·Firestore 규칙·운영 입력 변경은 없다. 개선은 탐색·표시 신뢰성·로딩 경로이며
매출 예측 적중률 상승을 주장하지 않는다.
