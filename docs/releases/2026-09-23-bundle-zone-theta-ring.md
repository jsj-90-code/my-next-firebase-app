## 왜

바깥 표본(경쟁점 핑봇 47곳)이 두 가지를 잡아냈다. (가) 수요 수준이 약 1.5배 작다. (나) 옛 배선은 자사우위를
3.50배로 예측하는데 실측은 1.74배(1년차 자사 9곳 vs 성숙 경쟁점, 같은 달)다. 둘은 독립이라 하나만 고치면
다른 쪽이 무너진다 — θ만 내리면 자사·경쟁점이 같이 −10%p 과소, 고리만 켜면 자사가 +10%p 과대.

"빼는 게 정답인가"에 비중 0 / .06 / .12 / .18 / .238을 돌렸다. 비중을 남길수록 자사 r·짝 r이 오른다(존구성이
순서에는 일한다). 세게 두면 자사우위를 부풀린다. 사전 등록 기준(두 편향 ±3%p → 자사우위 1.74 근접 → 자사 r)
1위가 존 0.06·θ1.75·λ600이었다. 팀룸 유입 기전(사용자)이 있으니 항목은 자르지 않는다.

## 같은 날 저녁 — 고리 점유율을 "가까운 쪽으로"(gravity)로, λ 600→800

사용자: *"예상가동률 편차가 더 커진 것 같은데?"* → 맞았다. 자사 예측 SD 8.1→9.9(실측 6.4), 최악이 발산역 +23·
수원망포 +21%p. 원인은 비대칭 — 1~2km 사람은 세면서 그 곁 PC방은 경쟁으로 안 셌다(경쟁 감쇠는 사실상 500m).
사용자: *"근거가 있어서 감수해야 하는 부분이면 인정인데 값을 위해 조정한 거라면 별로."*

고친 방법은 기하다. 우리에서 d 떨어진 경쟁점이 반경 r 고리 주민 중 우리보다 가까운 비율 = arccos(d÷2r)÷π.
이걸 경쟁점 무게로 써 고리 띠마다 점유율을 따로 구하고 1km 안 점유율과 이용자 수로 가중평균한다. 맞춘 계수 없음.
(`residentRingShare: "gravity"` · `ringRivalFraction`)

⚠️ 하네스도 고쳤다 — 경쟁점 주인공에 2km 경쟁점이 빠져 있어 gravity에서 우리만 깎이는 비대칭이 있었다.
그래서 위 표의 채택 칸 숫자가 조금 바뀐다(core λ600: 경쟁편향 −1.6→−3.3 · 자사우위 1.77→1.84).

| | core λ600 (낮) | **gravity λ800 (저녁 채택)** |
|---|---|---|
| 자사 MAE / 편향 / r | 7.82%p / +1.3 / 0.337 | **6.88%p** / −1.2 / 0.187 |
| 자사 예측 SD (실측 6.4) / ±5%p | 9.9 / 14곳 | **6.7** / 15곳 |
| 경쟁점 MAE / 편향 | 8.7%p / −3.3 | 8.2%p / −2.7 |
| 짝 r | 0.551 | 0.533 |

λ를 800으로 올린 건 gravity가 고리 몫을 줄여 수준이 내려가서다 — **눈금 값이고 사전 기준(두 편향 ±3%p)으로
자료에서 골랐다.** 치르는 값은 동네 간 순서(자사 r 0.34→0.19, n=37에서 1SE 안팎). 짝 r은 유지된다.
