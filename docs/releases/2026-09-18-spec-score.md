## 1. 먼저 사양 자체를 검정했다 (존구성과 같은 절차)

어젯밤 존구성은 "수준은 진짜, 순서는 없다"로 판정났다. 사양도 같은 잣대를 먼저 댔다.

운영 변환표 위에서(= 손대기 전):

```
지금 그대로            MAPE 22.60%  r 0.563
자사만 상수            MAPE 24.06%  r 0.523
경쟁점만 상수          MAPE 22.93%  r 0.534
둘 다 상수 (수준만)     MAPE 23.59%  r 0.502
사양 비중 0 (아예 뺌)   MAPE 25.23%  r 0.531

무작위 대조군(500회): 실제 2.62%p · 섞으면 95퍼센타일 2.56%p · p=0.042 ✅
```

새 표를 채택한 뒤 다시 재면 **관문이 더 강해졌다** — 실제 2.64%p · 95퍼센타일 2.16%p ·
**p=0.026**. 상수 바꿔치기도 같은 방향이다(자사만 상수 23.93% · 둘 다 상수 24.38% · r 0.499).

**존구성과 달리 사양은 순서 정보가 있다.** 자사 최소(2.64)보다 낮은 경쟁점이 49%로
(존구성은 89%였다) "우리가 항상 이긴다"도 아니다.

## 3. 원자료를 전수로 펴 보니 서열이 뒤집힌 자리가 있었다

```
RTX 3060 Ti  2.25점  <  RTX 4060  3.00점     실제로는 3060 Ti가 빠르다 · 23건
RTX 3070     2.50점  <  RTX 4060  3.00점     실제로는 3070이 한참 빠르다 · 12건
RTX 4070     3.50점  <  RTX 5060  4.00점     사용자 지적 · 9건
i3 13100F    3.00점  =  i5 13400F 3.00점     티어를 아예 안 본다 · 자사 9곳
i9 9900KF    1.00점  =  i5 9400F  1.00점     티어 + 바닥 포화
울트라5 225F 4.00점  =  i5 14400F 4.00점     사용자 지적 · 세대는 위다
```

**세대 숫자는 출시 연도지 성능이 아니다.** 같은 세대 안의 티어 차이가 세대 하나보다 클 때
서열이 뒤집힌다. 그래서 모델명 → **성능지수** → 점수로 바꿨다.

칸 착오도 두 종류 나왔다.
- `i7 12700KF`가 **GPU 칸**에 있는데 운영 `scoreFromVga`가 "12700"을 읽어 **5.00점**을 준다.
  실험실은 가드를 넣어 null로 거른다(운영은 안 고쳤다 — 1건이고 V62 불가침이다).
- `RTX 2070s`·`RTX 3080Ti`·`RTX 4060Ti`가 **CPU 칸**에 있다. 이쪽은 운영에도 가드가 있어 이미 null이다.

## 4. 눈금은 사용자가 정한 사다리를 그대로 이었다

사용자 확정: *"5060이 지금 4점일텐데, 그럼 4060이 3점, 3060 2점, 2060 1점"*

이 네 칸을 성능지수로 놓으면 한 칸이 **성능 ×0.83**이다.

```
RTX 5060 100 · RTX 4060 83 · RTX 3060 72 · RTX 2060 58
ln(58/100) / 3칸 = 칸당 -0.1816
점수 = 4 + ln(성능지수/100) / 0.1816
```

같은 식에 네 모델을 도로 넣으면 **4.00 · 2.97 · 2.19 · 1.00**이 나온다. 새 눈금이 아니라
같은 눈금을 모델 전체로 넓힌 것이다.

## 5. 성능만으로는 모자랐다 — 세대 벌점을 더했다

1차로 성능지수만 켰더니 **RTX 3080이 5.00점**이 됐다. 사용자 지적: *"GPU 3080 5점 너무과하다.
이거 조정필요할거같은데. 3060 - 4060 - 5060 이간격차를 늘려야하나?"*

⚠️ **간격을 늘리는 쪽은 반대 효과다.** 간격을 늘린다는 건 기울기를 작게 하는 것이고,
그러면 3080이 상한에 더 세게 박힌다(4+1.65 → 4+2.5). 원인은 기울기가 아니라 **앵커 4점과
상한 5점 사이가 1점뿐**인 것이었다. RTX 5070·4070·3080·5080이 전부 5.00에 몰려 있었다.

이어진 사용자 방향: *"성능외에 세대별 차등도 적용이 되는구조가 좋을것같은데"*

맞는 방향이었다. 성능지수만 쓰면 **"구형이라도 빠르면 장땡"**이 된다. PC방에서는 그렇지 않다 —
같은 성능이라도 구형은 노후·고장, 신작 게임의 최신 기능 지원, 손님이 사양표에서 받는 인상에서
불리하다. 그래서 두 축을 더한다.

```
점수 = 4 + ln(성능지수/100) / 기울기 − 세대벌점 × (5 − 세대)
기울기 = 앵커 아래 0.1816 · 앵커 위 0.45      세대벌점 = 0.15
```

**둘을 같이 써야 풀린다.** 위 기울기 없이 세대 벌점만 주면 3080이 벌점 0.30에서도 5.00에
그대로 붙어 있다(식으로 5.05가 나와 잘림).

| | 5060 | 5060Ti | 5070 | 5080 | 4060 | 4070 | 3060 | 3060Ti | 3070 | **3080** | 2060 | GTX1080 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 성능만 | 4.00 | 4.91 | 5.00 | 5.00 | 2.97 | 5.00 | 2.19 | 3.60 | 4.22 | **5.00** | 1.00 | 1.54 |
| 성능+세대 | 4.00 | 4.37 | 4.83 | 5.00 | 2.82 | 4.43 | 1.89 | 3.30 | 3.79 | **4.37** | 1.00 | 1.00 |

RTX 3080이 신형 RTX 5060 Ti와 같은 자리가 되고, RTX 4070(4.43)이 한 세대 최신이라 한 끗 위에 선다.

세대 벌점 훑기(위 기울기 0.45에서):

```
벌점 0.00   MAPE 22.75%  r 0.582
벌점 0.10   MAPE 22.64%  r 0.581
벌점 0.15   MAPE 22.59%  r 0.581   <- 채택
벌점 0.20   MAPE 22.55%  r 0.580
벌점 0.30   MAPE 22.51%  r 0.579
```

세대 벌점은 **MAPE를 개선하고 r을 거의 안 깎는다.** 자사에도 걸리는데(4060 23곳 2.97→2.82 ·
3060 10곳 2.19→1.89) 그래도 좋아지는 건 **경쟁점에 구형이 더 많아** 상대 우위가 커지기 때문이다.

⚠️ 벌점을 더 키우면 MAPE가 더 좋아지지만 r은 계속 내려간다. **수준으로 버는 구간**이라
0.15에서 멈췄다([[feedback_lab_mape_follows_level]]).

## 6. 대조군 — 델타를 모델끼리 뒤섞는다

표를 바꾸면 모델마다 점수가 얼마씩 움직인다. **움직임의 크기는 그대로 두고 어느 모델에
붙는지만** 300회 뒤섞었다. 새 표가 "실제 서열을 맞혔다"면 뒤섞은 것보다 나아야 한다.

```
1차 (성능만)      실제 r 0.563 -> 0.582 (+0.019) · 뒤섞기 95퍼센타일 0.014 · p=0.017 ✅
최종 (성능+세대)   실제 r 0.563 -> 0.581 (+0.018) · 뒤섞기 95퍼센타일 0.014 · p=0.013 ✅
```

좋아진 게 **점수를 움직였기 때문이 아니라 맞는 모델에 맞게 움직였기 때문**이라는 뜻이다.
⚠️ 표를 손볼 때마다 이걸 다시 돌린다 — 안 그러면 "대조군을 넘었다"는 말이 낡는다.

## 7. CPU는 같은 방식인데 반대로 나왔다

```
CPU 성능지수        r 0.563 -> 0.566   MAPE 22.60% -> 23.02%
CPU 성능지수 · 수준 되돌림                MAPE          22.93%
```

경쟁점 CPU 평균이 2.006 → 2.788로 **0.78점 오르는데 자사는 0.28점만** 오른다. 축척은
독점매장에서만 맞추므로(`textbookModel.ts`의 `calibrationTarget`) 이 수준 이동을 축척이
안 먹어주고 MAPE에 그대로 찍힌다. 그래서 **수준을 빼고** 다시 봤는데도 r이 0.002만 움직였다.

**세대 산술이 CPU에서는 이미 충분했다.** 바닥에 깔린 66건의 순서를 살려도 성적이 안 변한다는
결과(22.60 → 22.61%)와 같은 방향이다.

⚠️ 표는 **지웠다가 다시 만들지 않으려고 남겨 뒀다**(`LAB_USE_CPU_PERF_INDEX = false`).
표본이 45~50곳 되면 다시 켜 본다.

## 8. 사용자 질문에 대한 답

**(1)** *"4070 4080은 성능대비 5060보다 우위일텐데 이런거 어케할지?"*
성능지수로 풀었다. RTX 4070은 3.50 → 4.43으로 RTX 5060(4.00) 위에 선다. 상한에 몰리던 문제는
5절의 위쪽 기울기와 세대 벌점으로 같이 풀었다.

**(2)** *"메모리의 1점차이가 의미가 있는지 궁금."*
**거의 없다.**

```
격차 0.00 (16GB=4.00)  MAPE 22.48%  r 0.588
격차 0.25              MAPE 22.55%  r 0.587
격차 0.50 (지금)        MAPE 22.62%  r 0.586   <- 그대로 둔다
격차 1.00              MAPE 22.76%  r 0.583
격차 1.50              MAPE 22.90%  r 0.580
격차 2.00              MAPE 23.05%  r 0.578
```

늘리는 쪽은 확실히 나쁘다. 지우는 쪽(0.00)은 MAPE가 0.14%p 좋아지지만 **r이 0.002만
움직인다** — 순서가 아니라 수준으로 번 것이다(자사 평균 RAM 3.56 < 경쟁점 3.72라 상수화하면
자사가 상대적으로 올라간다). 수준으로 MAPE를 버는 건 채택 근거가 아니고, 항목을 죽이는
것이라 안 한다. **운영과 같은 0.5를 그대로 둔다.**

**(3)** *"울트라5 225f가 4점, i5 14400F랑 한세대 차이나는거아닌가?"*
세대는 위가 맞다(코어 울트라 200S가 14세대 다음). 다만 **게임 성능은 사실상 같다** —
생산성에선 앞서지만 PC방은 게임이 전부다. 성능지수로는 102 대 100이라 4.11 대 4.00점,
즉 지금의 "같은 점수"가 크게 틀린 게 아니다. 게다가 CPU 표 자체를 껐으므로 지금은 운영과
같은 4.00을 쓴다. 해당 6건은 **전부 경쟁점이고 자사엔 없다.**

## 9. 모니터 — 사용자 결정 대기

존구성 이름표와 **같은 종류의 비대칭**이 있다.

```
특화 칸 채움률(기본이 적힌 곳 중)   자사 40/40 (100%)  ·  경쟁점 71/152 (47%)
그 결과 격차           기본만 0.279  ->  특화까지 0.389
자사 기본 값 가짓수     2가지(39곳이 3.50 = 32인치 FHD 240Hz) · 경쟁점 8가지
```

사용자 진단: *"신규후보지조사할때 모니터 스펙에대한 조사가 디테일하게 이뤄지지 않고있다.
그래서 네이버지도 정보등에서 내가 추가검토하는데, 이게 일괄성이없다."*

측정(채택된 GPU 표 위에서):

```
지금대로 (특화 포함)   MAPE 22.59%  r 0.581
기본만 (특화 무시)     MAPE 22.55%  r 0.573   <- 순서가 오히려 나빠진다
모니터 뺌             MAPE 22.31%  r 0.586
```

**특화를 무시하면 순서가 나빠진다** — 특화 칸이 조사 성실도만 담은 게 아니라 실제 정보도
담고 있다는 뜻이다. 모니터를 통째로 빼면 둘 다 좋아지지만 그건 **항목 자르기**라
([[feedback_item_vs_coefficient]]) 검정 결과로 할 일이 아니다. 사용자가 뜻으로 정할 자리다.

스위치는 만들어 뒀다 — `LabSpecOptions`의 `monitorBaseOnly` · `dropMonitor`. 둘 다 기본 꺼짐.
