# 존구성 검정 — 제일 세게 일하는데, 하는 일이 "수준"이다 (2026-09-17 밤, 집)

재현: `npx vitest run src/lib/storeEval/_zoneComposition.test.ts --disable-console-intercept`

## 왜 봤나

입지 두 항목(중심도 ν=0.25 · 접근성 κ=0.25)까지 붙이고 나서 남은 층이 점유율 쪽
경쟁력점수다. 네 항목 중 뭘 먼저 잡을지 고르려고 **하나씩 빼봤다.**

| 항목 | 재정규화 비중 | 비중 0으로 돌리면 | 자사 38곳 퍼짐 |
|---|---|---|---|
| **존구성** | 28.7% | **MAPE +4.72%p** | 2.35~4.00 (값 9개) |
| 사양 | 31.8% | +1.86%p | 2.64~4.06 (값 22개) |
| 관리 | 18.2% | +0.39%p | 2.39~4.90 (값 32개) |
| 인테리어 | 12.3% | +0.15%p | **전 매장 4.00 상수** |
| 먹거리 | 9.0% | **−0.09%p** | **전 매장 4.00 상수** |

존구성이 압도적인데 **값의 생김새가 수상했다.**

```
경쟁점 153건 중 116건(75.8%)이 최저점 1.00
자사 최소(2.35)보다 낮은 경쟁점 = 136/153건 (89%)
(비교) 사양은 같은 기준으로 73/122건 (60%)
```

사양은 자사가 이기기도 지기도 하는데 존구성은 **"우리는 거의 항상 이긴다"**다. 그러면
저 4.72%p가 매장별 **순서**를 맞히는 것인지, 자사 전체를 한 번 띄우는 **수준 보정**인지
갈라야 한다. 품질 지수 θ에서 이미 한 번 겪은 함정이다 — θ가 줄인 건 수준이고 남긴 건
순서였다.

## 1. 바닥 1.00은 자료 구멍이 아니다

```
경쟁점 153건 중 바닥 116건
  존구성을 아예 안 적은 경쟁점(규칙으로 1.0)    8건
  조사했는데 존이 없어서 1.0인 곳             108건
```

오늘 낮에 `UNSURVEYED_COMPETITOR_ZONE_SCORE = 1.0` 규칙을 넣으며 "미조사 36곳이 바닥에
몰린다"고 봤는데, **실험실 표본(38곳의 경쟁점 153건)에서는 미조사가 8건뿐이다.**
나머지 108건은 조사해보니 진짜로 존이 없다. **경쟁점 존구성은 메울 구멍이 아니다.**

## 2. 값을 상수로 갈아치워도 성적이 안 떨어진다

수준은 그대로 두고 순서만 지운다. 판정은 r(예측↔실측 상관)이 한다 — MAPE는 수준에
끌려다녀서 이 비교에 안 맞는다.

| | MAPE | 중앙 | r |
|---|---|---|---|
| 지금 그대로 | 22.02% | 13.7% | **0.582** |
| 자사만 상수 (자사 순서 지움) | 22.99% | 13.7% | 0.539 |
| 경쟁점만 상수 | 20.60% | 14.9% | 0.576 |
| **둘 다 상수 (수준만 남김)** | **20.67%** | 13.7% | **0.554** |
| 존구성 비중 0 (항목 제거) | 26.74% | 25.6% | 0.557 |

읽는 법이 두 줄이다.

- **항목을 빼면 크게 나빠진다**(26.74%). 자사 3.35 / 경쟁점 1.00이라는 **수준 차이는 진짜 일을 한다.**
- **값을 상수로 바꿔도 안 나빠진다**(20.67%, 오히려 1.35%p 좋다). 매장별 값은 거의 일을 안 한다.

즉 존구성은 지금 사실상 **"블랙라벨인가 아닌가" 더미변수**로 작동하고 있다.

## 3. 무작위 대조군 — 순서는 관문을 못 넘는다

기준선을 "둘 다 상수(수준만)"로 두고 zone 값을 매장끼리 섞는다. 500회.

```
[MAPE] 실제 -1.35%p · 섞으면 중앙 -1.44%p · 95퍼센타일 0.53%p · p=0.455 ❌
[r]    실제  0.027  · 섞으면 중앙 -0.031  · 95퍼센타일 0.033  · p=0.066 ❌
```

MAPE 기준은 **실제가 섞은 것의 중앙보다도 못하다.** r 기준은 p=0.066으로 아슬아슬하게
미달이다 — 500회 중 33회가 실제보다 나았다.

**결론: 순서가 없다고 단정할 근거도, 있다고 채택할 근거도 없다.** 표본 38곳에서는 안 갈린다.
QSC 바닥과 같은 처지다.

## 4. 계단 탓도 아니다

지금 존구성은 계단을 두 번 탄다 — 다양성은 존 종류 수(정수)에서, 수용력은 특화좌석비율을
5칸(0.1/0.2/0.3/0.5 경계)으로 자른다. 그래서 자사 38곳이 **서로 다른 값 9개**뿐이다.
원자료인 특화좌석비율은 연속인데 계단이 그걸 버린다. 계단을 펴봤다.

| | 자사 서로 다른 값 | MAPE | r |
|---|---|---|---|
| 지금 (계단) | 9개 | 22.02% | 0.582 |
| 계단 펴기 | **40개** | 22.96% | 0.580 |

값을 9개에서 40개로 늘려도 **r이 0.002 움직인다.** 뭉개서 순서가 안 나온 게 아니라
**원자료에 매장별 순서 정보가 없다.**

## 한 줄

**존구성이 하는 일은 수준이고, 그건 진짜다. 매장별 변별은 표본 38곳에서 안 보인다.**
자료 구멍(미조사)도 아니고 산식이 뭉갠 것(계단)도 아니다.

## 그래서 안 바꿨다

`DEFAULT_TEXTBOOK_PARAMS`는 한 줄도 안 건드렸다. 상수로 박으면 MAPE가 1.35%p 좋아지지만,
그건 "지금 값이 잡음"이라는 뜻이지 상수가 옳다는 뜻이 아니다. 그리고 상수로 박는 순간
**존 구성을 늘린 매장이 평가에서 아무 보상도 못 받는다** — 실무 감각(*"시설 팀룸이런거
없으면 경쟁력 확떨어져서 2천 정도는 차이날거같고"*)과 정면으로 어긋난다. 이건 사람이
정할 일이다.
