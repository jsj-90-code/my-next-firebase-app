# 계정 변경 후 입력 저장 개선 재개

2026-09-13. `store-eval-work`의 미커밋 변경을 보존하고 입력 검증·미저장 경고·저장 원자성 작업을 이어서 검토했다.

## 현재 변경

- 기본정보·경쟁점·입지평가 저장 시 본문과 감사이력을 동일한 Firestore 트랜잭션으로 기록한다. 감사이력 쓰기가 거절되면 본문도 저장되지 않는다.
- 기본정보의 좌표 확정과 담당자 판단 저장은 해당 필드만 갱신한다. 기본정보 편집 중 다른 화면에서 저장한 판단·좌표를 되돌리지 않는다.
- 기본정보·경쟁점·입지평가는 편집 시작 시점과 최신 문서를 비교한다. 독립적인 변경은 병합하고 같은 필드의 서로 다른 변경은 오류로 안내한다. 편집 중 삭제된 문서를 재생성하지 않는다.
- 경쟁점·입지평가 신규 저장도 이미 같은 문서가 존재하면 덮어쓰지 않는다. 기존 두 인자 호출은 복사 등 기존 동작과의 호환성을 유지한다.
- 경쟁점 붙여넣기 초안의 미저장 판단은 초안 자체가 아닌 저장된 원본을 기준으로 한다.
- 이전 세션 변경인 입력 숫자 검증, 저장 중 중복 조작 차단, 링크·상세 메뉴·새로고침 이탈 경고, 좁은 화면 입력 배치와 오류 알림을 유지했다.

## 검증

- 일반 테스트: 47개 파일, 689개 통과. 에뮬레이터 전용 31개는 이 명령에서 건너뜀.
- `npm.cmd run test:rules`: 실제 로컬 Firestore 에뮬레이터에서 2개 파일, 31개 통과. 기존 보안 규칙 22개와 입력 저장 통합 테스트 9개다.
- 통합 테스트로 감사이력 거절 시 원자성, 저장값과 반환값·이력의 일치, 독립 변경 병합, 동일 필드 충돌, 중복 신규 저장, 삭제 문서 재생성 방지를 확인했다.
- 최종 변경 후 `npm.cmd run build` 통과: TypeScript 검사 및 26개 페이지 생성 완료. `npm.cmd run lint` 통과.

## 범위와 남은 확인

운영 산식·가중치·운영 데이터는 변경하지 않았다. 이번 검증은 로컬 코드와 demo 에뮬레이터 기준이다. 실제 로그인 화면에서의 모바일 배치·입력 이탈 동작은 이번 재개 세션에서 아직 검증하지 않았다. 커밋·푸시·배포는 수행하지 않았다.
