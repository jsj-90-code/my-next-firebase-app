# 좁은 화면에서 표 12곳 실제 확인

2026-09-13 밤. 인계 문서(`docs/handoff-to-codex-20260913.md`)의 남은 후보 중
"표 12곳은 `overflow-x-auto`가 붙어 있지만 실제로 열어본 적은 없다" 항목을 해소했다.
같은 날 앞선 확인(`2026-09-13-mobile-and-reload-check.md`)에서 후보지 3개 탭에는 표가 없다는 걸
알았으므로, 표가 실제로 있는 나머지 화면을 전부 열었다.

## 방법

일반 Chrome을 운영 배포본에 로그인한 상태로 두고, 390px와 320px 두 폭에서 각 화면의 모든 `<table>`에
대해 (1) 표 내용 폭, (2) 가장 가까운 스크롤 조상의 `clientWidth`/`scrollWidth`, (3) 문서 전체 가로
넘침을 측정하고 화면을 이미지로 확인했다. 읽기만 했고 실행·백업·저장 버튼은 누르지 않았다.

## 결과 — 전부 정상

**문서 전체 가로 넘침은 확인한 모든 화면에서 390px·320px 모두 0px이었다.** 세로 스크롤만 생긴다.

실제로 렌더된 표 14개는 모두 가로 스크롤 컨테이너가 동작했다.

| 화면 | 표 | 내용 폭 → 컨테이너(390px) |
| --- | --- | --- |
| 점포평가 홈 | 2개 | 720 → 356 (스크롤 O) |
| 기존 가맹점 목록 | 1개 | 900 → 356 |
| 기존점포 상세 · 상세매출 | 1개 | 640 → 322 |
| 기존점포 상세 · 평가 비교 | 2개 | 2169 → 309, 1617 → 309 |
| 검증(validation) | 8개 | 최대 1700 → 314 |

- 320px에서도 같은 표가 모두 스크롤된다(컨테이너만 좁아짐).
- 화면 캡처에서 표 아래 **가로 스크롤 막대와 좌우 화살표 표시가 실제로 보인다** — 사용자가 스크롤
  가능하다는 걸 알 수 있다.
- 신규후보지 목록의 표는 `hidden md:block`이라 모바일에서는 표 대신 카드 목록이 나온다(의도된 설계).

## 렌더 조건 때문에 화면으로 못 본 5곳 — 마크업만 확인

아래는 특정 동작을 해야만 표가 생긴다. 운영 데이터를 건드리거나 비용이 드는 동작이라 실행하지 않았고,
소스에서 스크롤 래퍼만 확인했다.

- `backup/page.tsx` — 백업 파일을 업로드해 `stage === "ready"`가 되어야 함. `overflow-x-auto` 있음.
- `ai-validation/page.tsx` — AI 검증을 실제로 돌려 결과가 있어야 함. `overflow-x-auto` 있음.
- `MarketDataUploadPanel.tsx` — 상권자료를 붙여넣어 추출해야 함. 래퍼가 `overflow-y-auto`만 있는데,
  CSS 규격상 한쪽 축이 `visible`이 아니면 반대 축은 `auto`로 계산되므로 가로 스크롤도 동작한다.
  바꾸지 않았다.
- `LocationEvalAiReviewPanel.tsx` — 입지평가 AI 초안을 생성해야 함. `overflow-x-auto` 있음.
- `ResultTab.tsx`의 §4.1 V61 학습모형 설명표 — `<details>` "적용된 산식과 계수 보기" 안에 있고,
  **모델버전이 `-usage-v1`로 끝나지 않을 때만** 렌더된다. 현재 운영 모델은 `V62-usage-v1`이라 이 표는
  지금 데이터로는 나오지 않는다. `overflow-x-auto` 있음.

## 최종결과 탭도 함께 확인

표는 없지만 숫자가 가장 많은 화면이라 390px에서 전체를 이미지로 훑었다. 문서 폭 390px, 가로 넘침 0,
요인별 영향 막대그래프·요금 변경 계산 입력칸·판정 배지 모두 겹침이나 잘림 없음.

## 도구 함정 (다음 세션용)

이 탭 중간 구간에서 `page.screenshot()`과 CDP `Page.captureScreenshot` 둘 다 계속 타임아웃했다.
DOM에는 원인이 없었고(거대 요소·sticky·무한 애니메이션·canvas 모두 없음), **크롬 창이 다른 창에 가려져
있어서 래스터가 지연된 것**이었다. `Page.bringToFront`를 먼저 부르면 40~80ms에 캡처된다.
앱 문제로 오해하기 쉬우니 캡처가 멈추면 창부터 앞으로 가져올 것.
