# 2026-10-24 · 견적서 반영 — 탭 갈아 끼우기 → 바뀐 칸만 덮어쓰기

## 왜
반영(`scripts/quote/sync.mjs`)이 영업부용 탭을 통째로 새 탭으로 바꿔서, 반영할 때마다 영업부용의
칸별 수정 기록·댓글·탭 링크(gid)가 끊겼다(10-26 골드 표지 건에서 사용자가 수정 기록을 못 봄).

## 바뀐 것
- 영업부용 탭은 그대로 두고:
  1. 원가를 뺀 깨끗한 탭(원본 안에서 만들고 원가 흔적 검사 — 이전과 같음)을 영업부용에 숨김 준비 탭으로 복사
  2. 원본에서 넣고 뺀 행을 같은 자리에서 넣고 뺌 — 행 짝짓기는 글자로 직접 쓴 칸(품목명·제목)으로, 번호·금액·수식은 기준에서 뺌
  3. 값·수식·서식·메모·입력 규칙이 다른 칸만 칸 복사(걸치는 병합까지 넓혀서), 병합·행 높이·열 너비·눈금선 맞춤
- 백업은 같은 시트 안 숨김 사본, `--rollback`은 백업 내용을 같은 탭에 다시 덮어씀(탭 링크 유지).
- 잠금은 탭이 그대로라 손대지 않음(새로 생기는 탭만 잠금).
- 구글 다시 시도 6번(약 33초) → 8번(2분 남짓): 1분 읽기 한도가 풀리기 전에 포기하던 문제.

## 시험 (블랙 시험용 사본)
| 시험 | 결과 |
|---|---|
| 변경 없이 반영 | 바뀐 칸 0, 탭 번호·크기·잠금 그대로 |
| 병합 묶음 안 행 넣기 + 행 지우기 + 행 높이 + 칸 수정 | 바뀐 칸 4만 덮어씀, 검증 전부 일치 |
| 영업부용을 망가뜨린 뒤 `--rollback` | 차이 264건 → 전부 일치, 탭 번호 그대로 |
| 영업부용 직접 수정 | 감지해 멈춤, `--adopt`로 원본에 옮긴 뒤 반영 |
| 댓글 단 행 위에 행 넣기 | 댓글이 행을 따라 내려감, 안 건드린 칸 수정 기록 유지(사용자 확인) |

## 한계
- 번호만 바뀌는 행처럼 글자 칸이 없는 행은 짝짓기 기준이 약해, 드물게 넣기/지우기 대신 "고친 행"으로 처리될 수 있다.
  내용은 칸 비교로 항상 맞게 되지만 그 행 댓글이 한 칸 어긋날 수 있다.
- 병합의 아래쪽 칸(대표 칸이 아닌 칸)에 들어간 값은 화면·읽기에 안 보여 변경 감지에도 안 잡힌다(시험 중 확인, 원래 그런 구조).

## 마무리 검토에서 잡은 것 (같은 날)
- **칸 안 일부 글자 서식만 바뀐 칸을 건너뜀 — 검증도 못 잡음**(조용히 틀림). 시험: E25 앞 4글자만 빨강 → "바뀐 칸" 미포함·"전체 일치".
  → 칸 비교와 `verify.mjs` 모두 textFormatRuns 포함. 고친 검증으로 실제 블랙·골드 원본↔영업부용은 전체 일치(오탐 없음).
- **자기 탭 이름을 쓴 수식**(`='PC 및 …'!E27`)이 준비 탭 이름(`'__반영준비_…'!`)을 달고 들어감 — 검증이 잡아 멈춤(백업으로 되돌림).
  → 칸 복사 전에 준비·백업 탭의 자기 이름 참조를 원래 탭 이름으로. 실제 원본 14개 탭엔 이런 수식 0개.
- 중간에 끊긴 반영이 남긴 준비 탭은 다음 반영 시작 때 지움.
- 시트 위 그림·도형·차트·탭 색은 API로 못 읽어 따라가지도, 검증되지도 않음 — 블랙·골드 원본 xlsx 내보내기로 0개 확인. 스킬에 주의 적음.
- 되돌리기(`--rollback`)는 '내용에 맞춤' 행을 그때 높이로 고정할 수 있음(겉모양만).

## 별도 검토 1차 (같은 날, 코드만 본 검토 에이전트)
- **되돌리기가 지운 행을 못 되살림**: 백업 탭이 같은 시트 안에 살아 있어 반영 중 다른 탭 행을 지우면 백업의 그 참조도 #REF!.
  → 반영 전 값·수식 스냅숏(`~/.isens-quote/반영전-<책>.json`, PC마다), 되돌린 뒤 칸마다 대조해 고치고 다시 확인, 안 맞으면 백업을 남기고 멈춤.
  시험: 서버 탭 행 지움 + 검증 실패 유도 → 되돌림이 #REF! 1칸을 반영 전 값으로 고치고 "전부 일치".
- **앞 탭을 먼저 복사한 뒤 뒤 탭에 행을 넣으면 앞 탭 수식이 한 번 더 밀림**(검증에서 멈춤).
  → 모든 탭 행 맞추기를 먼저, 그 뒤 준비 탭 복사·칸 복사. 시험: PC 탭이 서버 탭 28행 참조 + 서버 탭에 행 넣음 → 전체 일치.
- 검증에 추가: 입력 규칙(드롭다운), 틀 고정, 탭 색, 조건부 서식(영업부용으로 가는 열), 밴드·필터·차트 개수. 반영도 틀 고정·탭 색을 맞춤.
  실제 블랙·골드에 오탐 없음. 시험: 원본에만 조건부 서식 → 검증이 잡아 멈춤.
- 원가 검사에 추가: IMPORTRANGE·INDIRECT 등 글자로 주소를 넘기는 수식, 열 전체(K:K, A:K)·행 전체(5:5) 참조, 열을 안 자르는 탭(정보입력·표지)의 J열 뒤 내용.
  실제 원본에 해당 0건(판정 바뀐 수식 0개).
- 다시 시도로 두 번 돈 복사가 남긴 보이는 사본 탭도 정리, 행 맞춘 뒤 열 수까지 확인. `--adopt`가 원본에 쓴 뒤 확인 실패하면 쓴 칸을 알림.
- 안 고친 것(원래부터 있던 것): 새로 생긴 탭은 되돌리기로 안 지움, `--adopt`의 "001"→1 같은 형 변환(다시 읽기 확인에서 멈춤),
  직접 수정 감지는 값·수식만(서식·메모만 고친 건 못 잡음 — 영업부용은 잠겨 있어 담당자만 고칠 수 있음).

## 별도 검토 2차 (새 검토 에이전트)
- **되돌림 기록이 PC 파일이라 다른 PC·지난 반영의 기록으로 '고치고' 성공이라 할 수 있었음** → 원본 숨김 탭 `__반영직전기록`으로 옮김.
  백업과 같은 반영에서 만들고 같이 지움(백업이 남아 있으면 새 반영을 안 하므로 짝이 안 바뀜). 기록이 없으면 성공이라 하지 않고 백업을 남김.
  시험: 기록 있음 → #REF! 1칸 고치고 기록·백업 삭제 / 기록 지움 → "대조하지 못함", 백업 남김.
- **`--accept`가 검증 없이 확정** → 검증을 다시 돌려 차이가 있으면 거부(`--accept --force`만 확정), 백업이 없으면 거부. 시험: 차이 332건 → 거부.
- **반영 기록을 읽다 오류가 나면 '첫 반영'으로 보고 직접 수정 확인을 건너뜀 / 기록을 지운 뒤 쓰다 실패하면 같은 일** →
  탭이 없을 때만 첫 반영, 읽기 오류·빈 기록은 멈춤. 기록은 지우지 않고 예전 크기만큼 빈칸으로 채워 한 번에 덮어씀.
- **원가 칸을 그대로 옮기는 수식(=K5)이 값으로 굳어 원가 숫자가 넘어감** → 멈춤. 시험: =K7 → "원가 흔적 발견 → 중단".
- 원가 검사에 끝이 열린 범위(E5:K), OFFSET, 이름 붙은 범위·표 참조 추가. 실제 원본 수식 518개(블랙 254·골드 264)에 새 규칙 걸린 것 0개.
- 안 고친 것: 최종 금액 비교 칸이 고정(F20·F17) — 위에 행이 들어가면 다른 칸을 비교하지만 칸 단위 비교가 실제 차이를 잡음. '내용에 맞춤' 행 높이는 비교 안 함(겉모양).
