# 2026-10-24 · 견적서 반영 — 탭 갈아 끼우기 → 바뀐 칸만 덮어쓰기

## 왜
반영(`scripts/quote/sync.mjs`)이 영업부용 탭을 통째로 새 탭으로 바꿔서, 반영할 때마다 영업부용의
칸별 수정 기록·댓글·탭 링크(gid)가 끊겼다(10-26 골드 표지 건에서 사용자가 수정 기록을 못 봄).

## 바뀐 것
- 영업부용 탭은 그대로 두고:
  1. 원가를 뺀 깨끗한 탭(원본 안에서 만들고 원가 흔적 검사 — 이전과 같음)을 영업부용에 숨김 준비 탭으로 복사
  2. 원본에서 넣고 뺀 행을 같은 자리에서 넣고 뺌 — 행 짝짓기는 글자로 직접 쓴 칸(품목명·제목)으로, 번호·금액·수식은 기준에서 뺌
  3. 값·수식·서식·메모·입력 규칙이 다른 칸만 칸 복사(걸치는 병합까지 넓혀서), 병합·행 높이·열 너비·눈금선 맞춤
- 백업은 같은 시트 안 숨김 사본, `--rollback`은 백업 내용을 같은 탭에 다시 덮어씀(탭 링크 유지).
- 잠금은 탭이 그대로라 손대지 않음(새로 생기는 탭만 잠금).
- 구글 다시 시도 6번(약 33초) → 8번(2분 남짓): 1분 읽기 한도가 풀리기 전에 포기하던 문제.

## 시험 (블랙 시험용 사본)
| 시험 | 결과 |
|---|---|
| 변경 없이 반영 | 바뀐 칸 0, 탭 번호·크기·잠금 그대로 |
| 병합 묶음 안 행 넣기 + 행 지우기 + 행 높이 + 칸 수정 | 바뀐 칸 4만 덮어씀, 검증 전부 일치 |
| 영업부용을 망가뜨린 뒤 `--rollback` | 차이 264건 → 전부 일치, 탭 번호 그대로 |
| 영업부용 직접 수정 | 감지해 멈춤, `--adopt`로 원본에 옮긴 뒤 반영 |
| 댓글 단 행 위에 행 넣기 | 댓글이 행을 따라 내려감, 안 건드린 칸 수정 기록 유지(사용자 확인) |

## 한계
- 번호만 바뀌는 행처럼 글자 칸이 없는 행은 짝짓기 기준이 약해, 드물게 넣기/지우기 대신 "고친 행"으로 처리될 수 있다.
  내용은 칸 비교로 항상 맞게 되지만 그 행 댓글이 한 칸 어긋날 수 있다.
- 병합의 아래쪽 칸(대표 칸이 아닌 칸)에 들어간 값은 화면·읽기에 안 보여 변경 감지에도 안 잡힌다(시험 중 확인, 원래 그런 구조).
