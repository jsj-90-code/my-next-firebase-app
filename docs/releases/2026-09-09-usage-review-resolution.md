# 요금 분리 모형 검토 마무리

사용자가 Claude의 주간 사용량 부족으로 배정한 검토까지 Codex가 인수하도록 요청했다. 추가 Claude 호출 없이 전달 문서와 분석 코드를 검토하고 계산을 재현했다. 같은 에이전트의 재검토이므로 별도 모델의 독립 검토 완료라고 표현하지 않는다.

## 고정 PC비중 제안의 비교 오류

`2026-09-09-claude-usage-review.md`의 PC매출 MAPE 5.82%는 40곳의 **실제 총매출**에 전체 평균 PC비중을 곱해 얻은 값이다. 신규점 총매출을 예측하는 오차를 포함하지 않으며 대상 점포와 참고점도 평균 비중에 들어간다. 실제 총매출을 미리 아는 분해 실험으로는 유효하지만 신규점 예측 정확도 비교로는 사용할 수 없다.

자료 시점은 `2026-09-08T00:05:10.035Z`로 고정했다. 현재 코드가 사용한 정식 표본 38곳과 같은 점포를 비교했고, 고정 비중은 각 대상 점포를 뺀 37곳에서 계산했다. 총매출도 해당 점포를 뺀 기존 총매출 모형의 최종 예측값을 사용했다.

| 항목 | 기존 총매출 예측 × 대상 제외 평균 비중 | 현재 PC·먹거리 분리 모형 |
|---|---:|---:|
| PC매출 MAPE | 10.500% | 14.409% |
| 먹거리 매출 MAPE | 12.986% | 12.599% |

고정 비중의 PC 오차는 이 자료에서 낮지만 먹거리 오차는 높다. "2.5배 정확"이라는 주장은 비교 조건이 다르므로 채택하지 않는다. 반복 활용한 표본에서 얻은 결과이며 미관측 신규점 성능을 입증하지 않는다.

### 요금 직접 반영 조건

기존 총매출 모형을 **변경 요금으로 다시 계산하고** 일정 비중으로 나누면 먹거리도 달라지고 PC매출은 요금에 정비례하지 않는다. 정식 표본 첫 점포의 1,500원→1,000원 비교에서 총매출은 55,133,523→50,630,216원, 먹거리는 약 28,878,915→26,520,085원이다. PC매출 비율은 0.9183이며 요구된 2/3가 아니다.

기존 예측을 특정 기준요금에서 고정한 뒤 PC분만 비례 조정하는 **별도 시나리오**라면 계산 가능하다. 그러나 기준요금을 어떻게 고정할지와 후보지 기본정보에서 요금을 바꿀 때의 일관성을 별도로 정의해야 한다. 현재 모형과 같은 성질이면서 정확도 손실이 없다고 말할 수 없다. 현재 주 모형을 교체하지 않는다.

재현: accuracy-release에서 `npx.cmd vitest run src/lib/storeEval/_fixedShareIndependentReview.test.ts --reporter=verbose`.
로컬 보관 자료가 필요한 미추적 분석이며 CI·배포에 포함하지 않는다. 결과는 루트 `.local-tools/fixed-share-independent-review-20260909.json`에 저장했다.

## 기타 해석 정정

- 요금과 PC비중의 상관이 유의하지 않다는 결과는 비중의 불변성이나 동일 점포의 가격 변경 효과를 입증하지 않는다.
- 역산 가동률이 설정 상한 55% 아래라는 사실은 현재 요금이 과거 실효요금과 같다는 증거가 아니다. 또한 55%는 모형이 설정한 운영 상한이며 초과 관측만으로 원인을 과거 요금 차이로 확정할 수 없다.
- 전체 오차가 구성별 MAPE보다 낮은 이유를 12곳의 부호 상쇄만으로 모두 설명할 수 없다. 총매출 상대오차는 실제 구성 비중으로 가중한 오차다. 부호 상쇄는 일부 기여이며 인과적 원인 규명은 아니다.
- ±20% 밖으로 이동한 네 점포에서 PC 오차가 모두 주도했다는 표현은 맞지 않는다. 양주덕정·장산은 먹거리 상대오차의 절댓값이 PC보다 크다. 청주지웰시티·김포구래와 같은 이유라고 묶지 않는다.
- 요금 변경 후 실제 관측이 없으므로 현재 총매출 MAPE나 PC MAPE 어느 하나도 요금 시나리오의 검증된 신뢰구간이 아니다.
- A4 lambda 30은 현재 구조에서 ±10% 20/38→18/38, 최악 과소·과대 모두 악화하여 적용 보류를 유지한다.

## 구현 검토 및 추가 검증

- 후보지 화면은 `trainingSales`를 넘기고 검증 화면은 `runUsageCohortValidation`을 사용한다. 두 경로가 `fitUsageRevenueModel`과 `predictUsageRevenue`를 공유한다.
- 요금 특징은 이용시간·먹거리 학습에서 제외되며 PC매출에 직접 곱한다. 과거 PC매출 / 현재 등록요금은 이용시간 대용값이라는 한계가 보고서 문맥에도 포함된다.
- 검증 대상은 두 구성 모형의 학습에서 제외된다. 외부 참고점은 전체 적격 표본으로 예측한다. 자료 부족 시 검증된 것처럼 과거 모형으로 되돌아가지 않는다.
- 학습용 매출 구성은 완료월과 기존 안정화 매출 구간을 맞추며 구성 합계와 목표 매출을 대조한다. 현재 보관 자료에서 적격 표본 손실은 없다. 미래 입력의 완전성을 보장하는 결론은 아니다.
- 추가 회귀 검증: 좌석 상한이 적용된 후보지의 요금 비례, 먹거리·이용시간·가동률 유지, 최종 구성 합계와 보수매출 연결을 확인했다.
- 추가 회귀 검증: 초과수요 이용시간 500시간을 받은 정식 점포와 외부 참고점의 반영, 좌석 상한, PC·먹거리 합계, 학습 표본 수 15/16을 확인했다. 이는 코드 경로 검사이며 실제 경쟁점 초과수요의 경제적 효과 검증은 아니다.
- 최초 후보지 상한 테스트에서는 초과수요까지 동시에 생길 것으로 가정했으나 자사 수용량도 이미 넘은 입력이라 초과수요 보너스가 0이었다. 해당 테스트는 상한 검증으로 한정하고, 초과수요는 명시적인 입력을 가진 검증 경로에서 별도로 확인했다. 구현 결함으로 보고하지 않는다.

최종 검증: 일반 테스트 19파일 454개, 고정 비중 비교 분석 1개 통과. TypeScript, 변경 테스트·추가 분석 파일 ESLint, diff 검사 통과.

애플리케이션 산식이나 운영 자료·설정을 바꿀 구체적 결함은 이번 검토에서 확인하지 못했다. 변경 범위는 회귀 테스트와 검토 기록이다. 빌드·운영 배포는 수행하지 않았다. 과거 요금 자료 확인과 신규점 검증은 장기 정확도 개선 과제로 남으며 Claude 회신 대기 과제는 없다.
