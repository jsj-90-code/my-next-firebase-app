## 1. 산식 구조 — `src/lib/storeEval/textbookModel.ts`

매출을 **세 층의 곱**으로 본다. 층마다 독립으로 맞춘다.

```
월매출 = 수요시간 x 점유율 x 총단가

[1층] 수요   = (주거인구 1km 연령가중 + 유동인구 400m 연령가중 x 0.15) x 특수수요배수
              x hoursPerUserPerMonth(축척)
[2층] 점유율 = 자사PC ÷ (자사PC + Σ 경쟁PC_i x (경쟁품질_i ÷ 자사품질)^θ) x 입지배율
              θ=3 · 유효거리 300m 계단(밖은 0) · 바깥선택지 0
[3층] 총단가 = PC몫 + 상품몫
              PC몫 = 1343 x (정가/1343)^0.546   ·   상품몫 = 상수 1,493원
```

**축척을 맞추는 순서가 중요하다** (`fitHoursPerUser` → `fitProductUnitPrice`):

1. `hoursPerUserPerMonth` ← **독점 매장(경쟁IP=0) 3곳의 실측 가동률**에서만 맞춘다.
   독점은 점유율이 1이라 수요식만 남는다. 전체로 맞추면 경쟁 항의 오차가 축척에 스며들어
   "수요가 맞는지"를 영영 못 가른다.
2. `productUnitPrice` ← 실측 가동률이 있는 **전 매장**에서 남은 몫으로 맞춘다.

독점 3곳: **탕정역점 · 광주각화점 · 남악점**.

### ⭐ 핵심 진단 — 여기서 시작하면 된다

```
log(필요 점유율) = a + b x log(예측 점유율)      b = 0.765   r = 0.804

  필요 점유율 = 실측 가동률 ÷ "경쟁이 아예 없다고 본" 예측 가동률
              = 우리 수요식이 맞다면 이 매장이 실제로 먹은 몫

예측 점유율 4분위        필요÷예측
  1분위  31%(경쟁 센 곳)   1.49     <- 49% 과소예측
  2분위  45%              1.18
  3분위  62%              1.12
  4분위 100%(독점)         1.01     <- 거의 완벽
```

**독점에서는 산식이 정확하고, 경쟁이 셀수록 틀린다. 완벽하게 단조롭다.**
독점 3곳의 필요 점유율 퍼짐도 SD(log)=0.0084로 거의 0이다 → **수요식은 맞다.**

⚠️ **b가 유일한 구조 지표다.** 축척(`hoursPerUserPerMonth`)도 경쟁무게 전역 상수도
`a`만 움직이고 `b`는 못 바꾼다. 그래서 "MAPE가 좋아졌다"는 수준을 맞춘 것일 수 있지만,
**b가 1로 갔다면 구조가 맞은 것이다.** 판정은 b와 r로 한다.

## 4. ⚠️ 밟으면 안 되는 함정 — 전부 실제로 밟은 것들이다

1. **나눗셈 함정** — 필요 점유율은 수요로 나눈 값이라 인구와 **자동으로** 음의 상관이 난다.
   "필요 점유율 ↔ 인구"를 그냥 보면 안 된다. (`_demandGap`)
2. **훑기 유의선** — n=38에서 단일 가설은 ±0.32가 맞지만, **9가지만 훑어도 우연히 ±0.41**이
   나온다. 훑기 결과를 ±0.32로 판정하지 말 것. (`_schoolInflow` 4절)
3. **순환** — 분류에 쓴 재료로 분류를 설명할 수 없다. `_marketSupply`가 본보기다:
   관문 셋을 통과했는데 순환을 걷어내니 죽었다.
4. **축척이 수준을 흡수한다** — MAPE가 좋아졌다고 구조가 맞은 게 아니다. b를 봐라.
5. **`effectiveRadiusM` 이중 필터** — `computeTextbook`이 경쟁점을 유효거리로 **한 번 더**
   거른다. 경쟁점 `ip`를 아무리 바꿔도 300m 밖이면 그냥 건너뛴다. 감쇠를 실험하려면
   `effectiveRadiusM: Infinity`로 계단을 꺼야 한다. (`_rivalDecayNormalized` 주석)
6. **목표값 창** — `actualMonthlyRevenueAvg`는 `evaluationMonths`(개점월+1부터)가 아니라
   **elapsedMonths 2~12**(개점월+2부터, 없으면 1~12)의 평균이다. 한 칸 어긋나면 어린 매장의
   지수가 통째로 틀린다. 38곳 전부 이 정의와 맞는 걸 확인했다.
7. **스냅샷이 세션 중에 낡는다** — 사용자가 웹에서 점수를 고치고 있으면 그 밑에서 값이 바뀐다.
   후보지 숫자를 인용하기 전에 문서 `updatedAt`과 스냅샷 `fetchedAt`을 대조할 것.
8. **한 효과만 보정하면 과보정** — 계절(6~8월 1.16)과 램프(2~3개월차 0.87)가 서로 상쇄한다.
   하나를 고칠 때 반대로 도는 게 없는지 먼저 볼 것. (`_seasonality`)

## 5. 판정 규칙 — 이 저장소의 관례

새 갈래를 팔 때는 **파일 머리에 관문을 먼저 적고** 시작한다. 결과를 보고 기준을 고치지 않는다.
커밋 순서로 그걸 확인할 수 있게 한다(`_leisureAlternatives`는 자료를 받기 전에 커밋했다).

관문은 보통 이렇게 짠다:

```
관문 0  검정력 — 그 축에서 실제로 움직이는 매장이 몇 곳인가. 5곳 미만이면 판정 안 한다
관문 1  과녁에 재료가 들어가 있나 — 한 줄씩 적는다. 들어가 있으면 그 축은 증거가 못 된다
관문 2  중첩 확인 — 새 자유도를 끈 값(δ=1, ν=1, ψ=0)이 지금과 소수점까지 같아야 한다
관문 3  LOO 홀드아웃 — 축척·상품몫까지 훈련겹에서만 맞춘다
관문 4  ⚠️ 가운데가 안 무너지나 — 오차 4분위로 갈라 1·2분위를 본다.
        꼬리만 좋아지고 가운데가 나빠지면 트레이드오프다. 오늘 δ·ν·감쇠가 전부 여기서 죽었다
관문 5  무작위 대조군 — 그 축을 매장 안에서 섞는다. 섞어도 같은 이득이면 그 축이 한 일이 아니다
관문 6  짝지은 부트스트랩 — 개선폭 95% 구간이 0을 품으면 자료가 못 고른 것이다
```

**자료가 못 고르면 실무 판단이 이긴다.** 2026-09-21 오송점에서 그렇게 결정했다
(`_effectiveRadiusRetest` — 부트스트랩이 0을 품고 가짜 반경 대조군이 실제와 같이 나빠졌다).

## 6. 지금 열려 있다고 보는 것

손잡이는 여섯 방향 다 막혔다. r=0.804를 넘으려면 **산식이 지금 못 보는 정보**가 필요해 보인다.

1. **경쟁점 방향** — 같은 400m라도 방향이 결정적이다. 오송점은 경쟁점이 배후와 자사 **사이**,
   하안금당은 경쟁점 3곳이 **유동 몰리는 쪽**을 선점했다. 한 번 기각됐지만(`_rivalDirection`)
   그 검정의 명시된 한계가 *"300m 바깥을 안 본다 · 방향 자료가 격자 300m로 거칠다"*이다.
2. **경쟁점 좌석률** — "그 경쟁점이 실제로 차 있나". 지금 커버리지 100%가 9곳/33곳뿐이라
   검정력이 없다(유의선 ±0.58). 진주혁신 2.0% · 광주첨단 9.4%로 꼬리가 여기 몰려 있다.
3. **건별 매출원장** — 객단가·체류시간·정액할인의 실체. 상품몫이 상수 1,493원인데 실측은
   1,060~2,080원으로 2배 차이가 난다. 유형별로 갈리는 조짐이 있으나 표본 부족으로 [보류]
   (`_productShareByType` — 대조군 p=0.076).
4. **표본 확대** — 기존점 7곳 더 필요. 2027 상반기.
