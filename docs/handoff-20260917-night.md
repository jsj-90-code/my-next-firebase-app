## 2. ⭐ 채택된 것 — 존구성을 룸으로 센다

```
존구성 = 룸종류점수 x 0.3 + 특화좌석점수 x 0.7

룸종류 = 1인룸 · 2인룸 · (팀룸 + 퍼스트클래스존) 중 갖고 있는 종류 수 (0~3)
특화좌석 = 이름과 무관하게 실재하는 좌석 전부 / 총PC
         퍼스트클래스존 1개 = 11석 · 팀룸은 실좌석 우선(없으면 개수 x 5)
```

**왜** — 존 이름표가 한쪽에만 있었다.

```
VIP존 · 프렌즈존 · 퍼스트클래스존  ->  자사 29/19/19곳, 경쟁점 228건 전부 0건
자사엔 "일반 2인석" 칸이 아예 없다  ->  우리 2인석은 전부 커플존으로 계상
```

우리 브랜드 용어라 조사자가 경쟁점의 같은 실체를 보고도 그 칸에 안 넣는다. 그래서
**종류를 세면 자사가 항상 이겼다**(41/41곳). 룸만 세면 자사 35/41 · 경쟁점 23/153이 된다.

**룸은 정의가 명확하다** — 벽과 문이 있나 없나. 파티션 높이·재질 판단(유리냐 목재냐)이
안 들어가고 양쪽 다 조사돼 있다. 개방석은 모든 PC방에 있어 칸으로 세면 상수라,
개방형 이름표는 **좌석으로만** 들어간다.

**어디에 넣었나**
- 새 파일 `src/lib/storeEval/labZoneComposition.ts`
- `labInput.ts`가 이걸 쓴다 → 실험실 **화면과 하네스가 같은 함수**를 본다
- 실험실 화면에 설명 블록 추가(비중은 상수에서 읽어 그린다)
- ⚠️ `calc.ts`는 안 건드렸다. 운영 V62 존구성은 그대로다
