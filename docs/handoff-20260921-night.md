```
log(필요 점유율) = a + b x log(예측 점유율)      b = 0.765   r = 0.804

예측 점유율 4분위        필요÷예측
```

**독점에서는 수요식이 정확하다**(독점 3곳 퍼짐 SD(log)=0.0084). 경쟁이 셀수록 틀린다.

  없앨 수 있지만 MAPE가 61%로 터진다. r이 세 방식 모두 0.804로 똑같은 게 이유다 —
  **축척은 모든 매장을 같은 비율로 밀 뿐이라 매장 간 상대를 못 바꾼다.**

## 2. ✅ 거리 감쇠 — **채택 완료** (커밋 `27caaf2`)

```
textbookModel.ts  rivalDistanceDecay: { plateauM: 300, scaleM: 150, weightFactor: 0.90 }
```

⚠️ **`weightFactor`가 이 채택의 핵심이다.** 감쇠를 켜면 300m 밖이 새로 세져 총 경쟁량이
늘어나는데, 축척은 **독점매장(경쟁 0)에서만** 맞추므로 그걸 못 흡수하고 전 매장이 아래로
밀린다. 2026-09-20에 이 설계가 실패한 이유가 정확히 그것이다. 실제로 보정 없이 켜 보니
최악이 **안 줄었다**(54.7 → 55%). 0.90을 넣으니 51.9%로 줄었다.
자의적 계수가 아니라 `Σ(ip x 계단) ÷ Σ(ip x 감쇠)`로 잰 정규화다. 표본이 늘면 다시 잰다.

아래는 그 결정의 근거다.

### 결정

> *"감쇠로가자. 개념이 그게맞을것같다. 기본 거리는 100으로보고, 기준 거리초과하는매장은 감쇠.
> 이게 개념이 맞는거같은데. **나중에 401m 나오면그건어쩔건데.**"*

계단의 근본 문제를 짚은 말이다 — 경계를 어디에 두든 **그 바로 밖 사례가 계속 나온다.**
오송점 342m가 그랬고, 400으로 옮기면 하안금당 407m가 그렇다.

### 값 — R=300 · λ=150 (내가 판단, 사용자 위임)

```
무게 = 1                        (거리 <= 300m)
     = exp(−(거리 − 300) ÷ 150)  (그 밖)

곡선   300m 100% · 350m 72% · 400m 51% · 500m 26% · 700m 7% · 1km 1%

실제   오송 팀플PC 342m   76%   (지금 0%)
       하안금당 407/446/480m  49/38/30%
       문경 371m  62%  ·  1500m  0%
```

**기준거리를 400으로 안 넓힌 이유** — 격자를 돌려보니 R=400은 r이 0.803~0.809로 오히려
떨어지고 LOO도 22%대다. 감쇠를 켜면 342m가 이미 세지므로 넓힐 필요가 없다.

**λ=50이 성적은 낫지만(19.96%) 사실상 계단이다** — 350m에서 이미 37%로 떨어진다.
개념을 사기로 한 결정이니 150이 그 개념을 제대로 구현한다.

### 성적 — 지표가 서로 다른 말을 한다

```
                r      LOO MAPE   최악    SD       1분위(가운데)
계단300(지금)  0.804    19.02%   54.7%  16.0%p     3.5%
R=300 λ=150   0.812    21.11%   51.9%  ~15%p     11.5%
```

**짝지은 부트스트랩 2000회 (채택 판정)**

```
MAPE 차이   실제 +2.09%p   95% 구간 [-0.02, +4.57]%p   0을 품는다 → **자료가 못 고른다**
최악 차이   실제 -2.8%p    95% 구간 [-3.8, 0.0]%p      상한이 0.0 → 개선이 거의 유의
```

👉 **자료가 계단을 못 고른다.** 그러면 오늘 아침 오송점에서 세운 규칙이 적용된다 —
*자료가 못 고르면 실무 판단이 이긴다*(`_effectiveRadiusRetest`). 사용자가 개념을 택했으므로
채택 가능하다.

⚠️ **알고 넣어야 할 것** — 좋아진 곳 14 · 나빠진 곳 19. 특히 **장산점이 2.2% → 40.5%**로
38%p 나빠진다(302m·345m에 211/193대가 새로 세진다). 넣고 나면 이 매장을 따로 봐야 한다.

재현: `_rivalDecayNormalized.test.ts` (6)(7)절

## 3. ⛔ 오후에 닫은 것 — 점유율식 여섯 방향

| 갈래 | 무엇 | 결과 |
|---|---|---|
| δ 경쟁점 규모 지수 | `자사PC^δ ÷ (…+Σ경쟁PC^δ…)` | 대조군 **p=0.980** |
| 거리 감쇠(총량 자유) | 어제 설계 재현 | LOO 20.9~28.7% |
| 거리 감쇠(총량 고정) | 전역 상수로 총량 묶음 | MAPE는 지고 **최악·r은 이김** → 2절 |
| θ 품질 지수 ↑ | 3 → 4·5·6·8 | r **0.804 → 0.713** |
| ν 점유율 지수 | `rawShare^ν` | b는 고쳐지나 가운데 3.5→14.0% |
| 거리 x 품질 | `R_i = 300 x (품질비)^ψ` | 대조군 **p=0.075** |

**공통 패턴**: b(편향)는 여러 방법으로 고칠 수 있는데 **고칠 때마다 분산이 커진다.**
지금 값(θ=3 · ν=1)이 편향-분산 최적점이다.

⚠️ 마지막 것에서 표본의 일반 사실이 하나 나왔다 — **경쟁점은 대체로 우리보다 품질이 낮다**
(품질비 < 1). 그래서 품질 기반 손잡이는 전부 "경쟁을 덜 센다" 방향으로만 작동한다.
오송 팀플PC 0.80 · 하안금당 0.62~0.77 — 품질로는 이 자리가 안 풀린다.
