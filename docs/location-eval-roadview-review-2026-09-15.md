# 입지동선평가 전수 검토 — 카카오 로드뷰 직접 확인 (2026-09-15)

사용자 요청: "신규후보지 점포입지평가 너가 좀 해줄래? 기능에 들어가 있는 AI 초안받기 말고 너가 직접" →
"9곳 전부 재검토" → "지금 카카오 API 들어가 있고, 거리뷰도 너가 직접 보면 되니까 싹 다 정리" →
"기존 가맹점도 해줘"

## 방법

1. **좌표 확보** — 후보지는 저장된 lat/lng(8곳), 없는 1곳과 기존점 41곳은 카카오 로컬 API로 지오코딩(41/41 성공).
2. **로드뷰 직접 확인** — `https://map.kakao.com/link/roadview/{lat},{lng}`를 Playwright로 열어 캡처 후 육안 확인.
   촬영 시점 2024-08 ~ 2026-07. 캡처는 `.playwright-mcp/`에 보관(`rv-N0xx` 후보지, `ex-{storeCode}` 기존점).
   ⚠️ 파노라마가 WebGL이라 페이지 로드 직후엔 검게 나온다. **촬영날짜 텍스트(`/20\d\d년 \d\d월/`)가
   뜰 때까지 기다린 뒤** 캡처해야 한다 — 6~7초 고정 대기로는 실패한다.
3. **기존 38곳 잣대와 대조** — 내 판단으로 새로 매기는 대신, **학습 표본이 실제로 어떤 기준을 쓰는지**
   먼저 역산해서 그 잣대로 후보지를 다시 쟀다. 다른 자로 재면 예측이 깨지기 때문이다.

## 1. 기존 가맹점 41곳 — 고칠 것이 없다

### 접근가시성은 층수에 따라 거의 기계적으로 매겨져 있다

| 층 | 곳수 | 가시성 점수 |
|---|---:|---|
| 1층 지상 | 1 | 5 |
| 2층 + 엘베 | 14 | **4** (13곳이 4) |
| 3층 + 엘베 | 7 | **4** (전부) |
| 4층 + 엘베 | 6 | **3** (전부) |
| 5층 + 엘베 | 3 | **3** (전부) |
| 6~7층 | 3 | **2** (전부) |
| 지하1층 | 3 | 평균 2 |

이 규칙으로 38곳을 다시 채점하니 **35곳(92%)이 그대로 나왔다.**

### 안 맞는 3곳은 평가자가 더 정확했다

로드뷰로 확인한 결과다.

- **전대후문점** (지하1층·엘베X인데 3점) — 전남대 후문 **사거리 코너**이고 건물 외벽에 `PC CAFE 3F`
  간판이 크게 걸려 있다. 지하여도 눈에 띈다. 가동률 47%로 38곳 중 최고다.
- **구미산동점** (2층인데 3점) — 신도시 상업지구의 **차량 위주 넓은 도로**. 보행 노출이 적다.
  가동률 21%로 38곳 중 최저다.
- **증평점** (지하1층·엘베X, 1점) — 증평읍 사거리. 지방 소읍이고 지하+계단. 가동률 18%로 최저다.

즉 **층수를 기본으로 하되 거리 맥락으로 조정**하고 있었다.

## 2. 후보지 9곳 — 8곳이 잣대에서 벗어나 있다

**후보지만 접근가시성이 층수와 무관하게 거의 다 3점이다.**

| 후보지 | 층 | 현재 가시성 | 38곳 잣대 |
|---|---|---:|---:|
| 춘천퇴계점 | 6층 | 3 | **2** |
| 호구포역점 | 2층 | 3 | **4** |
| 하안금당사거리 | 지하1 | 3 | **2** |
| 울산삼산점 | 2층 | 3 | **4** |
| 평택소사벌점 | 2층 | 3 | **4** |
| 마산산호점 | 2층 | 3 | **4** |
| 산본점 | 7층 | 1 | **2** |

모형은 "2층 = 4점"을 38곳에서 배웠는데 2층 후보지에 3점을 주면 그만큼 깎아서 예측한다.
2026-09-15부터 접근가시성이 매출에 직접 곱해지므로(`accessScoreMode: visibility-x-preemption`)
이 어긋남이 그대로 오차가 된다.

|---|---|---|

### 선점경쟁 — 명백한 3건

- **마산산호점 2 → 4** — 경쟁점 2곳이 **187m·206m 밖 4층**인데 우리는 2층. 우리가 유리한데 불리 점수다.
- **산본점 3 → 2** — 우리 7층인데 경쟁점 9곳이 **전부 지하1층**(32~143m, 그중 185대·164대).
  명백히 선점당했는데 중립 점수다.
- **창원상남점 3 → 2** — 12곳이 24m부터 밀집, 우리(4층)보다 낮은 층 4곳.
- (보조) **하안금당 3 → 4** — 경쟁점 3곳이 407m 밖. **울산삼산 1 → 2** — 1점은 38곳에 없는 값.

## 4. 따로 판단이 필요한 것 — 선점경쟁 정의

2026-09-01에 선점경쟁을 **"경쟁점 개수가 아니라 특정 경쟁점이 더 좋은 자리를 차지했는지"**로
재정의했는데, 실제 데이터는 여전히 개수·거리를 따르고 있다.

| 점수 | 경쟁점 수(평균) | 최근접(중앙) |
|---|---:|---:|
| 5 | 0곳 | — |
| 4 | 2.6곳 | 145m |
| 3 | 5.0곳 | 65m |
| 2 | 5.6곳 | 60m |

선점경쟁과 경쟁점 개수의 상관이 **−0.466**이다(재정의 전 −0.51~−0.64).

지금은 **기존 38곳과 후보지가 같은 방식**이라 내부 일관성은 있다. 새 정의로 바꾸려면 50곳을
한꺼번에 다시 매겨야 하고, 그러면 학습 데이터가 바뀌어 모형 전체가 달라진다. 별도 판단 사항이다.

## 5. 한계

- 로드뷰는 좌표 지점의 **기본 방향**만 봤다. 건물 정면을 돌려서 확인하지 않았다.
- 기존 41곳 중 **9곳만 육안 대조**했다(캡처는 41곳 전부 보관). 나머지는 층수 규칙 92% 재현으로 갈음했다.
- 상권위치·동선은 거리 한 장으로 판단한 것이라, 현장을 아는 사람의 판단이 우선한다.
