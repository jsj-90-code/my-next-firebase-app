## 2. ⭐ 오늘 본론 — 상권 분리 눈가림 판정

### 왜 하나

경쟁상권 35곳이 **평균 12.6% 과소예측**된다(독점 3곳은 +3.0%). 점유율을 너무 낮게 본다는 뜻이다.
계수로는 안 고쳐진다 — θ를 올리면 치우침은 닫히는데(−15.6%p → +0.9%p) **퍼짐이 커진다**
(MAPE 22.51% → 25.93%). 자를 맞춘 뒤에 올려도 마찬가지다(27.08%).

> **치우침을 줄이면 퍼짐이 커진다 = 계수가 아니라 변수가 빠졌다.**

사용자가 그 변수를 짚었다: *"부천상동역점같은경우에 대로변이 왕복8차선도로이고 이 사거리를
기준으로 매장들이 되게많아. 위쪽매장들이랑 아래쪽매장들이 상권이 좀 나뉘는데 거리는 유사거리니까
이게 경쟁이 같이잡히는상황"*

### 이미 나온 증거 (그리고 그 한계)

사용자가 두 매장에서 손으로 지목했다.

| 매장 | 뺀 경쟁점 | 잔차 |
|---|---|---|
| 강릉교동점(신) | 라이킷(216m 남) · MX5(240m 남서) | −42.1% → −33.2% |
| 부천상동역점 | 더엑스(214m) · 크리드(238m) · 레벨업(249m) 전부 남서 | −38.5% → **−8.8%** |

둘 다 **과소예측 상위권**이고, 지목된 경쟁점이 **전부 한 방향에 몰려 있다.** 그 방향에서
300m로 이미 빠진 매장도 있다(헌터 392m 남서 · 철구 309m 남서).

**그런데 사용자가 스스로 한계를 짚었다**: *"근대내가 지금 예상매출 낮은매장만 보고있긴함"*

그래서 질문을 바꿔 검정했다 — "빼면 좋아지나"가 아니라 **"하필 그 경쟁점을 고른 게
아무거나 고른 것보다 나은가"**. 같은 수를 빼는 조합을 **전부** 세어 등수를 봤다.

| 매장 | 사람 판정 등수 | 백분위 |
|---|---|---|
| 강릉교동점 | 4등 / 15가지 | 상위 27% |
| 부천상동역점 | 12등 / 35가지 | 상위 34% |

**중앙보다 낫지만 1등과는 멀다. 그냥 "빼면 좋아진다"와 구분이 안 된다.**
(부천상동역점은 어떤 조합을 빼면 오차 0.1%까지 떨어진다 — 답안지 맞추기다.)

### 그래서 눈가림이 필요하다

**절차**
1. **판정 목록을 뽑는다** — 매장명·경쟁점명·거리·방위·좌표·지도링크만.
   **잔차·예상매출·실매출·PC대수 비교는 절대 넣지 않는다.**
2. 순서를 **섞는다**(고정 시드). 과소예측 매장이 앞에 몰리면 그것만으로 단서가 된다.
3. 사용자가 지도만 보고 **"같은 편 / 길 건너 / 모르겠음"** 삼지선다로 판정한다.
4. **전 매장을 다 판정한 뒤** 한꺼번에 잰다. 중간에 성적을 보면 눈가림이 깨진다.
5. **무작위 대조군**으로 검정한다 — 같은 수를 무작위로 뺀 것보다 나아야 한다.

**⚠️ 과대예측 매장을 반드시 포함할 것.** 부경대점(+56.2%) · 수원망포점(+31.6%) ·
발산역점(+24.6%) · 전대후문점(+19.0%). **거기서도 "길 건너"가 잔뜩 나오면 이 변수는
잔차와 무관한 것이다.** 그게 진짜 시험이고, 넣지 않으면 검정 자체가 성립하지 않는다.

### 자동 판정도 알아볼 것

230쌍을 손으로 보는 대신 자동으로 되면 좋다. 후보 둘:

1. **도보거리 ÷ 직선거리** — 길 건너면 횡단보도로 돌아가 비율이 커진다.
   ⚠️ 카카오 공개 API에 **보행자 경로가 있는지 확인이 안 됐다.** 자동차 경로는 유턴 때문에
   보행 장벽과 다르게 나오므로 대용으로 쓰면 안 된다.
2. **OSM 주요 도로 교차 판정** — Overpass API(무료·키 불필요)로 자사↔경쟁점 직선이
   `highway=trunk/primary` 또는 차선 수가 큰 도로와 교차하는지 본다.
   장벽의 **뜻에 제일 가깝다.** 8차선이면 `lanes` 태그로 걸러진다.

자동이 되더라도 **사람 판정 표본과 대조**해야 한다. 자동 판정이 사람과 어긋나면 자동 쪽이
무엇을 놓치는지부터 봐야 한다.

### 판정 결과를 어디에 담나

⚠️ **경쟁점 문서를 지우지 말 것.** 조사 기록은 그대로 두고 파생값으로만 갈아끼운다
(`distanceM`을 좌표 거리로 대체한 것과 같은 방식). 새 필드를 하나 두고
`labInput.ts`에서만 읽는다 — `calc.ts`는 안 읽어야 운영 V62가 안 움직인다.

  즉 **자사와 동급**으로 센다(가장 불리한 쪽이다). 고칠 값이지만 **그 20곳은 전부 후보지
  경쟁점이고 기존점엔 0곳**이라 기존점 성적이 한 칸도 안 움직인다. **후보지 예측 전용 문제다.**
  (그중 9곳은 조사자가 "노후저경쟁력미조사"로 적은 곳 — 약하다는 정보를 거꾸로 쓰고 있다.)
- **유효거리 줄이기** — 200m에서 격차 −4.1%p지만 MAPE 26.04%로 나빠진다.
- **자(척도) 맞추기** — 자사를 경쟁점 평균으로 내리면 MAPE 33.28%로 무너진다(4절).

### 손잡이 훑기 결과

크게 틀린 전력이 있다(화면 설명 참고). **자료가 좋아 보인다고 켜지 말 것.**

그 후보지는 유동 몫(수요의 약 21%)과 중심도가 빠진 채 **말없이 낮게** 나온다.
구리돌다리점이 실제로 그랬다(3,886만 → 4,272만, +9.9%).

⚠️ `--include-500`은 쓰지 말 것 — **운영 V62가 읽는 유일한 유동 필드가 `floating500Avg`**다.
100/200/300/400/1000만 쓰면 V62 예측값이 안 움직인다.

⚠️ `settings`는 실험실로 동기화하지 않았다. 운영과 갈라져 있어 덮으면 기준값 22.51%가
조용히 움직일 수 있다. 사용자 결정 사항이다.

### 후보지 필드가 기존점과 다른 자리

| | |
|---|---|
| PC수 | **`expectedPcCount`** (기존점은 pcCount/evaluationPcCount) |
| 특수수요 | 매장 문서가 아니라 **입지평가**에 있다 |
| 관리 점수 | QSC가 없다 → 가맹점 평균 4.20 |
| 자사 시설 빈칸 | 결측이 아니라 **표준 구성**(STANDARD_OWN_FACILITY_DEFAULTS) |
| 경쟁력격차 | 품질 모드는 **안 쓴다**. null이어도 결과가 같다 |

## 7. 요금 — 검증 끝났다, 다시 꺼내지 말 것

사용자 질문: *"먹거리 제외되어야하기때문에 절반만 적용된다하면 지금이 적절한건가?"*

**겹치지 않는다. 지금이 맞다.**

- 상품몫 1,493원은 총단가의 47% — "절반은 요금과 무관"이 맞다
- β=0.546은 **실효단가 = PC매출 ÷ 참이용시간**의 회귀 기울기라 **분자에 먹거리가 안 섞여 있다**

분해: 요금 +46.7% → PC몫 +23.3%(β) → 총단가 +11.1%(상품몫 희석).

실측 버킷과 대보면 **모델이 6개 구간 전부에서 실측보다 +1.9~5.1%p 위**다 — 오히려 **덜 깎는다.**
"요금이 덜 반영된다"는 걱정과 반대 방향이다.

⚠️ **요금은 상권이 정하고 우리가 맞추는 것이다.** 2026-09-18에 "자사가 2,000원을 받을 수
있나"로 적었다가 지적받았다 — 그 상권 시세가 2,000원이라 맞추는 상황이다. 같은 인과 역전을
9/18에 CPU에서도 한 번 했다(*"i3라고 요금이낮은건아닌데"*). **요금을 매장 선택으로 쓰지 말 것.**
