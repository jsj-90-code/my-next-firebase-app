## 0. 사용자가 말한 것 (그대로)

> *"기존 V62 버전 산식을 자동화하려고 하거든. 주소만 입력하면 알아서 평가까지 완료되도록.
> 경쟁점평가, 인구분석 이런 거 기존에 반자동 하던 거 아예 자동화하는 거."*
>
> *"자동으로 안 되는 건 보정값 또는 고정값으로 변환해서 진행하자. 이건 별도로 진행하는
> 걸로 하자 **V62에 덮어씌우는 형태 말고.** 목적은 주소만 기입하면 예상매출까지 나오면서
> **너의(AI) 평가까지** 나오도록. **점포개발 초기 완전 초기자료**라고 보면 됨."*

핵심 제약 셋:
1. **운영 V62를 덮지 않는다.** 별도 경로로 만든다.
2. 모르는 값은 **보정값/고정값**으로 채운다.
3. 산출물은 예상매출 **+ AI 평가문**이다.

## 1. ⭐ 먼저 알아야 할 숫자 — 주소만으로 얼마나 맞히나

**이미 쟀다.** `src/lib/storeEval/_addressOnlyMode.test.ts` (운영 V62를 그대로 쓰고 입력만 비웠다).

| 단계 | n | MAPE | 중앙값 | ±10% | ±20% |
|---|---|---|---|---|---|
| L0 지금 — 전부 조사됨 | 38 | **8.83%** | 7.67% | 60.53% | 92.11% |
| L1 경쟁점 품질만 기본값 | 38 | 12.57% | 12.50% | 42.11% | 78.95% |
| L2 + 경쟁점 대수도 기본값 | 38 | 10.82% | 8.21% | 63.16% | 89.47% |
| **L3 + 입지평가도 없음 ← 주소만** | 38 | **13.40%** | 11.58% | 47.37% | **86.84%** |

**주소만 넣으면 MAPE 8.83% → 13.40%(1.52배)이고, ±20% 안에 86.8%가 든다.**
초기 선별용으로 쓸 만한 수준이다. 도구를 만들면 **이 숫자를 화면에 같이 띄워라** —
"이건 초기 추정이고 오차가 이만큼"이라고 말해 주지 않으면 정밀 평가로 오해된다.

### ⭐ 설계에 제일 중요한 발견 — L1이 L2보다 나쁘다

품질만 비우고 **대수는 실측**을 쓰면 12.57%인데, 둘 다 비우면 10.82%다.
**어설프게 반만 채우면 자료가 어긋나 더 틀린다.**

> 조사가 들어오면 **품질과 대수를 같이** 채워야 한다. 한쪽만 채우지 마라.

## 2. 좋은 소식 — 기본값 장치가 이미 코드에 있다

새로 만들 게 아니다. 운영 V62가 **이미 결측을 처리한다**:

| 모르는 값 | 누가 채우나 | 어디 |
|---|---|---|
| 자사 시설 구성 빈칸 | 회사 표준 존 구성 | `applyStandardOwnFacilityDefaults` (calc.ts) |
| 경쟁점 PC 대수 빈칸 | 간략_기본대수 90대 | `computeCompetitorAppliedPcCount` (calc.ts) |
| 경쟁점 품질 빈칸 | 결측 처리 → 동급(비율 1) | `rivalQualityParts` · `computeQualityScore` |
| 자사 관리 점수 | 가맹점 평균 | `resolveManagementScores` |

⚠️ **하나 예외가 있다 — 가시성 점수(`visibilityScore`)는 없으면 정식검증군에서 빠진다**
(`isCoreEligibleForV61Training`의 `hasRequiredVisibility`). 처음에 입지평가를 통째로
비웠더니 표본이 0이 됐다. 위 L3는 **표본 중앙값으로 치환**해서 잰 것이다.
→ 도구에서도 가시성은 고정값을 주거나 로드뷰 자동 판정을 붙여야 한다.

## 4. ⚠️⚠️ 자동 자료는 조용히 틀린다 — 오늘 밟은 함정 전부

**이게 이 문서에서 제일 중요한 절이다.** 지금은 사람이 중간에 있어서 걸러지는데,
자동화하면 **그대로 결재 숫자로 들어간다.**

| 자료원 | 함정 | 근거 |
|---|---|---|
| 카카오 장소 | **매장당 40건쯤에서 잘린다**(다만 실체 판정은 제일 정확하다) | 전대후문 인허가 216건 vs 카카오 32건 |
| 소상공인 상가업소 | **폐업을 못 따라온다** | 구리돌다리 500m에 폐업 추정 7곳이 남아 있다(사용자 확인) |
| 인허가(LOCALDATA 후신) | **폐업 미신고가 대량으로 "영업"이다** | 안산선부 500m에 "퍼니PC방(적발:2010.3월경)" "해피데이PC (유선통보 2009.)"가 영업으로 남아 있다 |
| 인허가 `TOTAL_GMCON_CNT` | **소형 구간은 가짜다** | 사용자: *"20대, 6대 매장 없어 저거 가짜야"* · 70 이상이면 실측과 일치(±20% 안 78%) |
| 인허가 `FCAR`(면적) | **40%가 말이 안 된다** | 우리 발산역점이 95대에 25.04㎡로 등록돼 있다 |
| 상가업소 업종 R10406 | **성인PC방(오락기)이 섞인다** | 사용자 지적. 인허가 짝이 없으면 자동으로 빠진다(진주게임랜드·꽃길PC라운지 등) |
| 같은 건물 다중 등록 | **80m 매칭이 죽은 등록을 살린다** | 문정프라자·서울프라자에 PC방 등록이 대여섯 개씩. 결합은 **상가업소 → 인허가** 방향으로 |

### 그래서 정한 결합 규칙 (2026-09-22 밤 최종)

```
실체 = 카카오 장소  −  오락실류(상호 규칙)
시점 = 인허가 인허가일자·폐업일자 (짝이 없으면 세는 쪽에 둔다)
대수 = 운영과 같은 미조사 기본대수 90대   ← 아직 안 풀린 자리(5절)
```

⚠️ **인허가로 목록을 만들지 마라. 이미 확인된 가게에 날짜만 달아 줘라.**
같은 건물에 PC방 등록이 대여섯 개씩 겹쳐 있어서, 인허가를 기준으로 돌리면
그 안의 진짜 가게 하나가 **죽은 등록을 전부 살려 준다**(안산선부 500m에서 34건 vs 실제 12건).

### ⚠️⚠️ 실체 판정의 순위 — 이걸 틀리면 전부 틀린다

```
카카오  >  소상공인 상가업소  >  인허가
```

**상가업소도 인허가도 폐업을 못 따라온다.** 사용자가 구리돌다리에서 확인해 줬다 —
자동 목록이 낸 10곳 중 7곳(물라·마카오·또와·대박·툰·교문·뉴스타)은
*"네이버지도에 안 떠, 폐업으로 추측됨"*이고, **카카오에도 하나도 없다.**
사용자가 실제 경쟁점으로 꼽은 4곳(불독·녹스·지원·레드포스)은 **카카오에 전부 있다.**
500m 채점에서도 카카오는 사람이 조사한 실재 273건 중 **270건(99%)**을 맞혔다.

> **나는 이 판단을 오늘 두 번 틀렸다.** 아침에 카카오를 "도시 편향"으로 기각했는데
> 눈대중이었고(재 보니 r=-0.14로 유의선 아래), 상가업소로 갈아탔다가, 사용자 확인으로
> 다시 카카오로 돌아왔다. **자료원은 성적이나 인상으로 고르지 말고 아는 답과 대조해라.**

### 성인PC방·오락실 거르기

상호에 드러난다. 카카오 500m 밖 고유 상호 728개 중 **26개(3.6%)**가 걸린다:
```
/게임랜드|게임장|오락|성인|스크린|멀티방|다트|보드게임|만화|플스|VR|사격|당구|노래/
   지구성인게임랜드 · 메가오락실 · 인형뽑기왕오락실 · 슈팅존스크린사격 · 캠프VR …
```
⚠️ 인허가 짝으로 거르는 방법도 있지만 **최근 개점한 진짜 PC방까지 뺀다**
(레드포스는 2024-11에 상가업소 등재됐는데 인허가엔 아직 없다). 이름 규칙 쪽이 안전하다.
⚠️ 이름 규칙이라 **새 업태가 생기면 갱신**해야 한다.

### ⚠️ 카카오의 약점 하나 — 40건 상한 (아직 안 풀었다)

매장당 40건쯤에서 잘린다(전대후문·전대상대·수원인계·부천상동역 4곳).
**반경을 격자로 쪼개 조회하면 우회된다** — 아직 안 해 봤다. 자동화 도구를 만들면
여기부터 손보는 게 값이 크다.

## 5. ⛔ 안 풀린 것 하나 — 경쟁점 PC 대수

오늘 다 시도하고 다 막혔다. **또 파기 전에 여기를 읽어라.**

| 시도 | 결과 |
|---|---|
| 우리 매장으로 면적→대수 회귀 | **R²=0.064.** 전부 90~110대 규격형이라 대수 방향으로 안 퍼져 있다 |
| 조사 경쟁점 138곳으로 회귀 | 대수=0.2213×면적+41.7 · **R²=0.679**인데 표본이 **61~243대**뿐이라 소형 구간이 외삽이다 |
| 인허가 총게임기수 | 70+ 는 정확한데 **지역 편향 r=−0.486**(서울은 53%가 미등록, 울산은 4%) |
| 면적 문턱으로 대형만 세기 | 우리 500m DB 재현 F=0.66이 최선. 면적 40% 구멍 때문 |

**=> "기전이 없어서"가 아니라 "기전은 있는데 자료가 계수를 못 고른다"이다.**
새 자료(소형 PC방 대수)가 들어오면 열리는 갈래다.

## 6. 권하는 설계

### 6-1. "평가 자동화"가 아니라 "조사 자동화"로 잡아라

```
주소 입력
  → 좌표·인구 자동
  → 경쟁점 후보 목록 자동 생성        ← 2026-09-22에 뚫린 부분
  → 사람은 "찾기"가 아니라 "확인하기"만 (대수·품질 입력)
  → 평가 + AI 평가문
```

사람이 하는 일이 **"주변에 뭐가 있나 찾기" → "이 목록이 맞나 확인하기"**로 바뀐다.
품이 줄고, 무엇보다 **누락이 사라진다.**

그 값이 실제로 크다 — 구리돌다리점 후보지는 우리 경쟁점 DB에 **3곳**만 있는데
상가업소는 같은 500m에 **18곳**을 안다(사용자 판정으로는 4곳: 레드포스·녹스·불독·지원).
**레드포스가 우리 DB에 빠져 있었다.** 자동 목록이 있으면 이런 누락이 안 생긴다.
이건 실험실이 아니라 **결재 숫자를 직접 좋게 만드는 개선**이다.

### 6-2. 두 모드를 분명히 갈라라

| | 초기 모드(주소만) | 정밀 모드(지금 V62) |
|---|---|---|
| 입력 | 주소 + 자사 기획값 | + 경쟁점 현장조사 + 입지평가 |
| MAPE | **13.40%** | 8.83% |
| ±20% | 86.84% | 92.11% |
| 쓰임 | 후보 선별·줄 세우기 | 결재 |

**초기 모드 숫자를 결재에 쓰지 못하게 화면에서 막아라.** 섞이면 오늘의 모든 함정이
결재로 들어간다.

### 6-3. AI 평가문에 넣을 것

숫자만 내면 오해를 부른다. 같이 적어야 할 것:
- 이 추정의 **오차 범위**(±20% 안에 86.8%)
- **무엇을 기본값으로 채웠는지** (경쟁점 대수 90대·품질 동급·가시성 중앙값)
- **경쟁점 목록의 출처와 한계** (상가업소 기준, 성인PC방 제외, 대수는 미확인)
- 확인이 필요한 항목 목록 = 그대로 현장 조사 체크리스트가 된다
