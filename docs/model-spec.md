## 0. 운영 원칙 (00_V62사용안내, 08_계산기준, 12_운영판정)

- **V62가 신규점포의 최종 운영모델**이다. 최종 예상매출은 `13_신규후보지판정`의 K열(V62 최종예상월매출)을 사용한다.
- **V61은 비교·기준값(참고)**이며 `13_신규후보지판정`의 G열이다.
- **70% 레거시 보수예상매출은 신규점포 판단에 사용하지 않는다** (08_계산기준 R28: "레거시 보수예상매출 = V61 예측월매출 × 70%, 기존 시트 호환용, 신규 출점 판단에는 사용하지 않음. 13_신규후보지판정의 V62 및 85~115% 범위를 사용").
- 신규 후보지 평가 순서(00_V62사용안내 표): `07_신규후보지`(기본정보) → `05_경쟁점정보`(경쟁점) → `09_입지동선평가`(입지·외부유입) → `13_신규후보지판정`(자동 결과).
- **현재 모델 상태(12_운영판정 F4 셀, 2026-08-19 기준 스냅샷)**: `조건부 사용`. 전체 검증표본 26곳(<30 기준 미달), 외부유입 '강함' 표본 2곳(<5 기준 미달)이라 "정식 적용 가능" 등급에는 못 미치고, 성능지표(MAE 등)는 통과다. 최종 운영판정 문구(E24): "현재는 내부 검증·의사결정 보조로 사용. 정상점포 4곳 이상 추가 후 재검증." **이 상태값 자체가 시점 스냅샷이므로, 표본이 늘어나면 웹에서도 같은 로직으로 재계산되어야 한다** (하드코딩 금지, §5 참고).
- **학습/검증 대상 브랜드는 블랙라벨만** 사용한다. `09_입지동선평가` P열(브랜드구분)이 `블랙라벨`이 아니면(리그PC방/확인필요/미평가 포함) 검증 표본에서 자동 제외된다.
- **리그PC방은 모델 학습에서 제외**된다 — 09_입지동선평가에 아예 등록하지 않거나, 등록해도 P열이 `리그PC방`이면 XLOOKUP 매칭에서 "블랙라벨"이 아니므로 제외.

## 2. 핵심 발견: 07_신규후보지의 계산열은 "셀 수식"이 아니라 **Apps Script가 값으로 채운다**

`07_신규후보지`의 AV~BZ열(원수요, 상권수요, 상권등급, 상권성격, 경쟁점수, 경쟁IP, 총IP, IP당수요, 상권판정, 자사_경쟁력점수, 경쟁력격차, 예측_대당일매출, 예측_월매출(BW), 보수예상매출(BX), 모형학습표본(BY), 예측신뢰도(BZ), 최종계산일시(BU))은 **셀 수식이 아니라 정적 값**이다(실제로 열어본 N001/N002 행에 수식이 하나도 없음). `12_운영판정` R29행 "3. 동기화 / 메뉴 실행 / 점포평가 관리 → 신규 후보지 분석 실행 / 07 예측_월매출 산출"이 이를 뒷받침한다 — 즉 **이 계산은 스프레드시트 수식이 아니라 `점포평가.gs`(Apps Script)가 메뉴 실행 시 계산해서 07 시트에 값을 기록하는 구조**다.

**따라서 07 시트의 AV~BZ열을 만드는 정확한 코드는 `점포평가.gs`/`repair.gs` 원본 없이는 100% 재현할 수 없다.** 대신 `08_계산기준`(프로즈 명세)과 `04_점포평가요약`(기존 41개 점포에 대한 계산 스냅샷 사례)을 근거로 각 단계의 산식을 아래 §3에 최대한 복원했다. 이 복원본과 실제 스크립트가 다를 수 있는 지점은 `docs/data-issues.md`의 "핵심 미해결 항목"에 모두 남겼다.

**다행히 `13_신규후보지판정`은 이 07 계산 결과가 비어 있어도 최종 판정까지 이어지도록 만든 안전장치(폴백 회귀식, §4의 G열)를 자체 셀 수식으로 가지고 있어, 07 계산열이 없어도 V61/V62/최종판정까지는 100% 셀 수식으로 재현 가능**하다. 이것이 이번 웹 구현의 1차 목표가 되어야 한다(§6 권장사항 참고).

### 4.1 13_신규후보지판정 G열 폴백 공식 (07 시트 BW열이 비어 있을 때만 사용)

```

선형값 = V61후보_절편
       + V61후보_요금계수 × 시간당요금
       + V61후보_수요PC계수 × 자사수요_per_PC
       + V61후보_자사점수계수 × 자사_경쟁력점수(BM)
V61(폴백) = 예상PC대수 × MAX(0, 선형값)     // 반올림(ROUND, 0자리)
```

- 입력 중 하나(예상PC대수 E, 시간당요금 F, 상권수요 N, 경쟁력격차 S, 자사_경쟁력점수 BM)라도 비어 있으면 G열은 공백("")이 된다.

## 10. 기존 가맹점 검증 관련 시트 요약

- **01_점포기본정보**: 가맹상태(E), 오픈일(G), PC대수(C), CO(산식학습제외 플래그) / CP(학습제외사유) — **개별 점포를 학습에서 강제 제외하는 수동 스위치**. 브랜드(블랙라벨/리그) 컬럼은 이 시트에 없음 — 브랜드 판정은 09_입지동선평가 P열이 유일한 소스.
- **02_월별성과DB**: 점포×월별 실적(가동률, 월매출, PC/상품매출, F열 평가대상여부 Y/N, O열 데이터상태(반영 등)) — 6~12개월 안정화 구간 판정(08_계산기준 R2/R3)의 원천.
- **04_점포평가요약**: 기존 41개 점포 각각에 대해 §3 전체 계산 파이프라인을 미리 계산해 둔 표. G열(평가진행상태: "12개월 완료" 등) H열(평가등급 A~E, 가동률 구간) AX열(검증사용여부) AY열(검증제외사유) AZ열(절대오차_월매출pct) BA열(보수예상매출=V61×0.7).
- **06_검증대시보드**: A(검증사용여부) B(검증제외사유, 자유서술 — 실제 사례: "12개월 미완료", "수동 학습제외(오픈 후 경쟁점 500원 가격전쟁)", "실측가동률 없음", "수동 학습제외(오픈 후 운영관리 문제)") + P/Q열에 요약지표(유효표본수, 평균/중앙 절대오차, 최대 과대예측, 보수값 과대예측 비율 등).
- **10_오차원인분석**: 오차 큰 점포에 대한 사람 작성 정성 분석(원인분류/상세판단/추가확인자료) — 계산 로직 아님, "왜 이 점포는 오차가 크게 났는지"에 대한 운영 지식 기록. R30~R34에 요약 카운트 수식(COUNTA/AVERAGE/COUNTIF)만 존재.
- **11_보정안검증**: 과거에 시도했던 보정계수 후보(특수수요 가산, 상권흡인력 가산 등)의 시뮬레이션 결과와 "탈락" 판정 로그 — **현재 미채택**. 참고용 히스토리로만 취급.

## 11. 검증 지표 정의 요약 (화면 6. 기존 가맹점 검증에 필요)

- **오차율(개별)** = `(V62예측 − 실제매출) / 실제매출` (12_운영판정 I열)
- **절대오차율** = `ABS(오차율)` (H열)
- **평균절대오차 / 중앙절대오차** = 사용표본(N="사용")에 대한 AVERAGE/MEDIAN of 절대오차율
- **±10%/±20% 이내 비율** = COUNTIF/COUNTIFS 절대오차율 조건 ÷ 표본수
- **과대·과소예측** = 편향(I열) 부호로 구분 (양수=과대, 음수=과소); 점포판정(J열)로 "양호/주의/재검토" 3단계
- **표본 수** = `COUNTIF(N열,"사용")`
- **검증 제외 점포와 사유** = 06_검증대시보드 A/B열 (사유는 자유서술 텍스트)
- **리그PC방 제외** = 09_입지동선평가 P열이 "블랙라벨"이 아니면 자동 제외 (12_운영판정 N열 = `IF(M="블랙라벨","사용","제외")`)

## 12. 최종판정 규칙 매핑 (요청서 vs 원본 시트)

| 요청서 표현 | 원본 시트 실제 문자열(13_신규후보지판정 T/U열) | 근거 |
|---|---|---|
| 입력 필요 | "07 분석 필요" (G열이 비어 07 계산 자체가 안 됨) | T열 1단계 |
| 입지평가 필요 | "09 입지평가 필요" | T열 2단계 |
| (요청서에 없음, 원본에만 존재) | "외부유입 확인 필요" | T열 3단계 — I열(외부유입제한)이 비어있을 때 |
| 브랜드 확인 필요 | "브랜드 확인 필요" | T열 4단계 |
| 계산 확인 필요 | "V62 계산 확인 필요" | U열, T="완료"인데 K(V62)가 빈 경우 |

## 13. 설정 테이블화가 필요한 값 (하드코딩 금지 대상)

12_운영판정 O/P열 전체(§4) + 예상하한/상한계수(0.85/1.15) + 검증 통과기준(30/5/0.15/0.1/0.75/0.05) + V61 폴백 회귀계수 4개 + 모델버전 문자열. 이 값들은 운영설정 화면(§7 화면 요구사항)에서 관리자만 변경 가능해야 하고, 변경 이력을 남겨야 한다.
