# 데이터/산식 불명확 항목 (점포평가 원본 분석)

> `reference/점포평가_V62_원본.xlsx` 전수 분석 중 발견된, 임의로 추측해서 채우지 않고 남겨둔 항목들이다. 각 항목에 확인한 시트/셀 근거를 남긴다.

## 핵심 미해결 항목 (구현 착수 전 반드시 확인 필요)

### 1. `점포평가.gs` / `repair.gs` 원본 코드 미확보 — 가장 중요한 gap
- **근거**: `07_신규후보지` AV~BZ열(원수요/상권수요/경쟁점수/자사_경쟁력점수/예측_월매출 BW 등)을 실제로 열어보면 **셀 수식이 하나도 없고 정적 값만 들어있다**. `12_운영판정` R29행("3. 동기화 / 메뉴 실행 / 점포평가 관리 → 신규 후보지 분석 실행 / 07 예측_월매출 산출")도 이 계산이 Apps Script 메뉴 실행으로 이뤄짐을 뒷받침.
- **영향**: `08_계산기준`(프로즈 명세)만으로는 아래가 재현 불가:
  - "대당월매출 비음수 릿지회귀 60% + 중앙값 40%"의 정확한 회귀 구현(피처 스케일링 방식, λ=1의 정확한 적용식, 학습에 쓰인 26개 표본의 정확한 목록/가중치)
  - "V61 최종월매출 → 대당일매출 → 학습표본의 매출-가동률 관계로 환산"이라는 예측가동률 역산식의 정확한 회귀/보간 방법
  - 유동/주거 원수요 계산 시 "40개 상권 평균 연령구성"(연령 실측이 부족할 때 대체하는 값) 자체의 수치
  - "scoreFromAccess_" 함수(입지 점수: 층수+엘리베이터+지상/지하 → 1~5점)의 정확한 매핑 규칙
  - 상권 실측수요/경쟁점 가동률 보완 로직의 정확한 커버율 계산 방식
- **웹 구현 대안(1차)**: `13_신규후보지판정` G열에 이미 들어있는 **폴백 회귀식**(model-spec.md §4.1, 26개 검증표본의 V61 출력을 4개 계수로 근사한 선형식)은 100% 셀 수식으로 확보되어 있으므로, 이를 1차 구현의 V61 계산 엔진으로 채택하는 것을 권장한다. 다만 이는 "진짜 V61"의 **근사치**이며, Apps Script 원본과는 잔차가 있을 수 있다는 점을 화면에 명시해야 한다.
- **확인 요청**: 사용자에게 `점포평가.gs`/`repair.gs` 파일 원본(Apps Script 편집기 → 파일 다운로드 또는 코드 복사)을 요청 완료. 확보되는 즉시 §3.5/§4.1 산식을 정확한 코드로 교체해야 한다.

### 2. 09_입지동선평가 D/E/F/G/J열(1~5점) 판단 기준 텍스트가 시트 어디에도 없음
- **근거**: 헤더 셀(D1~G1, J1) note/comment를 exceljs로 확인했으나 실제 텍스트 없음(빈 anchor만 존재). `08_계산기준`에도 이 4개 개별 점수의 1~5점 기준은 없고, 종합점수 가중치(30/30/25/15%)만 있음. I열(지도판단메모)은 점수 산정 "근거"를 자유서술로 남기는 용도일 뿐 고정 기준표가 아님.
- **영향**: 요청서 "각 점수의 1~5점 판단 기준을 입력 화면에서 바로 볼 수 있게 구성"을 만족할 고정 텍스트가 원본에 없다.
- **확인 필요**: 사용자에게 별도 기준표(사내 매뉴얼 등)가 있는지 확인. 없다면 웹 구현에서 "판단 기준"란은 원본에 없는 신규 콘텐츠이므로, 실제 기재 사례(I열 27건 코멘트, model-spec.md §7.1)를 참고자료로만 노출하고 "공식 1~5점 기준"이라고 표기하지 않아야 한다.

### 3. 05_경쟁점정보 "경쟁점 데이터 없음" vs "노후·저경쟁력으로 미조사" 구분 필드 없음
- **근거**: C열(조사수준) 데이터 검증 목록은 `상세,간략,외관만` 3개뿐(전체 4464개 데이터검증 셀 중 C열 스캔 결과 확인). "미조사"류 옵션 없음. 05시트 전체(163행 실데이터)에서 "미조사/저경쟁력/노후" 키워드는 AA/AC(평가근거) 자유서술에 2건("노후") 등장할 뿐, 상태값으로 쓰인 사례 없음.
- **영향**: 요청서의 "경쟁점 데이터가 없는 경우와 노후·저경쟁력으로 미조사한 경우를 구분" 요구를 원본 그대로는 구현할 수 없음.
- **확인 필요**: 이 구분이 07_신규후보지 BD열("상권판정": 실사례 값 "유동 미입력", "보통") 쪽에서 상권 단위로 처리되는 것인지, 아니면 신규로 필드를 추가해야 하는지 사용자 확인 필요. 신규 필드 추가는 산식 변경이 아니라 워크플로우 상태값 추가이므로, 사용자 승인 하에 웹에서만 새로 도입하는 방향을 제안.

### 4. 03_회원정보입력 시트가 실제 계산에 참조되는지 불명확
- **근거**: 연령별 회원수 입력 시트이나, 07/08/12/13/04 어느 시트의 수식에서도 `03_회원정보입력`을 참조하는 셀을 발견하지 못함(전 수식 텍스트 검색 기준).
- **영향**: 회원 데이터가 실제 V61/V62 계산에 쓰이는지, 아니면 별도 참고/리포팅용인지 불명확.
- **확인 필요**: 사용자에게 이 시트의 실제 용도 확인. 결과가 나올 때까지 웹 구현에서는 "참고 데이터"로만 취급(계산에 연결하지 않음).

### 5. 유동/주거 원수요 계산의 "40개 상권 평균 연령구성" 수치 미확보
- **근거**: 08_계산기준 R4 "연령별 합계가 유동인구의 80% 이상이면 실측 연령구성, 아니면 40개 상권 평균 연령구성을 사용" — 이 "40개 상권 평균"이라는 참조 테이블/수치가 어느 시트에도 없음(07/01 어디에도 별도 "평균 연령구성" 행 없음).
- **확인 필요**: `점포평가.gs` 확보 시 함께 확인. 그 전까지는 실측 연령구성 미달 후보지는 "계산 불가/추가 확인 필요"로 처리(값을 임의로 지어내지 않음).

### 6. 12_운영판정 D21행(입지평가 누락) 수식 결과가 `undefined`로 표시됨
- **근거**: `COUNTIFS($A$36:$A200,"<>",$E$36:$E200,"미평가",$N$36:$N200,"사용")` — exceljs가 캐시된 결과값을 못 읽어 `undefined`로 나왔으나, 화면상 D21 판정은 "통과"로 캐시되어 있어 값 자체는 0으로 추정됨. 재계산 시 다른 값이 나올 수 있으니 웹에서는 이 COUNTIFS를 실제로 재계산해서 사용해야 하며, 캐시값을 신뢰하지 말 것.

## 참고용 — 확인은 됐으나 시점에 따라 바뀌는 값 (하드코딩 금지)

- 12_운영판정 F4(검증상태)="조건부 사용", E24(운영판정 문구), 전체표본 26/외부유입강함표본 2 등은 **2026-08-19 스냅샷**이다. 표본이 늘어나면 자동으로 바뀌어야 하므로 웹 구현에서 이 문자열들을 상수로 박아넣으면 안 되고, §model-spec.md §5의 판정 로직을 그대로 함수화해야 한다.
- 08_계산기준에 있는 "표본 2곳/3곳/4곳" 같은 계수 근거 문구도 향후 표본이 늘어나면 갱신될 수 있는 스냅샷 텍스트다. 계수값(0.53/0.61/0.78 등) 자체는 설정 테이블에 넣되, 근거 텍스트는 별도 메타데이터로 취급.

### 7. (구현 결정) 사양/좌석/입지 점수는 자동계산 대신 1~5점 직접 입력으로 통일
- **근거**: 08_계산기준에 "사양=VGA70%+모니터30%+가산", "좌석=존다양성50%+독립룸수용력50%", "입지=층수+엘리베이터+지상/지하(scoreFromAccess_)"라고만 적혀 있고, VGA 모델명/존 개수/층수 조합을 실제 1~5점 숫자로 바꾸는 변환표는 `점포평가.gs` 안에만 있어 확보하지 못했다(§핵심 미해결 항목 1과 동일 원인).
- **결정**: 새로운 변환표를 지어내는 대신, 원본에서도 사람이 직접 매기는 먹거리/인테리어평가와 동일하게 **사양·좌석·입지 점수도 평가자가 1~5점을 직접 입력**하도록 `src/lib/storeEval/types.ts`(CandidateInput.ownSpecScore/ownSeatScore/ownLocationScore, Competitor.specScore/seatScore/locationScore)를 설계했다. 종합 경쟁력점수의 가중합 공식(사양25%+좌석30%+먹거리20%+인테리어15%+입지10%)은 08_계산기준 그대로 적용한다(`calc.ts`의 `computeCompetitivenessScore`).
- **영향**: 존 개수(팀룸/커플존/VIP존 등)와 자사_존종류수/독립룸수는 여전히 입력값에서 순수 집계로 파생한다(`computeOwnZoneTypeCount`/`computeOwnPrivateRoomCount`) — 이 부분은 08_계산기준 수치(팀룸2/커플존3/VIP존5)와 정확히 일치하므로 그대로 유지.
- **확인 요청**: `점포평가.gs` 확보 시 VGA→사양점수, 존구성→좌석점수, 층수·엘리베이터→입지점수 변환표를 찾아 자동계산으로 교체할 것.

## 경미한 항목 (구현에 영향 적음, 기록만)

- `temp`, `매출DB의 사본_최지은`, `멀티매출계산`, `피카매출계산` 시트는 백업/개인 작업용 또는 특정 브랜드 전용 수동 계산기로 보이며, 이번 V61/V62 모델과 무관하다고 판단해 깊게 분석하지 않음.
- `99_동기화로그`는 Apps Script 실행 이력(실행일시/기능/결과/처리건수/메시지)일 뿐 계산 로직이 아님.
- `01_점포기본정보`, `04_점포평가요약` 등 대형 시트는 1000행 중 실제 데이터가 41행 내외뿐이라, 전 행을 순회하지 않고 데이터가 있는 행까지만 확인함(추가 행이 있다면 같은 헤더 구조를 그대로 따른다고 가정).
