> `reference/점포평가_V62_원본.xlsx` 전수 분석 중 발견된, 임의로 추측해서 채우지 않고 남겨둔 항목들이다. 각 항목에 확인한 시트/셀 근거를 남긴다.

## 2026-08-21 갱신 — "실측기반 예상월매출" 백테스트 구현 + 결론: 지금은 검증 자체가 불가능(핑봇 데이터 없음)

- **구현**: `computeExistingStoreMeasuredForecast`(calc.ts)를 새로 만들어 evaluate.ts가 후보지에
  대해 하는 계산(자사 점수→경쟁력격차→경쟁점 실가동좌석→수요확보율 룩업→예상가동좌석→실측기반
  예상월매출)을 기존 가맹점에 그대로 적용하고, `validation/page.tsx`에 "5. 실측기반 예상월매출
  검증" 섹션을 추가해 정식검증(26곳) 중 조건을 만족하는 매장만 골라 MAE/중앙값/±5/10/20%를
  보여준다(V61/V62 전용 목표치는 적용하지 않고 수치만 표시).
- **실데이터로 돌려본 결과 — 표본 0곳**: 존구성/VGA는 정식검증 26곳 전부 실측값이 있었지만
  (물리적 시설 사실은 이미 잘 채워져 있음), 이 경로가 필요로 하는 **"핑봇 기간평균 가동률"
  데이터가 전체 경쟁점 레코드 160건 중 딱 1건(N003 호구포역점의 경쟁점 "워너비PC")뿐**이었다.
  나머지는 5건이 방문 시점 실시간값(2026-08-21에 이미 "평균으로 못 씀" 처리한 그 케이스), 154건
  (96%)은 아예 가동률 데이터 자체가 없었다.
- **먹거리/인테리어/모니터평가(1~5점, 평가자 직접입력)도 26곳 전부 비어 있었다** — 원본 시트의
  "공백이면 표준값 4" 규칙(후보지와 동일)을 적용해 표본에서 빼지 않도록 고쳤다(처음엔 "기존
  가맹점은 실제값을 알아야 정상"이라는 판단으로 표준값 폴백을 안 썼었는데, 이 3개는 물리적 시설이
  아니라 주관적 평가 항목이라 원본 규칙을 그대로 따르는 게 맞다고 재판단함).
- **결론**: 코드/계산 자체는 이제 정확하고 테스트로 검증됐지만, **"핑봇으로 경쟁점 가동률을
  실측한다"는 이 경로의 전제 데이터가 실질적으로 수집되고 있지 않아서 지금은 백테스트를 돌릴
  표본이 없다.** 이건 코드 문제가 아니라 현장 데이터 수집 관행의 문제다. 앞으로 핑봇 조사를
  늘릴지, 이 경로 자체를 (데이터가 없으니) 포기할지는 사용자 결정이 필요하다 — 결정 전까지는
  화면에 "미검증 참고 지표"로 계속 격하 표시해둔다(2026-08-21 이전 결정 유지).

## 2026-08-22 갱신 — 동기화 스크립트를 diff 기반 부분쓰기로 전환(Firestore 쓰기 할당량 초과 재발 방지)

  비교하고, **실제로 달라진 문서만** write하도록 바꿨다. 부수적으로
  `storeEvalCompetitors`가 안 바뀐 문서도 매번 `createdAt`을 "지금"으로 리셋하던 버그도 같이
  고쳤다(기존 createdAt을 보존).
- **실측 확인(2026-08-22)**: 두 스크립트를 실제로 재실행해본 결과 전부 `0건 write`(매출

  건너뜀")로 끝났다 — 값이 안 바뀐 재실행은 이제 쓰기가 거의 0에 가깝다. 이 재실행으로 그동안
  막혀 있던 문산점 오픈일 수정 반영(완료월/평균매출 재계산)도 같이 마무리됐다(재계산 결과가

- **참고**: 이번 발견 — `20260529432` 매장이 오픈일 없어 completedMonths 재계산이 안 되고 있음

   빠져있었음=0). 정밀값으로 교정. 유동/거주 원수요 계산 전체에 쓰이는 기초 계수라 모든 후보지
