## B. 경쟁점 가동률로 수요 산식 조정 (10-14 이후)

- **표본 구성 변화에 주의**: 매장이 날마다 추가된다(C 세션이 계속 등록) → 그냥 평균하면 새 매장이 들어온 날 지수가 튄다. 이틀 연속 잰 매장만으로 전날 대비 변화율을 구해 잇는 **연쇄 지수**(또는 고정 표본)로. 우리 매장(`isOwnStore`)·IP 확인 필요·측정 불가 의심은 뺀다.
- 하루 단위는 summary.ts의 일일 기준(10-08부터 24시간)을 그대로. 평일/주말 구분 표시.
- 목록 화면이 이미 모든 매장의 `days`를 읽으니 **추가 읽기 없이** 화면에서 계산. 위치는 `/ping-monitor` 위쪽 카드 + 작은 선 그래프. 설명 문구에 "언제부터 몇 곳으로 잰 지수인지"를 값에서 읽어 쓴다.
- ⚠️ `src/app/ping-monitor/*`·`summary.ts`는 C 세션이 고치는 중일 수 있다 — 시작 전 `git pull`, 작업 중 `git status`로 남의 변경을 섞지 말 것(파일 단위로 `git add`).
- (같은 날 추가) 사용자 "신규후보지 등록할 때 가동률 웹에 경쟁점 추가" — 후보지 경쟁점을 **저장하면** 측정기에 "IP 미등록" 빈칸으로 자동으로 올라간다(`registerCompetitorsToPing`, 모양은 `scripts/pingMonitor/addNoIpCompetitors.mjs`와 같음, 올리기 직전 competitorId로 다시 찾아 중복 방지, "경쟁점 없음" 문서 제외). 이미 있던 경쟁점은 카드 "측정기에 등록"·위쪽 "n곳 측정기에 등록" 버튼. 경쟁점을 지워도 측정기 문서는 남는다(규칙상 삭제 불가 — 측정기 화면에서 "중지").
- (같은 날 추가 2) 경쟁점 설명 붙여넣기 자동완성 — 인테리어 수준·매장 관리 상태 → 인테리어/관리 점수(하 2.0·중하 2.5·중 3.0·중상 3.5·상 4.0(처음 4.5로 넣었다가 사용자 지적으로 기준표와 함께 4.0), 화면 기준표와 같은 값), 먹거리(사용자: 수준 글자면 그 점수, "파악안됨"이면 중 3.0, 브랜드면 그 브랜드·목록 밖은 기타브랜드), 매장명 밑 IP 대역 → 경쟁점 저장 때 측정기로(새로 올리거나 빈칸 채움, 다른 IP가 이미 있으면 안 덮음). 붙여넣기 IP는 `ipCheck`="붙여넣기 IP — 지금 확인 전"으로 측정기 "IP 확인 필요"에 뜬다. 카드에 "IP 넣기"(측정기 등록 칸 StoreForm 재사용). 암사 TEST 경쟁점("tset")은 사용자 요청으로 경쟁점·측정기 문서 둘 다 지움.
- (같은 날 추가 3, 사용자 "측정기 칸 말고 경쟁점 정보란에, 등록 전 한번 체크") — 경쟁점에 `ipRanges`(선택 필드) 추가. 붙여넣기 IP는 폼의 "IP 대역(가동률 측정기용)" 칸으로, 옆 "지금 확인"(/api/ping-monitor/probe, 기록 없음)으로 대답 확인 → 저장하면 측정기 칸으로. 확인에서 한 대라도 대답했으면 `ipCheck` 없이, 아니면 "경쟁점 정보 IP — 지금 확인 전"으로 측정기 "IP 확인 필요"에. 카드 "IP 넣기"도 경쟁점 IP로 채워 연다. 후보지 화면에서만 보임.
