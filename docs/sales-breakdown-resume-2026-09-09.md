# 상세매출 작업 재개 기록

작업 폴더는 `.local-tools/accuracy-release`이며 루트의 `weekend-work`와 구분한다. 사용자는 매출DB를 원본으로 블랙라벨 PC·상품 상세를 웹에서 조회하고 싶다고 요청했고, 회의 중 자율 진행을 맡겼다.

이번 변경은 `306ba2c`로 별도 커밋하고 `origin/main`에 push했다. 기존 미커밋 테스트·검토 문서는 포함하지 않았다.

## 구현 및 확인

- 가맹점 목록 상세매출 링크 → 가맹점 상세의 `?tab=sales` 탭.
- 월별 PC·상품·총매출, 상품/(PC+상품) 비중. 연도 선택, 완료된 월의 기간 평균 및 합산 비중.
- 목록 관리 패널에도 같은 컴포넌트 적용.
- 후보지 결과에 상품 비중 표시 추가. 모형 계산과 운영 데이터는 변경하지 않음.
- 일반 테스트 458개, TypeScript, 변경 ESLint와 diff 검사 통과. 최초 화면 변경은 로컬 프로덕션 빌드 성공. 후보지 비중 문구 추가 후 TypeScript·ESLint 통과, 최종 빌드는 Vercel에서 수행.
- 로컬 브라우저에서 안산선부점 연도 필터·매출DB 금액 대조, 광주첨단점 목록 검색·관리 패널 상세 표시 확인.

## 원본 및 판단

Google Drive 커넥터로 매출DB를 직접 읽었다. 지점명 노란색 기준 블랙라벨 41곳 중 2026년 8월 금액을 확인할 수 있는 39곳의 점포별 상품 비중 평균 52.185%, 최소 40.405%, 최대 62.081%다. 사용자 수치와 일치한다.

일부 과거 헤더는 PC대비 비율, 최근 헤더는 매출대비 비율이며 일부 저장 비율은 금액 역산과 차이가 있다. UI는 금액으로 직접 산출하고 시트는 읽기만 수행했다. 상세 원본은 ignored `.local-tools/black-label-sales-source-20260909.json`에 보관했다.

현재 운영 브라우저에 이미 열려 있던 호구포역점 상품 비중은 51.7%다. 보관된 9월 8일 기존점 검증 38곳의 예측 비중은 평균 52.4%, 범위 46.7~61.3%다. 시기·표본이 다르므로 평균 일치를 정확도 입증으로 쓰지 않는다. 상품이 PC보다 높다는 이유로 모형을 조정하지 않았다.
