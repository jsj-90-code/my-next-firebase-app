## 2. ⭐ 오늘 세운 원칙 — 서술과 영향력은 다른 것이다

하루 동안 CPU를 세 번 재고 두 번 뒤집었다. 헷갈린 이유는 내가 두 가지를 섞어서였고,
사용자가 그 둘을 갈라줬다.

> *"아니 영향력은 잘모르겠다지만 CPU사양별 차이는 있잖아."*
> *"제품스펙을 고객이몰라도 이용했을때 프레임이나 버벅임 이런것들은 느낄수도있잖아."*

| | 담당 |
|---|---|
| **영향력** — 매출에 얼마나 미치나 | **비중** |
| **사양 차이** — 하드웨어가 실제로 다른가 | **변환표** |

**대조군은 "영향력"을 재는 도구다.** 비중이 작은 항목이 못 넘는 건 당연하다. 서술을 고치는 건
대조군이 판정할 대상이 아니다. 단 **성적이 크게 나빠지면 멈춘다**는 안전선은 둔다.

`i3 13100F = i5 13400F`는 영향력이 작아서 같은 게 아니라 **그냥 틀린 서술**이었다.

## 3. 사용자가 방향을 일곱 번 잡았다

1. *"GPU 3080 5점 너무과하다"* → 원인이 기울기가 아니라 **앵커 4점과 상한 5점 사이가 1점뿐**인
   것이었다. 사용자가 물은 "간격 늘리기"는 반대 효과(더 세게 박힌다).
2. *"성능외에 세대별 차등도 적용이 되는구조가 좋을것같은데"* → 세대 벌점 신설. GPU·CPU 둘 다.
3. *"i3라고 요금이낮은건아닌데? 요금은 상권에 맞추는형태임"* → 내 인과가 거꾸로였다.
4. *"16기가 32기가차이로는 일부 게임중에 버벅이는게임이있다(아이온2)"* → RAM은
   "차이 없음"이 아니라 **"자료가 못 봄"**이다(평가창 66%가 아이온2 이전).
5. *"WQHD랑 QHD랑 같은건데, WWQHD (울트라와이드) 이게 차이있는건데"* → 집계 정규식이 틀렸다.
6. *"두개사실 비슷함"* (FHD 240Hz ↔ QHD 165Hz) → **등가점 앵커.** QHD 가산을 0.7336으로 역산.
7. *"듀얼모니터... 존형태에서 가점을 안받는걸로알고있어서"* → 확인해보니 **존구성이 이미 센다**
   (`1인석 = 칸막이·듀얼모니터만 있는 개방형 좌석`).

## 4. 내가 네 번 틀렸다

1. **"MAPE로 판정"** — 아침에 CPU를 MAPE 악화로 기각했다. 이 모델의 축척은 독점매장에서만
   맞추므로 경쟁점 점수 수준 이동이 MAPE에 그대로 찍힌다. 판정은 r이 한다.
   ([[feedback_lab_mape_follows_level]] 메모리에 남겼다)
2. **"i3라서 요금이 낮다"** — 인과가 거꾸로. i3는 2023년 코호트다.
3. **"CPU 차이는 잘 모르겠다 = 서술도 대충"** — 영향력과 서술을 섞었다(2절).
4. **비중 대조군을 순환으로 썼다** — 훑기를 보고 고른 값이 무작위 중 최상위인 건 당연하다.
   p=0.003이 나왔지만 근거가 못 된다.

그리고 셸 사고를 세 번 냈다 — `node -e "..."` 안의 백틱을 셸이 명령으로 먹어 빈 파일 3개가
생기고 릴리스 문서가 한 번 깨졌다. **Edit/Write 도구만 쓸 것.**

## 5. ⭐ 후보지 준비 상태 (다음 세션 본론)

### 막힌 곳은 코드 한 군데다

`buildLabRows`(labInput.ts)가 `ExistingStore[]`만 받고, 실험실 화면도 `listLabExistingStores()`만
읽는다. **후보지 경로가 아예 없다.**

### 자료는 갖춰져 있다 (후보지 11곳)

```
✅ 11/11   요금 · 주거1km · 유동 400m/300m/1km · 층·엘리베이터 · 연령별 주거
           자사 GPU · 자사 CPU · 자사 모니터 · 경쟁점 조사
⚠️  3/11   자사 팀룸 (나머지는 블랙라벨 표준 구성으로 채워지는 게 정상)
❌  0/11   PC수  <- 필드명이 다르다. CandidateInput에서 확인할 것(pcCount가 아닐 것)
```

### 후보지에 원래 없는 둘은 문제가 안 된다

- **실측 가동률** — 예측 대상이다. 축척을 기존점으로 이미 맞춰 뒀으니 불필요하다.
- **QSC** — 신규점은 점검 기록이 없다. `labInput`의 **가맹점 평균 경로**가 그대로 쓰인다
  (`franchiseAverageManagement`).

### 만들 때 반영할 것 (어제까지 추가된 항목)

| 항목 | 후보지에서 |
|---|---|
| QSC → 관리 점수 | 가맹점 평균 |
| 존구성 (룸 기준) | 조사 자료 있음 · 자사는 `STANDARD_OWN_FACILITY_DEFAULTS` |
| 사양 GPU·CPU·모니터 | 조사 자료 있음 · 자사는 발주 계획 |
| 하드웨어 비중 50/15/20/15 | `LAB_SPEC_WEIGHTS` — 운영 설정을 안 읽는다 |
| 입지 중심도 ν=0.25 · 접근성 κ=0.25 | 유동 300m/1km · 층·엘리베이터 다 있음 |

### ⚠️ 사용자가 후보지를 등록하는 중이다

입력 주의사항으로 셋을 알려드렸다.
1. **모니터는 `(32인치·FHD·240Hz)` 형식으로** 인치·해상도·Hz를 다 적어야 점수가 나온다.
   Hz가 없으면 null이 된다(기존 경쟁점 73건이 그 상태).
2. **팀룸은 총좌석수를 직접 적어야** 한다. 안 적으면 `개수 × 5`로 환산되는데 실제는 룸당
   3~4석이라 40% 과대다(기존 후보지 19건이 그 상태).
3. **GPU 칸에 CPU가 들어가지 않게** (`i7 12700KF`가 GPU 칸에 있어 운영이 5.00점을 준 사례 1건).
