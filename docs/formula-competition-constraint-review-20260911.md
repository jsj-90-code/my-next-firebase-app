# 기존 특징을 유지한 경쟁 방향 제약 검토

2026-09-11 · 결과 확인 전 설계 기록.

고정 코드 1477c23과 2026-09-09 보존자료의 정식 38곳을 사용한다. 기존 특징·하한·ridge·월수 가중 k=2.46을 유지하고, 각 학습의 기존 적합 결과에서 수요·격차 표준화 계수 두 개만 가장 가까운 제약 만족점으로 투영한다. 이는 제약 ridge를 처음부터 최적화한 결과가 아니라 최소 계수 변경 대안이다. 교차보정의 내부 학습에도 같은 투영을 적용한다.

제약은 해당 학습에 포함된 점포에서만 만든다. 경쟁점 점수 고정 시 좌석의 국소 미분, +1대·+60대의 유한 변화, 전체 경쟁점 제거의 방향을 사용한다. 평가점포의 입력으로 제약을 만들지 않는다. 기존 수요·격차 계수 하한을 모두 유지한다. 나머지 계수와 학습 절편은 유지하고 기존 내부 교차보정을 다시 계산한다.

결과에 따라 제약 강도나 지수를 탐색하지 않는다. 기존 대비 LOOCV 총매출 MAPE, ±10%·±20%, 최악 오차를 비교한다. 각 외부 평가점포에서도 해당 외부 학습모형을 고정해 방향을 확인한다. 훈련 지점 제약 만족이 미관측 입력 전체의 단조성을 보장하지는 않는다. 초과수요는 0, 기존 이용시간 상한은 유지한다. 신규점 독립 검증이나 운영 변경은 포함하지 않는다.

## 제약과 구현 범위

원단위 수요·격차 계수를 bD, bG라고 두면 경쟁점 j의 좌석 수에 대한 로그예측 미분은 하한 비작동 구간에서 다음과 같다.

```
-bD/(N+C) + bG*Qown*(1/C-q_j/S)
S = Σ(n_j*q_j)
```

각 학습점의 미분과 유한 변화에서 `a*bD+b*bG<=0`을 만든다. a는 비양수이며 b가 양수인 조건만 계수 비율을 제한한다. 표준화 좌표로 환산해 가장 엄격한 조건 `betaG<=k*betaD`로 모은다. 기존 두 계수 하한을 함께 만족하는 영역에서 기존 계수와의 유클리드 거리가 최소인 점을 구한다. 이는 원단위 계수의 최소 거리도, 예측 오차의 최소화도 아니다. 표준화 좌표는 각 훈련집합에서만 계산한다.

학습행은 기존 특징 벡터로 보존자료의 점포에 연결하고, 중복 벡터가 없음을 검사했다. 각 호출에 실제로 전달된 학습행에서만 제약을 생성했다. 외부 평가점포는 내부 교차보정에도 들어가지 않는다. 기존 k=2.46 및 설정을 고정한 탐색 비교라는 한계는 남는다.

## 기존 격차 정의의 경계 문제

경쟁점이 하나이고 그 점수가 q라면 양수 경쟁좌석 C에서 `gap=Qown/q`다. 경쟁점이 없으면 기존 산식은 gap을 1로 둔다. 연속적인 좌석 가중치를 가정해 C가 0으로 접근해도 양수 쪽의 격차 항은 `Qown*log(Qown/q)`로 남고, C=0에서 갑자기 0이 된다. 약한 경쟁점(q<Qown)이면 양수 bG 때문에 이 항이 매출을 높인다.

로그 수요의 하한이 작동하지 않는 구간에서, C가 0에 가까워질수록 수요 항의 차이는 0으로 가지만 격차 항 차이는 남는다. 따라서 이 연속 입력 범위에서 양수 격차 계수와 현재 무경쟁 기본값을 모두 유지한 채 계수 조정만으로 전역 단조성을 보장할 수 없다. 실제 정수 좌석 범위의 모든 경우가 불가능하다는 증명은 아니며, 거리 가중으로 유효 좌석이 작아지는 설계에서는 특히 확인할 경계다.

이는 무경쟁 기본값을 임의 평균으로 교체하라는 결론이 아니다. 관측 범위를 정한 제약과 경쟁공급이 0으로 줄 때 격차 효과도 연속적으로 줄어드는 특징 설계는 서로 다른 대안이다. 후자는 별도 구조 변경이며 앞서 단순 통합안의 정확도가 악화한 사실을 함께 고려해야 한다.

## 결론과 인계

**이번 최소 계수 변경안은 채택하지 않는다.** 기존 특징을 유지했지만 정확도가 나빠졌고, 평가점포 전체 제거 시나리오의 방향 문제도 완전히 해결하지 못했다. 앞선 격차 제거·공급 통합안과 이번 제약안, 총 세 후보의 검증을 마쳤으며 운영 변경은 없다.

이번 결과로 모든 제약 최적화가 실패한다고 일반화할 수는 없다. 제약을 포함한 재최적화나 경계에서 연속인 새로운 특징은 별도 설계다. 다만 지금까지 검증한 안에서 정확도와 방향을 함께 개선한 후보는 없으므로 해결 완료로 표시하지 않는다. 운영 적용보다 이 결과를 Claude의 설계 검토 자료로 남긴다. 문서 작성은 완료했으며 Claude 수신·검토 완료는 확인하지 않았다.
