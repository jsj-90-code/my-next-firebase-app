## 1순위: 수요 압력에서 규모 효과를 분리

현재 `log(D/(N+C))`는 수요 D와 총 공급 N+C의 로그계수를 크기가 같고 부호만 반대이도록 묶는다. PC당 예측에 마지막으로 N을 곱하는 구조와 결합해 자점 규모 효과의 표현도 제한된다.

최소 후보: 기존 특징을 유지하고 `log(N/기준PC수)` 한 개만 추가한다. 기준PC수는 훈련집합 중앙값으로 정하며, 이 계수에는 별도의 강한 축소를 적용한다. 이는 작은 점포와 큰 점포의 PC당 매출이 수요 압력만으로 설명되지 않는다는 가설이다.

대안은 기존 수요압력을 `bD*log(D) - bS*log(N+C)`로 분리하되, `bD=bS` 방향으로 벌점을 주어 현행 구조로 돌아갈 수 있게 하는 것이다. 두 대안을 처음부터 함께 추가하지 않는다. N은 양수 검증, C와 D의 기존 단위·산출 정의를 유지한다. 경쟁 IP를 실제 좌석 수와 동일하다고 가정하지 않는다.

## 2순위: PC/상품별 경쟁력 표현 분리

현행 하나의 가중합은 PC 성능·먹거리·인테리어·입지의 차이를 압축한다. 같은 종합점수라도 구성은 다를 수 있다.

최소 후보: 기존 공통점수는 유지하고, 상품 모형에만 기존 먹거리 세부점수의 중심화된 편차 한 개를 추가한다. PC 모형은 그대로 둔다. 이후 별도 후보로 PC 모형에 성능 세부점수 편차를 추가한다. 세부점수가 기존 원자료에 실제 존재할 때만 사용한다. 상품 상세 실적이 없으므로 객단가·구매율을 새로 사실처럼 만들지 않는다.

세부점수는 정답 매출을 보고 재평가하지 않는다. 결측 처리와 중심값은 훈련집합만으로 정한다. 기존 점수의 중복 표현으로 계수가 불안정할 수 있으므로 강한 축소가 필요하다. 기존 가중치 후보(spec=.1, food=1/6, interior=.5333333333333334, location=.2)와 처음부터 결합하지 말고 각각 비교한다.

## 3순위: 총매출 목표와 학습 손실의 불일치 완화

현행 PC시간·상품매출 개별 로그 회귀의 손실 최소화는 총매출 백분율오차나 ±10% 적중률을 직접 최소화하지 않는다.

후보: 개별 모형은 유지한 채, 훈련집합 내부의 교차적합 예측만으로 PC·상품 보정계수 두 개를 추정한다. 총매출 상대오차에 부드러운 절대값 손실을 사용하고, 두 보정계수를 1에 강하게 축소한다. 현재 보정과 대체 비교하며 중복 적용하지 않는다. 점포별 보정은 금지한다.

단순 ±10% 통과 개수 최대화는 경계에 과적합하기 쉬워 첫 후보에서 제외한다. PC 과대·상품 과소의 상쇄만 만드는 보정도 채택하지 않는다. 실제 표본 수가 작아 두 계수조차 불안정할 수 있다.

- 매장별 같은 규칙을 적용하며, 제외 점포나 평가 입력을 결과에 맞춰 바꾸지 않는다.
- 특징 중심값·축소 강도·보정계수 선택은 외부 평가점포를 제외한 훈련 안에서 한다.
- 동일 38개 점포를 반복 분할해도 독립 신규 데이터가 생기는 것은 아니다.
- 개점일순 분할 역시 현재 시점의 입력을 쓴다면 진짜 과거 시점 백테스트로 부르지 않는다.
- 개선 수치·채택 여부는 Claude의 검증 결과가 나올 때까지 미확정으로 둔다.

## 후속 탐색: 기존 기록을 반영한 우선순위 수정

`2026-09-10-product-scaling.md`는 자사 먹거리 점수가 거의 모두 4점 상수라고 기록한다. 따라서 위 2순위의 자사 먹거리 편차 추가는 **보류**한다. 단순 피처 추가로 없는 정보를 만들 수 없다. 경쟁점 먹거리와의 상대 차이는 별도 신호일 가능성이 있지만, 기존 경쟁력 격차와 중복되므로 후순위다.

`calc.ts:1980` 이후 이력에는 원수요·경쟁량 분리와 여러 경쟁력 상호작용의 기존 실험이 있다. 따라서 위 1순위의 수요·공급 계수 분리도 완전히 새로운 방법이라고 취급하지 않는다. 현재 PC/상품 분리 모형에서 재검토할 후보이지, 미시도라는 주장은 철회한다.

### 신규 우선 후보 A: 상권 경계의 수요원 전환 완화

코드 근거: `calc.ts:160`은 r=유동500m/주거500m으로 상권을 분류하고, `calc.ts:207`은 주거형이면 주거 원수요 R, 그 외에는 유동 원수요 F만 선택한다. 따라서 혼합 임계값 t를 넘으면 일반적으로 `aR*R`에서 `aM*F`로 불연속적으로 전환된다. 입력이 조금 달라도 수요가 크게 바뀔 수 있는 구조다. 실제 38개 점포의 적중률에 미치는 영향은 아직 확인하지 않았다.

최소 수정 가설은 분류 표시는 그대로 두고 예측용 수요만 경계 주변에서 연결하는 것이다.

```
u = clamp((log(r) - log(t) + h) / (2*h), 0, 1)
w = u*u*(3 - 2*u)
D = (1-w)*(aR*R) + w*(aM*F)
```

- h>0은 로그비율상의 전환 폭. 아주 좁은 폭 하나와 현행을 먼저 비교하며, 점포별 폭은 금지한다.
- 이는 서로 다른 반경·단위의 원시 인구를 더하는 식이 아니라 **기존 유효율을 적용한 두 수요 대리값의 보간**이다. 그래도 두 대리값의 의미가 완전히 같다고 입증된 것은 아니므로 물리적인 실제 고객 수라고 해석하지 않는다.
- 한쪽 수요가 없을 때 0으로 채우지 말고 기존 가용 원천/폴백을 유지한다. 둘 다 없으면 예측 불가를 유지한다.
- 번화가 경계에서도 유효율이 바뀌지만, 첫 후보는 주거↔혼합의 수요원 교체만 다룬다. 많은 변경을 한꺼번에 묶지 않는다.
- 경계 부근 점포가 거의 없다면 적중률 개선 우선순위를 낮춘다. UI 안정성과 예측 정확도 개선은 별개다.

### 신규 우선 후보 B: 상품매출의 이용시간 의존을 부분적으로만 허용

기존 실험은 상품매출 기준을 PC대수에서 이용시간으로 완전히 교체했다. 기록상 중간 오차는 개선됐지만 꼬리가 악화됐다. 이것만으로 의존도를 0 또는 1 중 하나로 고정해야 한다는 결론은 나오지 않는다.

구조 후보:

```
상품매출 = N * exp(g(X)) * (예측이용시간 / N / Href)^alpha
```

N은 자점 PC수, Href는 훈련집합의 PC당 이용시간 기준값이다. alpha=0은 대당매출 구조이고 alpha=1은 시간 비례 구조다. 첫 후보는 중간 의존도 alpha=0.5 하나만 사전 지정한다. 이후 필요하면 훈련 내부에서만 선택하며 전체 38개 결과를 보고 촘촘히 고르지 않는다.

중요한 차이는 g(X)의 훈련에도 **그 매장을 제외하고 예측한 이용시간**을 사용한다는 점이다. 실제 이용시간으로 상품 모형을 학습하고 배포 때 예측시간으로 바꾸면 입력 오차 특성이 달라진다. 기존 productPerHour 실험의 내부 보정 경로는 `usageRevenue.ts:240,296` 주변에서 실제 PC매출/요금을 참조하므로, 기존 토글을 그대로 켜서 이 후보를 검증한 것으로 취급하지 않는다. 외부 평가 매장까지 포함해 예측시간을 미리 만들지 않는다.

이 후보는 손님의 체류시간이 길수록 구매도 정확히 비례한다는 가정을 완화한다. 새 상품 객단가나 구매율 자료가 생겼다는 의미는 아니다. 효과 및 꼬리 악화 여부는 Claude 담당 검증에서 판정한다.

## 후속 탐색 2: 하한선의 단위와 수요 조정의 실제 작동 원리

### C: 최소 효과를 표본 표준편차에서 분리하는 후보

`calc.ts:1742–1770`의 계산은 각 특징 x를 z=(x-mean)/sd로 바꾼 뒤 표준화 계수 beta에 하한 L을 적용한다. 따라서 원래 입력 단위의 최소 기울기는 L/sd이다. 예를 들어 동일한 가시성 1점 차이도 훈련집합의 가시성 sd가 작으면 더 큰 최소 매출 차이로 강제된다. 이는 버그라는 판정이 아니라 기존 하한의 해석이다.

가중치 변경은 종합 경쟁력의 평균·표준편차와 다른 특징과의 상관까지 함께 바꾼다. 그 결과가 좋아져도 곧바로 ‘인테리어의 진짜 영향력이 높아졌다’고 해석할 수 없다. 원래 단위로 환산한 효과를 같이 살펴봐야 한다.

후보는 정해진 입력 단위당 최소 효과 l을 사용하고, 각 학습에서 표준화 계수 하한을 `l*sd`로 변환하는 방식이다. 가시성·경쟁력 같은 척도가 정의된 특징부터 하나씩 다룬다. l을 전체 38개 매출에 맞추거나 외부 평가점포의 입력 표준편차로 정하지 않는다. 현재 L을 원 단위 l로 바꾸는 기준은 따로 필요하므로 **현재 바로 실행할 우선 후보는 아니며 설계 보류**다. 표본 구성이 바뀌는 데 따른 하한 효과 변동을 줄일 수 있다는 가설이지 적중률 개선 보장이 아니다.

### 탐색에서 제외할 조정: 전체 수요에 같은 배수 적용

클리핑·반올림·초과수요 등의 별도 경로가 작동하지 않는 구간에서는 전체 매장의 D를 같은 k배로 바꿔도 `log(D/(N+C))`에 log(k)가 더해질 뿐이다. 학습 때 평균을 빼면 이 상수는 사라진다. 따라서 전체 수요 일괄 +10%, +20% 같은 실험은 해당 회귀 특징 자체에 새 신호를 주지 않는다.

상권별 서로 다른 유효율 조정은 다르다. 이는 로그공간에서 사실상 상권별 오프셋을 넣는 역할을 할 수 있다. ‘전체 시장 수요 추정이 더 정확해졌다’는 주장과 ‘상권 유형별 예측 편향을 줄였다’는 주장을 구분해야 한다. 기존 joint-demand 후보의 개선도 이 구분 아래 해석한다.

### D: 경쟁점 부분조사에서 수요분모의 일관성 — 조건부 후보

`computeCompetitorIp`는 적용 PC대수가 하나라도 있으면 그 합계를 사용하고, 하나도 없을 때만 영업점 수 기반 폴백을 쓴다. 따라서 동일 상권에서 첫 조사값이 들어오는 순간 전체 영업점 수 기반 추정이 부분 조사 합계로 대체될 수 있다. 이것이 실제 누락 경쟁점을 의미하는지는 별도 확인이 필요하다.

영업점 수의 범위·조사일·자점 포함 여부가 일치하고, 누락된 영업 경쟁점의 존재가 확인될 경우에 한해서 다음 계산 후보가 가능하다.

`C = 확인된 경쟁점 적용PC 합계 + 미조사 영업 경쟁점 수 * 기존 미조사 기본PC수`

확인된 ‘경쟁점없음’을 덮어쓰거나, 오픈예정 점포를 현재 영업점에 포함하거나, 서로 다른 반경의 업소수를 맞추기 위해 임의로 경쟁점을 만들어서는 안 된다. 영업점 수가 더 작다고 조사된 PC합계를 잘라서도 안 된다. 자료 정의가 맞지 않으면 적용하지 않는다. Codex는 원자료를 변경하거나 누락 점포 수를 추정해 저장하지 않았다.

## E: ±10% 범위 밖의 오차에 초점을 둔 저차원 보정

현재 보정은 PC/상품 각각의 MAPE를 줄이는 가중 중앙값의 절반 이동이다(`usageRevenue.ts:266`). 사용자의 주목표인 총매출 ±10% 적중률과는 최적점이 다를 수 있다. 위 3순위 보정을 구체화하는 대안으로 아래 손실을 제안한다.

```
e_i(c) = c * (OOF_PC_i + OOF_상품_i) / 실제총매출_i - 1
loss(c) = 평균[max(0, abs(e_i(c)) - 0.10)^2]
          + rho * log(c)^2
```

- 먼저 **전체 매장 공통 보정 c 하나**만 사용한다. 현재 PC·상품 보정을 유지한 최종 OOF 예측 위에서 추가 비교한다. 채택하려면 중복 보정에 따른 편향도 Claude가 함께 확인해야 한다.
- 10%는 결과를 보고 고른 임계값이 아니라 사용자가 정한 목표다. rho는 내부 훈련에서만 정하고 외부 평가 결과로 선택하지 않는다. c=1을 포함한다.
- 이미 10% 안에 든 점포를 더 정밀하게 맞추기보다는, 밖으로 벗어난 점포의 초과오차를 줄이는 목적이다. 제곱항 때문에 먼 꼬리도 계속 벌점을 받는다.
- 이 손실은 **적중 개수를 직접 최대화하는 것과 다르다**. 꼬리 때문에 중심을 옮겨 기존 적중 점포를 놓칠 수도 있으며, MAPE가 악화될 수도 있다. 개선 가능성을 확인할 후보일 뿐이다.
- 총매출 보정 c를 PC·상품 모두에 적용한다면 각 성분 편향과 이용시간 상한도 다시 계산해야 한다. 총액 표시만 바꾸는 방식은 금지한다.
- 학습 보정에 쓰는 OOF 예측은 외부 평가점포를 제외한 훈련 안에서 생성한다. 현재 전체표본 LOOCV 결과를 재사용해 같은 표본에서 보정 성능을 주장하지 않는다.

이 후보의 장점은 설명변수를 더 늘리지 않는다는 점이고, 약점은 전체 공통 보정으로는 매장 간 순위를 바꿀 수 없다는 점이다. 이미 전체 편향이 작다면 개선 여지도 작다. 복잡한 신규 모형보다 먼저 확인할 수 있는 저차원 대안으로 분류한다.

## G: 수용량 상한이 적용되는 매장의 상품매출 일관성 확인

코드에서 기본 이용시간을 H, 기본 상품매출을 F, 유입배수를 q, 추가 이용시간을 E, 수용량 상한을 K라고 두면, 반올림 전 계산은 다음과 같다.

```
상한 전 시간 U = H*q + E
PC매출 = min(U, K) * 요금
상품매출 = F*q + (F/H)*E = (F/H)*U
```

PC 이용시간에만 상한이 적용되고 상품매출에는 상한 전 시간이 반영된다. 따라서 U>K이면 최종 이용시간당 상품매출은 `(F/H)*(U/K)`가 된다. 상한 초과가 커질수록 이 비율도 커진다. 예를 들어 H=100, F=200, q=1, E=100, K=150인 가상 사례에서는 PC 이용시간 150, 상품매출 400이 되어 시간당 상품매출이 2에서 약 2.67로 증가한다. 이는 산술 예시이며 실제 매장 수치가 아니다.

이 동작이 오류인지는 상품매출 정의에 달려 있다. 이용시간과 무관한 구매를 포함하면 PC 상한과 상품매출 상한을 같게 둘 근거가 부족하다. 반대로 `extraFood = food / hours * extraPcHours`는 추가 이용시간에 비례한 구매를 가정하므로, 상한 때문에 수용하지 못한 추가 시간에도 상품매출을 붙이는 것이 의도인지 확인할 필요가 있다.

Claude 검증 요청:

- 최신 코드에서도 같은 경로가 쓰이는지 확인하고, 기존 검증 결과에서 상한 적용 매장 수와 각 매장의 U/K, PC·상품별 오차를 먼저 확인한다. 상한 적용 매장이 없으면 이 후보는 현재 적중률 개선 우선순위에서 제외한다.
- 상품매출 전체를 `min(1, K/U)`로 줄이는 방식은 모든 상품매출이 이용시간에 비례한다는 강한 가정이다. 바로 채택하지 않고, 상품매출의 범위와 추가 이용시간 정의를 먼저 확인한다.
- 추가 유입 부분만 검토한다면 `E_accepted = min(E, max(0, K-H*q))`와 `extraFood = (F/H)*E_accepted`가 최소 비교안이다. 기본 시간 H*q 자체가 K를 넘는 경우는 이 안으로 해결되지 않으므로 별도로 보고한다.
- 후보 B의 시간 비례 강도 실험과 동시에 변경하지 않는다. 기존 산식 대비 총매출 적중률·MAPE 및 상품매출 과소예측 증가를 함께 비교한다.

현재 상태: 산술 관계만 확인. 실매장 영향·개선 여부 미검증. 코드·운영 설정·원자료 변경 없음. 이 문서로 공유 인계하며 Claude의 수신이나 검증 완료를 의미하지 않는다.
