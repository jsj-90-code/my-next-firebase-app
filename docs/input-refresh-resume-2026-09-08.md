## 남은 검토

기존 점수의 과거 스냅샷/파생 캐시 정의와 재계산 경로의 일관성을 Claude에 읽기 전용으로 검토 요청했다.
최초 실행은 응답 없이 지연되어 중단하고 승인된 환경에서 재실행했다.
운영 반영은 수행하지 않았다.

## Claude 검토 수신 및 후속 수정

- 파생 캐시라는 정의는 기존 동기화 코드와 타입 주석으로 뒷받침된다.
- 경쟁점은 시트 동기화에서 가맹점 코드로 저장하지만 전환 점포 화면은 원본 후보지 코드로 조회한다. 두 코드가 다른 경우의 자료 연결 정책을 추가 확인해야 한다. 보관된 스냅샷에는 두 코드가 다른 기존점이 0곳이므로 현재 표본으로 해당 경우를 검증할 수 없다. 두 코드 자료를 무조건 합치면 별도 문서로 저장된 같은 경쟁점의 중복 집계 가능성이 있어 합집합 변경은 하지 않았다.
- `evaluateCandidate`의 학습용 경쟁점·입지 자료를 필수 인자로 변경하고, 누락 시 저장된 파생 캐시로 되돌아가던 경로를 제거했다. 테스트 입력도 실제 재계산용 원본 필드를 제공하도록 수정했다.
- 일반 테스트 429개 통과. 전환 점포 경쟁점의 정본 정책과 실제 UI 확인은 아직 남아 있으므로 입력 연결 작업 전체를 완료로 표시하지 않는다.

## 후속 구현

- `store.ts`의 전환 처리 주석과 기존점 화면을 대조했다. 전환 점포의 경쟁점·입지는 복사하지 않고 원본 후보지 코드 아래에 유지하는 명시적 계약이 있다. 따라서 가맹점 코드 자료와 합산하지 않으며 공통 `existingStoreSourceCode`로 학습·검증·동기화의 선택을 통일했다.
- 직접 등록한 기존점과 전환 점포를 구별하는 회귀 테스트를 추가했다. 가맹점 코드 자료를 ‘다른 매장’이라고 단정했던 테스트 이름도 정정했다.
- 후보지 결과 계산은 전체 경쟁점·입지 조회 결과에서 대상 후보지 자료를 골라 사용한다. 중복된 개별 조회 2회를 제거했다. 서로 다른 컬렉션 사이의 원자적 스냅샷까지 보장하는 것은 아니다.
- 동기화가 기본정보를 저장한 뒤 메모리에는 옛 기본정보를 유지하던 결함을 수정했다. 동일 실행의 점수 계산에 새 기본정보를 전달한다. 문서 ID를 가맹점 코드의 기준으로 사용한다.
- 외부 서비스를 모킹한 동기화 회귀 테스트로 새 프로필·원본 후보지 웹 경쟁점 사용 및 파생 점수 저장을 검증했다. 운영 쓰기는 하지 않았다.
- 최초 프로덕션 빌드 성공. 별도 작업 폴더의 환경설정 누락으로 브라우저에 설정 안내가 보여 원래 프로젝트의 ignored `.env.local`을 로컬 복사했다. 재빌드는 Google Fonts 연결 오류로 실패해 승인된 환경에서 재실행 중이다.
- Claude에는 위 계약을 근거로 최초 키 누락 지적을 재검토하고, 최신 변경의 구체적 결함을 확인하도록 후속 작업을 배정했다.

## 화면 및 최종 확인

## Claude 후속 지적 반영

- 시트 경쟁점 쓰기에도 `existingStoreSourceCode`를 적용했다. 기존 문서 ID는 유지하고 `candidateCode` 필드만 원본 연결 기준을 따른다. 서로 다른 코드 자료를 무조건 합산하지 않는다.
- 레거시 `surveyState` 호환 변환을 `competitorCompatibility.ts`로 분리해 클라이언트 조회와 Admin SDK 동기화가 함께 사용한다.
- 동기화 테스트는 두 등록 경로에서 시트 경쟁점 저장 코드, 웹 경쟁점 조사상태 변환, 최신 기본정보 계산 및 파생 점수 쓰기를 확인한다.
- 최종 일반 테스트 17파일 432개 통과. 클로드에 두 지적의 최종 수정 검토를 다시 배정했다.
