# 견적서 단가 갱신 (블랙·골드)

2026-10-23 집 PC에서 처음 만들었다. **신규 가맹점 본계약 견적서**다 — 영업부가 계약에 그대로 쓰니 틀리면 계약 금액이 틀린다(사용자: "실수하면 큰일"). 아래 순서를 건너뛰지 않는다.
- **사용자가 미리보기 표를 보고 "적용해"라고 하기 전에는 `apply`·`sync`를 실행하지 않는다.** "그대로 해", "응"도 미리보기를 본 뒤의 답일 때만 승인으로 본다.
- 숫자는 스크립트 출력에서만 옮긴다. 암산·추정한 금액을 보고에 쓰지 않는다.
배경·결정 이유: 업무위키 `LLM위키/2_위키/가맹 운영/가맹 계약 견적서.md` 1-1절.

## 시트 구조 (알고 시작할 것)

- 시트 4개: 블랙·골드 각각 **원본**(원가·마진 있음, 사용자만)과 **영업부용**(원가 없음, 잠김). 주소는 `scripts/quote/lib.mjs`의 `BOOKS`.
- **원본만 고친다.** 영업부용은 `sync.mjs`로만 바꾼다(원가가 영업부 시트에 한 순간도 안 들어가게 원본 안에서 지우고 보낸다).
- 원가는 **부가세 별도**. PC 탭 N열 "부품별 원가", 서버 탭 K열(+ O열 "매입가 VAT 포함"). 판매 단가 F열도 부가세 별도.
- 같은 부품이 여러 줄에 있다(예: RTX5060 8GB = 카운터 세트 N10 + 좌석 N18). 블랙·골드는 부품·원가가 같고 **판매 단가는 다르다**(좌석 기본 블랙 105만·골드 79만) — 단가는 등급별로 따로 정한다.
- 원가 칸이 수식이면(32GB = `=N16*2`, 지원금 품목 = 차액 수식) 안 고친다. 따라 바뀐다.
- 평소 갱신은 **PC 및 주변 기기 탭만**. 서버·가구·인테리어는 변동이 드물어 사용자가 말할 때만(`--tabs all`).

## 1. 단가표 받기

사용자는 **항목 + 모델명 + 가격(부가세 포함)**으로 준다(10-23 사용자: "모델명으로 줄게, 그래야 정확하지. 항목과 모델명 둘 다"). 받은 그대로 JSON으로 적는다(스크래치패드에):

```json
[{ "항목": "그래픽카드", "모델": "RTX5060 8GB", "가격": 565000 },
 { "항목": "메모리", "모델": "DDR5 16GB", "가격": 295000 }]
```

- 가격이 "56만 5천"처럼 오면 숫자로. **부가세 별도라고 하면** ×1.1 해서 넣고 그렇게 했다고 말한다(기본은 포함가).
- 모델명이 시트 표기와 다를 수 있다(공백·대소문자는 무시함). 못 찾으면 2단계에서 "못 찾음"으로 나온다 — 시트의 비슷한 줄을 보여 주고 물어본다. 추측해서 고르지 않는다.

## 2. 미리보기 (시트는 그대로)

```
node scripts/quote/price.mjs preview <단가표.json>
```

- 블랙·골드 원본에서 줄을 찾아 원가 전→후, 판매 줄별 단위당 마진 전→후(%)를 보여 준다. 원본 안 임시 탭에서 실제로 계산하고 지운다(세트 원가 합계 같은 수식까지 정확).
- 계획은 `~/.isens-quote/last-plan.json`에 저장된다.
- 사용자에게 **대화창에 표로** 보여 준다: 원가가 바뀌는 줄, "(같음)"인 줄은 한 줄로 묶어서, 마진이 마이너스(⚠ 손해)인 줄은 맨 위에.
  웹 페이지·파일로 띄우지 않는다(10-23 사용자: "채팅으로만 하자" — 페이지에서 골라도 결국 대화창에 다시 쳐야 해서 두 번 일).
- **표의 줄마다 견적서(블랙/골드)·탭 이름·칸(예: N16)·시트의 품목 글자를 그대로 적는다**(10-23 사용자: 비슷한 항목이 다른 탭에 있을 수 있음).
  탭 이름을 줄여 쓰지 말고, 같은 모델이 두 탭 이상에서 잡히면 그 사실을 표 위에 한 줄로 따로 알린다.
- **확인받을 것**: 묶음 표시(×N)가 붙은 줄, 사용자가 말한 것과 다른 제품으로 보이는 줄. 빼야 하면 `--skip "탭:행,..."`로 다시 미리보기.

## 3. 판매 단가 정하기

원가가 바뀐 판매 줄마다 선택지 세 개를 보여 주고 **사용자가 고르게** 한다(10-23: 단가 규칙은 아직 없음 — 고른 결과가 쌓이면 규칙으로 만든다).

**판단 기준은 계약 1건 총 마진이다**(10-23 사용자, 인계 때 들은 개념): 블랙·골드별로 1건당 목표 마진이 있고, 총 마진이 목표만 넘으면
품목 하나 마진이 줄어도 단가를 그대로 둬도 된다. 미리보기의 "계약 1건 총 마진 전→후"(원본 '본사 내부 정리', 예시 매장 기준) 줄을 표 맨 위에 보인다.
목표 금액·기준 대수·선투자 포함 여부는 **아직 모른다**(10-26 부장님께 확인 예정) — 받기 전에는 "목표 대비"를 지어내지 말고 전→후 변화만 말한다.

| 선택지 | 뜻 |
|---|---|
| 그대로 | 판매 단가 유지, 마진이 줄거나 늚 |
| 마진금액 유지 | 원가 오른 만큼 단가도 올림(10만 원 이상은 만 원, 아래는 천 원 단위 반올림) |
| 마진율 유지 | 원가 비율대로 단가 조정(같은 반올림) |

- 단가가 수식인 줄(`=F16*2`, 서버 `=ROUND(K*1.1,-2)`)은 "자동"이라 묻지 않는다.
- 블랙·골드 단가가 다르면 각각 묻는다. 사용자가 "다 그대로"라고 하면 단가 파일 없이 간다.
- 고른 단가는 JSON으로: `[{ "book": "black", "tab": "PC 및 주변 기기 내역", "row": 16, "price": 330000 }]`
- 사용자가 자주 같은 쪽을 고르면(예: 메모리는 늘 마진금액 유지) 다음부터 "지난번처럼 ○○로 할까요?"로 묻고, 사용자가 규칙으로 하자면 이 절에 적는다.

## 4. 원본에 쓰기 → 영업부용 반영 → 검증

```
node scripts/quote/price.mjs apply [--prices <단가.json>]
node scripts/quote/sync.mjs black
node scripts/quote/sync.mjs gold
```

- `apply`는 미리보기 뒤 원본 원가·판매 단가 칸이 바뀌었으면 **아무것도 안 쓰고** 멈춘다 → 2단계부터 다시.
- `apply`는 쓰기 전에 임시 탭에 같은 값을 넣어 **정답지**를 만들고, 쓴 뒤 ① 바뀐 입력 칸 = 계획한 칸·값 ② 원본 탭 전체 값 = 정답지를 대조한다.
  어긋나면 그 회차에 쓴 칸을 전부 원래 값으로 되돌리고(되돌아온 것까지 확인) 멈춘다 — 이때는 `sync`를 돌리지 말고 출력을 사용자에게 그대로 보인다.
  성공 줄의 "적용 확인: 바뀐 칸 = 계획 N칸, 정답지와 전체 일치 ✓"가 없으면 성공으로 보고하지 않는다(10-23 사용자: "표는 맞게 줬는데 실제 반영이 어긋나는 경우"를 막을 것).
- `sync`는 영업부용에서 누가 직접 고친 칸이 있으면 반영하지 않고 목록을 보여 준다 → 사용자에게 보여 주고, 원본에 옮길지 덮어쓸지(`--force`) 묻는다.
- `sync`가 검증 차이로 멈추면 백업이 남는다 → 차이를 보여 주고 `--rollback`(되돌림) / `--accept`(확정)를 묻는다.
- 시트 수정은 사용자 본인 구글 계정으로 된다(로그인: `node scripts/quote/login.mjs`, PC마다 한 번). "로그인 정보 없음 → 서비스 계정" 경고가 뜨면 사용자에게 알리고 로그인부터 하게 한다(수정 기록에 로봇 이름이 남는 걸 싫어함).
- 구글 한도(429) 재시도 메시지는 정상 — 기다리면 끝난다.

## 5. 보고

짧게, 숫자 위주로:
- 블랙·골드 각각: 고친 원가 칸 수, 바뀐 판매 단가(전→후), **예시 매장 최종 금액 전→후**(`apply` 출력)
- 마진이 마이너스인 줄이 남았으면 따로 한 줄
- 검증 결과(전체 일치 / 차이)

## 하지 말 것

- 영업부용 시트를 직접 고치지 않는다(반영 기록과 어긋나 다음 반영 때 "직접 수정"으로 잡힌다).
- 시트 서식·행 높이·병합을 원본에서 바꾸지 않는다 — 단가 갱신 범위 밖. 사용자가 서식을 말하면 그때 따로.
- 잠금(보호)을 새로 걸거나 풀지 않는다 — `sync`가 반영 전 상태를 그대로 유지한다(10-23 사용자: "원래 안 걸린 거 걸지 마").
- 원가·마진 숫자를 영업부용이나 밖으로 나가는 글에 쓰지 않는다.
